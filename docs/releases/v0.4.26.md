# Orca v0.4.26

Durable multimodal sessions with streaming recovery and content-addressed images.

## Changes

- Raises the durable record limit to 64 MiB, including the newline, and validates records before appending. Session byte totals and record counts no longer block append or recovery.
- Replays history one record at a time. Surface recovery retains commit headers instead of full event payloads and pins the file identity and length across concurrent appends and atomic metadata rewrites.
- Stores inline images in SHA-256-addressed, session-owned assets. Repeated images share one blob, with length and digest validation during recovery. Fork, archive, compression, deletion, and portable export preserve image ownership.
- Keeps bounded list/search projections separate from authoritative recovery. Adds `orca storage` for explicit age/quota-based archive retention with dry-run by default and live-owner protection.
- Passes explicit model IDs through to providers and supports per-model `supports_images` configuration.
- Uses surface-owned child and workflow activity in the TUI, preserves focused workflow state, and acknowledges final workflow progress while shutting down.
- Adds navigable Trust workspace, Continue untrusted, and Exit choices. Existing API keys skip the redundant saved-key confirmation.

## Compatibility

Existing inline-image JSONL sessions remain readable. The record limit applies
to both stored and hydrated representations; a small asset reference cannot
bypass the allocation bound.

New asset-backed records require this version or later. Raw backups must include
the transcript and its sibling `.jsonl.assets` directory. Before downgrading,
use `JsonlThreadStore::export_session` to produce portable inline-image JSONL.
Image deduplication is per session; a fork owns its own assets.

Retention never acts as a write or resume gate. Only archived, idle sessions
are eligible for deletion, and no data is deleted without `--apply`.
