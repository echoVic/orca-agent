# Orca v0.3.20

Orca v0.3.20 adds durable, project-scoped automatic memory for recorded
sessions without turning auxiliary extraction latency into foreground latency.

## What Changed

- **Verifier-gated capture.** A root turn becomes eligible only after its
  transcript completion commits durably and its verifier succeeds. The
  extractor receives bounded, redacted user and assistant messages, never tool
  output or system context.
- **Durable asynchronous jobs.** Capture first enqueues an idempotent
  project job. A session-owned worker uses leases, fencing, wall-clock
  heartbeats, retry limits, and cross-process locks, so a crash, silent
  provider, or stale worker cannot publish an older result over newer state.
- **Typed, auditable project facts.** The authoritative candidate ledger keeps
  category and session/turn provenance. Markdown and SQLite FTS5 search are
  repairable projections; missing or corrupt indexes rebuild from the ledger,
  and recall falls back to bounded lexical matching if needed.
- **Bounded safe recall.** New turns receive at most six relevant facts and
  3,072 bytes as internal context, not transcript messages. Recalled entries
  are marked as historical claims that must be checked against the repository
  and current external state, rather than executable instructions.
- **Explicit controls.** `auto_memory` now defaults to `true` for recorded
  sessions. Set `auto_memory = false` in user or trusted-project configuration
  to stop automatic capture and recall; explicit `/remember` facts remain
  separate and continue to work.

## Compatibility

Automatic memory does not change the transcript or JSONL protocol. Stateless
history-disabled sessions do not start a worker, capture facts, or recall them.
Existing local memory is retained until users delete the exact project directory
as described in [Memory](../memory.md).
