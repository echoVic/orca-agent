# Orca v0.5.5

Changes since v0.5.4:
- Every request reserves reply tokens by reasoning effort (Max 128K, High 64K,
  Low 32K) instead of a fixed 384K, so the compaction line sits where it should.
- Compaction works by conversational unit: a pinned message no longer freezes
  its whole turn, and task/subagent completion notices are ordinary messages again.
- Session resume no longer drops un-compacted task notices from the model context.
- Emergency compaction either shrinks the prompt or tells you to start a new
  session with `/new` instead of silently failing.
- The context meter shows room left before compaction and updates on resume and
  effort changes.

## Changes

### Real reply reservation

Previously every DeepSeek request sent `max_tokens: 384000`, consuming 384K of
the 1M window regardless of context size. Compaction thresholds assumed only 4K
of reservation. The mismatch left about 250K of real headroom unaccounted for,
and a long full-auto session died with "maximum context length is 1,048,576
tokens".

Now the reservation follows the reasoning effort:

| Effort | Reserved for reply |
|---|---|
| Max | 131,072 |
| High | 65,536 |
| Low | 32,768 |

The reservation is capped at 15% of the context window and can be overridden
with `[model_runtime] max_output_tokens` (16,384–384,000). The compaction trigger
line is `min(0.8W, 0.9W − R)`, so it automatically accounts for the real
reservation and the incident session would have compacted far earlier.

### Unit-based compaction

Compaction previously kept every turn that contained a pinned message intact.
Background task notices and subagent completion messages were pinned in every
turn, so compaction removed nothing and the session grew until it hit the limit.

Compaction now works on units: a turn-opening user message, or an assistant
message together with the tool results that answer it. A pinned message keeps
only its own unit (or just itself for system notices), so a long history with
many task notices can now compact freely. The current turn keeps its opening
message and its most recent tool results; earlier tool output in the current
turn is trimmed first so the model keeps what it is actively working with.

### Ordinary delivery messages

Task completion notices, subagent results, parent guidance, wait results, and
budget reminders are now delivered as ordinary system messages rather than
pinned ones. This is backward-compatible: sessions from earlier versions have
those notices unpinned automatically on the first resume.

Sessions that resume after this update will no longer drop un-compacted notices
from the model context.

### Emergency compaction

When the prompt leaves no room for a minimal reply before a request is sent,
Orca now tries an emergency compaction. If the compaction actually shrinks the
prompt, the request is retried. If it cannot shrink the prompt, the turn stops
with a clear message:

> The conversation no longer fits the model's context window (about N tokens)
> and compaction cannot shrink it further. Start a new conversation with /new.

A provider-reported context overflow on retry follows the same rule.

Sub-agent overflow failures use separate wording that does not advise starting
a new session (the parent session is fine).

### Context meter

The meter now shows room before compaction hits — 100% means empty, 0% means
compaction is due — instead of a fraction of the full 1M window. The ceiling
is updated immediately on session resume and whenever reasoning effort or the
model changes mid-session.

`/status` now reports: `N left before compaction (compacts at T)`.

ACP clients see the same ceiling in the `context` usage field.
