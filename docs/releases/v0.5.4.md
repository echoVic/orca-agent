# Orca v0.5.4

Changes since v0.5.3:
- In auto-edit and suggest, a git write such as `git commit` costs one
  approval instead of failing against the read-only `.git`.
- The plan panel keeps up with the work: the model updates the plan as each
  step finishes, and a stale plan gets its reminder again.
- A change to the plan, goal, or recalled memory no longer makes DeepSeek read
  the whole conversation history as a cache miss.

## Changes

### Git writes in auto-edit and suggest

- auto-edit and suggest run bash in the workspace sandbox, where `.git` is
  read-only, so `git commit`, `git add`, `git mv`, and other commands that
  write git metadata failed. Orca now recognizes such a command before it
  runs.
- auto-edit asks first: allow it once, allow git writes for this session, or
  deny. The grant covers that one run, and the next command sees `.git`
  read-only again. After the session option, later git writes run without
  asking, each with a grant for its own run only.
- suggest adds a line about `.git` to the command's approval prompt, and
  approving the command grants the write. A command that a permission rule
  allows without a prompt is asked about the auto-edit way.
- The grant keeps `.git/config`, `config.worktree`, `hooks/`, and `modules/`
  read-only, because those are where code can be set up to run later outside
  the sandbox. A git command that writes config, such as
  `git branch --set-upstream-to`, still fails.
- Orca asks only when the command runs at the repository root, `.git` there
  is a real directory, and no existing grant already opens `.git`. Commands
  it cannot read with confidence run as before: ones that use `$(…)`, `eval`,
  `sh -c`, `git -c`, `--git-dir`, or `GIT_*` variables, and `config`,
  `remote`, `submodule`, or `worktree` writes.
- `fetch`, `pull`, and `push` are not covered, because the sandbox has no
  network.
- Deny returns `denied` to the model, and the command does not run.
- When the sandbox still stops a write under `.git`, `.agents`, or `.codex`,
  the diagnostic names the next step: call `request_permissions` with
  `fileSystem.write` and that directory.
- On Linux the grant needs bwrap to keep those paths read-only; without bwrap
  the command does not run. Windows gets only the diagnostic for now.

### Plan progress

- The plan panel could point at the first step while the model worked through
  the rest, because the model created a plan and did not update it until the
  end. The system prompt now asks for an `update_plan` call as soon as a step
  is verified, and allows marking several steps complete in one call only
  when they finished together.
- The reminder for a stale plan works again. Since v0.2.32 the agent loop
  recorded model replies without counting them, so the reminder never fired.
  After 10 replies without an update, while the plan still has open steps,
  the plan context carries the reminder.

### DeepSeek prompt cache

- The plan, goal, memory, skill, and mode context sat between the
  instructions and the conversation history. Any change to it made DeepSeek
  read the whole history as a cache miss: after each `update_plan`, and on
  each new message whose recalled memory differed. In one recorded session of
  376 requests, 11 such misses carried 94% of all uncached input tokens. This
  context is now the last message of each request, so a change costs only
  that message. The compaction summary stays ahead of the history.
- The new `internal_context_tail_realapi` example measures this against the
  live API. After a plan change, 96% of a 4,125-token prompt came from the
  cache with the context last, against 22% with it ahead of the history.
- An empty-response retry still adds its recovery instruction to the user's
  message.

## Compatibility

- Sessions from earlier versions open and resume. The first request of an
  existing session after the upgrade misses the cache once, because the
  instructions changed.
- The model now reads the plan and goal after the latest tool results.
- The session switch for git writes lives in memory: after a restart or a
  resume, the first git write asks again.

Existing configurations and conversation history remain readable.
