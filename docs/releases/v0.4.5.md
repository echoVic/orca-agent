# Orca v0.4.5

Patch release: remove the remaining TUI owner-type compatibility facade and enforce direct owner imports.

## Direct TUI Owner Imports

- Remove all `protocol.rs`, `transcript_state.rs`, `interaction_state.rs`, `viewport_state.rs`, and `surface_projection.rs` type re-exports from `types.rs`.
- Update integration tests and documentation to import each type from its owning module.
- Add a runtime-surface architecture check that rejects dedicated TUI owner types imported through `crate::types`.

`types.rs` remains the `AppState` composition root and retains only aggregate state and types without a dedicated owner. This is an intentional source-level migration; no backwards-compatible `types` facade is provided.

## Compatibility

- CLI commands, JSONL session metadata, runtime surface wire formats, npm package names, and release archive layouts remain unchanged.
- No persisted session, goal, or workflow formats change.
- TUI contributors must import protocol and state-owner types directly from `protocol`, `transcript_state`, `interaction_state`, `viewport_state`, or `surface_projection`.
