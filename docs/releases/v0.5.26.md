# Orca v0.5.26

Orca reuses more of the DeepSeek conversation when compacting, resuming, or starting a fork child, and keeps large tool results available for later reads.

## Changes

- **Deep compaction keeps a structured checkpoint.** Orca replays the last successfully sent DeepSeek request up to the compaction cut and asks the session's model to summarize intent, concepts, files and code, errors and fixes, pending work, current work, next step, and critical context. DeepSeek can charge cache-hit rates for the unchanged prefix. Orca counts the replay toward the session cost and budget, keeps recent and pinned messages, and falls back to a hierarchical Flash summary and then local truncation if the replay cannot produce a smaller usable checkpoint.
- **Context updates stay in the conversation.** Orca sends the skill catalog, MCP catalog, memory, and other internal context when they change. Updates begin `Current {kind} context (this replaces any earlier version):` and removals read `The {kind} context no longer applies.` The current plan stays at the end of each request. When you resume, Orca reuses the recorded leading prompt and adds a notice beginning `The "{section}" instructions changed; they now read:` for changed instructions. It rebuilds the prompt when the instruction sources no longer apply or the recorded prompt cannot be reused.
- **Start a child with the parent's completed history.** `subagent` accepts `context: "fork"` to reuse the parent's DeepSeek prompt, ordered tools, completed history, model, and reasoning effort. The child reports its own work and Orca checks role permissions on each call. It starts fresh with a note if there is no usable parent prefix. `context: "fresh"` remains the default. Use `resume_from` and omit `context` to continue an existing child.
- **Read or search the full tool result later.** In recorded sessions, Orca saves MCP, external tool, `web_fetch`, and `web_search` text results over an estimated 12,500 tokens. The preview includes the start, end, and path. The model can page through the saved text with `read_file` using `unit: "bytes"`, `offset`, and `limit`, or search it with `grep`. The path survives micro-compaction.
- **Load instructions for the files you touch.** In trusted workspaces, Orca discovers nested `AGENTS.md` files as it reads or changes files and records each version when it first applies. User-wide, project-root, and nested instruction chains each have a 65,536-byte budget. Orca drops the broadest instructions first when a chain exceeds its budget and names the files it dropped or shortened.
- **Find skills without listing them first.** The model sees a catalog of skill IDs and descriptions and can call `read_skill` when one matches the task. A `$skill` mention keeps that version of the skill body available for follow-up prompts until compaction. Orca finds project skills from the Git root, or from the workspace root outside a Git repository, and gives them precedence over user skills with the same ID.
- **Load MCP tools when needed.** Set a server's `tool_loading = "on-demand"` to send a catalog and `mcp__<server>__load_tools` first. The loader takes a `names` array. Loaded tools appear in the next request, count toward DeepSeek's 128-tool limit, and are restored on resume. The default is `"eager"`.
- **Apply a multi-file patch.** Set `apply_patch = true` under `[tools]` to add, update, delete, or move workspace files in one call. The tool takes an `input` string and checks the whole patch before writing. Each target follows the file-edit approval policy, and `/rewind` can restore the changes when file history is enabled.
- **Give the model more specific tool guidance.** `bash` explains that each call starts a fresh shell, points to `workdir`, and says how to handle a sandbox refusal and guard variables in delete or overwrite paths. `edit` says when to read first, and `read_file` points the model away from `cat`, `head`, `tail`, and `sed` for text reads.
- **Break a loop of identical calls.** After the third, fifth, and eighth consecutive calls with the same tool and arguments, Orca reminds the model `You have called <tool> with the same arguments <n> times in a row.` Each call still runs. A different call or new user message resets the count. `task_wait`, `task_read_output`, and `task_list` are excluded.
- **Run eligible network reads in parallel.** Consecutive `web_search`, `web_fetch`, and `read_document` calls can run alongside local reads when the active approval policy already allows the batch. Orca records results in request order. Reads of the same document run one by one.

## Fixes

- **Steer a parent while it waits for children.** Your message ends a `task_wait` or an end-of-turn child wait and reaches the next model step. The model can wait again afterward. The `Delegation` guidance now says `If only child results remain, end your reply. Orca resumes the turn as results arrive.` JSONL reports the steer after it is saved, and Orca keeps the input if saving fails.
- **Keep every workflow task-list update.** Concurrent updates use one writer. Only the agent attempt that claimed a running task can complete it. Claims survive checkpointed retries, are released on final exit, and are reconciled during recovery. A script can catch the error for a request over 1 MiB. On Windows, the workflow runner retries a task-list reply read if the reply file is temporarily unavailable during replacement.
- **Refresh MCP tools after HTTP session renewal.** Orca refreshes the tool list and tells the model `MCP server '<server>' renewed its session. Review its current tools and submit the tool call again.`

## Compatibility

- **Prompt cache.** The changed `bash`, `edit`, and `read_file` descriptions and the new `Delegation` sentence change the cached request prefix once for every session after upgrading.
- **Context fragments and recorded prompts.** Context fragments and prompt-section notices are stored in history as system messages with optional fields. Orca 0.5.25 and 0.5.24 can read these sessions. On resume, they rebuild the leading prompt and drop the fragment and notice messages.
- **Fork children.** The `context` argument selects `"fresh"` or `"fork"`. Orca stores private, redacted fork-history files for queued launches and resumes. Orca 0.5.25 resumes a fork child from its own transcript, without the inherited history. Child checkpoints carry a `digest` that 0.5.25 can verify and a `full_digest` that also covers the newer fields.
- **Saved large results and on-demand MCP.** Large results live in session files. The loaded MCP selection is kept in the optional `mcp_tool_load` field on tool results, which older versions ignore. When loading changes the tool list, the next request misses the cache once.
- **`apply_patch`.** The tool is off by default. Enabling it adds one tool definition to the request.
- **Repeat-call reminders.** Orca stores the reminder as a system message after the whole tool group has settled. The count survives compaction and resume.
- **Parallel network reads.** The existing approval rules still apply. A batch runs one by one if a call requires approval or the operation has a cost cap, such as `--max-cost-usd`.
