# Orca v0.4.0

Major release: add complete DeepSeek vision input and split the runtime's
generation, interaction, recovery, Goal, and task/workflow responsibilities
into focused controllers.

## Image input

- Add `deepseek-v4-flash-vision-exp` with OpenAI-compatible text, image URL,
  inline base64, and file content blocks. JPEG, PNG, GIF, and WebP inputs use
  `high` detail by default and remain durable across history, continuation,
  compaction, and replay.
- Add TUI system-clipboard image paste with `Ctrl+V`, forwarded `Cmd+V`, and
  Windows `Alt+V`. Clipboard reads run outside the renderer thread; request
  fences reject stale completions, and Enter waits for an in-flight read before
  submitting or queueing.
- Accept dragged or pasted image paths and `file://` URLs, including multiple
  Finder or clipboard files. macOS uses an isolated pasteboard helper, Linux
  and native Windows use the platform clipboard, and WSL falls back to the
  Windows clipboard through PowerShell.
- Represent composer attachments as atomic `[Image #N]` items. Deletion,
  `Ctrl+U`, image-only turns, queued follow-ups, queue editing, model routing,
  and rejected submission recovery preserve attachment identity and bytes.
- Accept images with every model selection. The vision model receives images
  directly; `auto`, Pro, and Flash use a task-aware, deduplicated vision
  analysis before the selected coding model continues.
- Render terminal-compatible image thumbnails in the composer preview and
  message area. Image items open a large viewer with zoom, pan, and fit
  controls. Kitty and Ghostty use Kitty Graphics, iTerm2 and WezTerm use their
  inline-image protocol, and terminals without either capability retain a
  low-resolution true-color cell fallback.
- Enforce PNG/JPEG/GIF/WebP magic-byte validation, a 600-image count bound, and
  a 5 MiB aggregate inline-image limit. SSH sessions without a graphical
  clipboard fail explicitly and continue to support remote paths and `@file`.
- Accept ACP image content blocks and route every TUI and ACP image through the
  same typed runtime surface and DeepSeek provider request.

## Runtime architecture

- Split generation-context, interaction, operation-recovery, Goal, and
  task/workflow logic out of the monolithic thread actor into focused
  controllers that return typed decisions or event batches.
- Add stable `ContextWindowId` epochs. Usage updates and failed compaction keep
  the current identity, successful compaction advances it, resume restores it,
  and forks receive an independent identity.
- Preserve Goal pause-before-cancel ordering and harden provider stream
  integrity recovery for premature EOF without duplicating visible output.

## Compatibility

- Existing text-only sessions and serialized messages remain readable through
  serde defaults. Image-analysis failure rejects the complete turn and restores
  the original composer text and attachments.
- CLI commands and JSONL request names remain compatible. Runtime surface input
  gains additive image blocks and context-window identity.
- `Cmd+V` depends on the terminal forwarding `Super+V`; use `Ctrl+V` when the
  terminal consumes the macOS shortcut itself.
