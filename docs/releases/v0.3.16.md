# Orca v0.3.16

Orca v0.3.16 hardens the execution-budget protocol end to end. Three review
rounds closed every gap where a budget terminal could misreport durable
state: resumable stops now always point at a real durable conversation
boundary, child-agent leases reserve and settle per child with usage
receipts, suspended and stateless exchanges never claim resumability or
success they cannot back, and the operation journal records the committed
tool outcome with dimension-specific stop reasons.

## What Changed

- **Real resume boundaries before resumable terminals.** A budget stop
  commits the session checkpoint (with the durable last-committed message
  id and the dimension-specific reason) first, then the operation journal's
  checkpoint and terminal — in that order, for turn, cost, and tool-dispatch
  stops. A crash can no longer leave a `resumable: true` terminal pointing at
  a boundary that does not exist, and the host no longer writes a duplicate
  best-effort checkpoint after the terminal.
- **Non-resumable stops where no boundary exists.** Stateless operations
  (JSONL without saved history, server submits without history) and
  suspended exchanges that exceed their budget commit a typed `Stopped`
  terminal with `resumable: false` (the journal still records the checkpoint
  fact). Approval-waiting operations never persist a terminal at all — the
  operation stays parked for approval and may resume.
- **Child-agent leases with per-child reservation and usage receipts.**
  Each batch child receives its own lease, children partition the parent's
  remaining capacity evenly (the first child can never monopolize it), and a
  fully-consumed dimension refuses new leases instead of padding the
  remainder. Child completion carries a mandatory budget receipt (via the
  typed terminal usage) that the parent merges exactly once — including on
  persistence and event-error paths — so concurrent children can never
  double-spend the parent's operation.
- **Suspended-provider accounting resumes from its snapshot.** The
  background completion path restores the controller usage taken at
  suspension (turns, tools, cost, wall time) before recording the exchange's
  cost and wall time, so a long or expensive background response cannot
  bypass the budget and be persisted as a success.
- **Journal records the committed tool outcome.** Tool settlement reads the
  committed conversation status and error (`completed`, `failed`, `denied`,
  `cancelled`, `indeterminate`, `not_implemented`) instead of a hardcoded
  success, so recovery and audit never disagree with the conversation.
- **Wall time is accounted after every provider exchange** — a provider that
  returns no usage, or fails after a long request, still lands a wall-time
  stop promptly.
- **Journal persistence follows every durable history mode.** Record,
  Resume, ResumeAt, and Fork operations persist their journal under
  `ORCA_HOME`; only Disabled (stateless) operations journal to the temp
  directory and never create runtime artifacts in `ORCA_HOME`.

## Compatibility

No CLI, JSONL envelope, or persisted-format shape changes. The round only
corrects terminal facts: checkpoint reason strings add dimension-specific
values (`turn_budget_exhausted`, `tool_call_budget_exhausted`,
`wall_time_budget_exhausted`; cost keeps its legacy string), and
`resumable` becomes truthful for stateless and suspended stops. Normal,
cancellation, rejection, timeout, retry, disconnect, and restart semantics
are unchanged from the redesign contract; existing sessions resume exactly
as before.

## Verification

```bash
cargo test --workspace --locked -- --test-threads=1
cargo test --test execution_budget_contract --locked
cargo test --test agent_loop_contract --locked -- --test-threads=1
cargo test --test history_contract --locked -- --test-threads=1
cargo test -p orca-runtime --test budget_lease_contract --locked -- --test-threads=1
cargo test -p orca-runtime --test execution_journal --locked -- --test-threads=1
cargo test --test session_server_contract --locked -- --test-threads=1
```

The review-round acceptance tests cover: stateless non-resumable stops,
suspended over-budget exchanges, batch budget partitioning, batch receipt
preservation on persistence failure, distinct turn-budget checkpoint
reasons, verifier independence on budget stops, and journal recovery from
torn writes.
