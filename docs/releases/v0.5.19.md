# Orca v0.5.19

This patch makes agent work reversible: `/rewind` and `orca rewind` restore files and conversation to an earlier user turn, or replace one side of that boundary with a model-written summary, using per-turn content-addressed checkpoints. It also carries the usage-accounting and TUI polish batch: provider usage from the generation stop reaches cumulative ACP/TUI metrics, the first-run welcome's `T`/`U` letters commit their trust choice, and the status line gains a context ring with a responsive right zone.

## Changes

- **File checkpoints and `/rewind`.** Before `edit` or `write_file` touches a workspace file, the runtime stores that file's pre-image in a content-addressed store under `$ORCA_HOME/rewind/sessions/<session_id>/objects` and appends a `session.snapshot` transcript record at the end of the turn. `/rewind` (alias `/checkpoint`) opens a picker of the session's user turns with per-turn file statistics, then one of six actions: restore code and conversation, conversation only, code only, summarize-from, summarize-up-to, or cancel. File restores are planned from the recorded pre-images (files created after the target turn are deleted, files deleted after it are recreated), applied atomically with a crash journal, and reported with per-file unified diffs in the confirmation page. A conversation rewind appends a durable `session.rewind` record; transcript loading folds it so a resumed session sees the truncated history, and the target prompt is put back in the composer. `summarize-from` replaces the target turn and everything after it with a model-written pinned summary, while `summarize-up-to` drains earlier turns into a summary kept after the system prompt. Dry runs never call the model. Bash commands and external processes are not captured: bounded workspace observation lists them as untracked and a rewind never restores them.
- **Checkpoint lifecycle.** A session keeps its most recent 100 checkpoints; evicting older ones writes a `session.snapshot_retention` watermark, after which those turns remain available for conversation rewind only. Eviction also garbage-collects checkpoint blobs no retained snapshot references. A new `[rewind]` config section controls capture (`enabled`), turn-boundary observation (`observe_untracked`) and retention (`max_checkpoints`); `ORCA_DISABLE_FILE_HISTORY` and `ORCA_REWIND_DISABLE_OBSERVE` still override it. An interrupted restore leaves a journal that blocks the next file rewind until `orca rewind --rollback OP_ID` restores the workspace, and `orca rewind --prune` reclaims unreferenced blobs on demand. A rewind that targets a snapshot recorded in a different workspace fails closed instead of writing into the current one.
- **Headless rewind.** `orca rewind [SESSION_ID] [--last] [--at MESSAGE_ID] [--mode both|code|conversation|summarize-from|summarize-up-to] [--dry-run] [--json] [--force] [--rollback OP_ID] [--prune]` performs the same operation from the command line. It refuses to overwrite files whose current contents changed outside tracked tool writes unless `--force` is passed, and summarize modes call the real summarizer using the effective provider configuration.
- **Rewind event.** The runtime emits a typed `session.rewind` event (target turn, mode, file counts, conversation kept count, rewind id, duration) after an applied rewind. It is published to observers attached to the live surface and journaled in recorded sessions; a dry run never emits it, and resume does not replay it as a conversation message.
- **Usage accounting.** The surface reducer now folds the usage delta carried by a generation stop into the thread usage total, so ACP usage updates, the TUI status bar and `/status` show cumulative tokens and cost instead of only the latest response. A priced mock turn now has an end-to-end regression from provider through the typed surface into TUI metrics.
- **First-run and status polish.** On the welcome screen, `T` and `U` commit their trust choice exactly like `Enter` instead of only moving the highlight, an existing API key skips the save step, notice lines wrap instead of clipping, tips are cut at the pane edge, and the popup keeps its decision rows on short frames. The TUI recovery hint for a cleared draft moved from the composer placeholder into the transcript, keeping the permanent affordance line visible. The status line's right zone shrinks in a defined priority order on narrow terminals and its context cell gains a quarter-step ring beside the consumed percentage; `/status` adds folder trust and the capability profile, names the full-auto folder-trust bypass, and opens expanded.

## Compatibility

- **Additive transcript records.** `session.snapshot`, `session.rewind` and `session.snapshot_retention` are new JSONL record types. Transcripts that contain them are not readable by Orca versions that predate this release; delete or archive such sessions before downgrading. Old transcripts load unchanged.
- **Capture defaults.** File checkpointing is on for sessions that record history. It captures only files written by `edit` / `write_file` and only files inside the workspace root, excluding `.git`, `target`, `node_modules` and `.orca`; set `[rewind] enabled = false` or `ORCA_DISABLE_FILE_HISTORY=1` to turn it off. Checkpoint blobs use disk space under `$ORCA_HOME/rewind`; `orca rewind --prune` and the retention GC reclaim it.
- **Rewind scope.** A file rewind restores exactly the files tracked by the selected checkpoint set; edits made by bash, another process, or another session are reported as untracked and are not restored. A conversation rewind keeps the same session id and does not roll back recorded token usage or budget history. `--mode code` leaves the conversation untouched, and `--mode conversation` leaves files untouched.
- **Summarize modes.** `summarize-from` and `summarize-up-to` call the provider when applied (not during a dry run) and consume tokens through normal accounting; a failed summary leaves the transcript and files unchanged. The semantic content of the summary is model-written, and the dropped turns are still present in the on-disk transcript for audit.
- **Event stream.** `session.rewind` is a stream event and is not replayed as a conversation message on resume.

## Verification

Release gates run with framework retries disabled. Linux and native Windows x64/ARM64 checks must pass on the final main commit before the tag is pushed; a tag-triggered release reuses those results instead of rerunning the full suites, while a manual dispatch runs every gate below. The release workflow builds all six target archives, publishes the npm packages, and checks the published archive and package checksums and clean installs.

The changes ship with unit and contract tests across the core, provider, tools, runtime and TUI crates: content-addressed blob round trips and planner/applier/journal cases, transcript fold and split semantics for all rewind kinds, capture and retention/GC, config parsing and environment overrides, CLI dry-run/apply/summarize/rollback/prune, host command coverage, a real-runtime TUI summarize flow, PTY `/rewind` smoke, and the `session.rewind` event plus golden ACP wire baselines. The tui-test black-box suites drive the shipped binary through `/rewind` and the first-run/status changes. The final gates run in CI.

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -j 1
cargo nextest run -p orca-tui --lib --locked --profile ci-serial --retries 0
cargo nextest run --test tui_pty_contract --locked --profile ci-serial --retries 0
cargo nextest run --workspace --all-targets --locked --profile ci --no-fail-fast --retries 0
node scripts/release/verify-version-sync.mjs
node scripts/release/test-stage-npm.mjs
node scripts/release/test-verify-published.mjs
npm --prefix site run build
npm --prefix site run check:seo
```
