# Orca v0.3.21

Orca v0.3.21 makes interactive sessions and resumed workflow tasks more
reliable by giving each state transition one explicit owner.

## What Changed

- **Consistent TUI projection.** Session identity, operations, Goals, plans,
  workflow tasks, usage, context, and presentation now cross explicit cursor
  and ownership boundaries. Equal or stale projections cannot silently replace
  newer visible state.
- **Reliable interaction and terminal lifecycle.** Queued submissions,
  approval responses, renderer wakeups, runtime events, terminal startup, and
  shutdown are handled by dedicated owners. This preserves input and response
  ordering through redraws, cancellation, and session changes.
- **Safe Side re-entry.** Returning to a Side conversation rotates attachment
  fencing before projecting authoritative history, preserves background task
  presentation, and prevents queued stale events from corrupting the restored
  transcript.
- **Legacy workflow-task recovery.** Restarted sessions adopt older active
  tasks into the current durable task registry and reconcile legacy terminal
  tasks without duplicating terminal state or reviving completed work.

## Compatibility

There are no CLI, JSONL, persistence-schema, or npm installation changes in
this release. Existing recorded sessions remain readable; legacy task records
are upgraded through reconciliation when their session is resumed.
