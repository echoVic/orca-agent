# Orca v0.5.27

Orca lets you open a subagent's terminal conversation while it runs and read it again after it finishes or you resume the session.

## Changes

- **Open a subagent without interrupting main.** Eligible subagents run inside the TUI's process. With an empty composer, select a row in the dock with Shift+↑ or Shift+↓. You can also select the row in `/agents`. Press Enter to open the conversation. It starts with the task, followed by the subagent's text and tool calls. Esc closes any open panel first, then returns to main.
- **See what main is doing while you watch.** The line below the conversation reads `Main is running · Esc return`, `Main needs your approval · Esc return`, or `Main needs your answer · Esc return` as appropriate. Under a finished agent it reads `Main is idle · Esc return` when main is idle.
- **Keep any text you try to send from an agent's view.** Orca puts it back in the composer. A running agent's view says `this is an agent's conversation: return to the main conversation to send a message`. A finished view says `this agent has finished: return to the main conversation to send a message`.
- **Read a finished agent's conversation after a resume.** It ends with `This agent has finished. Its conversation is read-only.` If Orca cannot load that task's conversation, it says `This agent's conversation could not be loaded. Showing its last checkpoint.` and shows the task's checkpoint if available.
- **Find launch and end lines in main.** Main shows `Delegating to 1 agent` or `Delegating to N agents in parallel` for each batch, followed by one end line per agent, such as `Agent completed: <name>` or `Agent stopped: <name>`. The lines stay with main when you return or resume.
- **Stop main's turn and its agents together, or stop one agent.** Esc on main or Ctrl+C from either view interrupts the running main turn and its in-process agents. To stop only one, select its row in `/agents` and press `s`. Main and the other agents keep running. Main is told `the person using Orca stopped this subagent from the Agents panel; it was not stopped by you and it did not fail. Do not start it again unless they ask.`
- **In-process agents do not prompt for approval.** Orca refuses those calls with `This call needs an approval, and a subagent cannot ask for one.` The subagent is told to report what it could not do to its parent and continues with the work it can do.
- **Quitting stops and records in-process agents.** While main runs, Ctrl+C first interrupts its turn. If main is idle but an in-process agent is still running, the first press says `1 agent is still running. Press Ctrl+C again to quit and stop it.` With several, it says `N agents are still running. Press Ctrl+C again to quit and stop them.` The second press within two seconds quits and records the remaining agents as stopped. If Orca was killed instead, `--resume` marks an in-process agent that was still running as `failed` and no longer counts it in the quit prompt.
- **Keep main in the foreground while its in-process agents run.** Ctrl+B shows `This turn cannot move to the background while its subagents are running.` Press it again after the agents end if you still want to move the turn.
- **Five kinds still use separate workers.** This includes `"isolation": "worktree"`, custom agent types, finite parent budgets, calls with `resume_from`, and `"context": "fork"` when the parent's history can be used. Their worker behavior is unchanged. `orca exec`, the app server, and ACP still launch subagents as before.

## Fixes

- **A host shutdown cancels the turn.** If shutdown closes the turn's own message path, the turn ends cancelled, including after an interrupt. A real failure saving a reply is still reported as a failure.
- **Servers sharing an `ORCA_HOME` leave each other's live shell sessions alone.** Recovery skips live owners, and each server writes to its own output archive.
- **A `command/exec` finish failure answers the original request.** The client gets an `error` instead of waiting for a completion that never comes.
- **`command/exec/list` finishes exits it observes.** It sends the pending command result to the original caller without waiting for another request.
- **A finished subagent can be continued while its parent cleans up.** Cleanup of the previous turn no longer refuses a continuation of an already finished task.
- **Denying an approval no longer looks like a crash in the TUI.** The conversation shows `Denied. Tell Orca what to do instead.` without a generic failure line. The underlying turn status is unchanged.

## Compatibility

- **Session history and task registries remain readable in both versions.** Orca 0.5.27 defaults the new task fields `registry_owner` and `ended_on_resume` when reading 0.5.26 records. Orca 0.5.26 ignores those fields and drops them if it rewrites the registry. The child thread ID was already optional; it is now recorded at launch for in-process agents. No new session record type or continuation checkpoint format is required, though 0.5.26 does not reproduce the new live and read-only views.
- **Stop the old version before sharing a home with the new one.** Orca 0.5.26 does not honor the new owner stamps and cannot read shell output in the new per-owner archives. Orca 0.5.27 can read the older archive as a fallback. A fresh opener can still recover an old, unstamped record even if its owner is live.
- **The main prompt and tool definitions are unchanged.** There is no release-wide prompt cache reset. In-process children get new approval guidance in their role context and new refusal text in tool results. Stopping an agent with `s` changes the result or notification its parent receives. After a resume, tasks recovered from a dead registry also return their settled status instead of still looking active. These messages can change the cached prefix where they appear.
- **Existing wire events keep their names.** Runtime JSONL `task.status.updated` and `workflow.tasks.updated` task summaries gain a `sequence` field. The server's runtime-event mapper preserves it if handed `task.status.updated`, but normal app-server turns and ACP use their own surface projections, whose message shapes are unchanged. The server fixes use existing response types.
- **In-process subagents no longer outlive the TUI.** To keep that work running after you quit, start an async subagent with one of the five detached cases above, or start it with `orca exec`.
