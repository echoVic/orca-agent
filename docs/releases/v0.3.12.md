# Orca v0.3.12

Orca v0.3.12 adds runtime-owned Side Conversations so a quick question can use
the main conversation's context without changing or interrupting the main task.

## What Changed

- `/side [question]` creates a separate process-local child from an atomic
  snapshot of the parent. The child has its own runtime identity, operation
  admission, cancellation, interactions, and transcript projection.
- `Ctrl+/` switches between Side and the parent while either can keep running.
  The Side footer shows the parent's latest running, input, approval, terminal,
  or closed state. `Ctrl+C` while Side is active closes and joins only the Side.
- Side is disposable and read-only: it uses Plan mode, disabled history, and
  disabled automatic memory, never
  creates a session catalog entry, and never merges messages, tools, plans,
  goals, memory, or settings into the parent.
- Navigation and parent replacement are rejected while the attached child
  exists. Close Side first; controller shutdown always settles the child before
  the parent through a bounded join barrier.
- TUI response projection now matches streamed provider output by logical turn,
  response item identity, and channel. Reconciliation drops incomplete
  assistant and reasoning tails before replay so older streams cannot replace
  the current response.

## Compatibility

CLI arguments, existing TUI session commands, server/JSONL and ACP protocols,
SQLite schemas, and persisted transcript formats are unchanged. Side threads
are intentionally process-local and cannot be resumed or merged. Existing
`/fork` remains the durable conversation-copy workflow.

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.12
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.12 sh
```

Windows PowerShell, including workspace sandbox setup:

```powershell
& ([scriptblock]::Create((irm https://orcaagent.dev/install.ps1))) -Version 0.3.12 -SetupSandbox
```
