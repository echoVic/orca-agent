# Orca v0.4.31

Unified subagent scheduling, durable task control, and one managed command
lifecycle.

## Changes

- Gives every root task tree one durable execution scope shared by direct,
  nested, Workflow, hosted, continued, and recovered subagents. The default
  scope runs up to 32 children, queues accepted overflow, and separately bounds
  queued and live work.
- Lets a parent release its execution lease at a safe checkpoint while waiting
  for children, then re-enter the fair queue when their state changes. Parent
  and dependency identities form a checked task graph that rejects self,
  ancestor, and cyclic waits.
- Makes admission, execution leases, owner epochs, launch intent, and restart
  recovery durable across processes. Work that was accepted but never started
  resumes under its original task id; work whose side effects may have started
  remains explicitly indeterminate instead of being replayed.
- Adds persistent child-budget reservations and terminal usage receipts.
  Workflow and detached children settle actual usage before publishing their
  terminal state, while missing receipts retain their reservation rather than
  refunding an unknown cost.
- Replaces separate subagent status and execution modes with one task control
  plane: `task_list`, `task_wait`, `task_read_output`, `task_send_input`, and
  `task_stop`. Durable result delivery uses claim, inject, and acknowledgement
  so a restart cannot silently lose or duplicate a child result.
- Makes `bash` the only model-visible command launcher. Commands belong to a
  task and can outlive one tool call; `yield_time_ms` controls how long the call
  waits, `timeout_ms` controls process lifetime, and the shared task tools
  observe, feed, wait for, or stop the command.
- Defaults delegation to `adaptive`, adds the read-only `explorer` role, and
  enforces role tool ceilings in both provider schemas and runtime admission.
  Read-only investigations receive bounded evidence collection and one
  tool-free final report instead of running indefinitely.
- Adds deterministic cross-platform recovery and UI contracts for stopping a
  child while its parent is waiting. Windows fixtures now use host-native paths,
  and the platform validator follows the new `TerminalService` ownership
  boundary.
- Preserves hard child-role tool ceilings and truthful command cancellation,
  timeout, and exit terminals through the unified command lifecycle. Network
  permission grants now resume the blocked proxy connection without replaying
  the shell command or repeating side effects that happened before the block.
  Explicit background Workflow turns no longer wait for completion before
  returning control to the parent.
- Records real DeepSeek A/B coverage for multi-branch investigation,
  dependency tracing, and controlled parallel exploration, including timeout,
  token, tool-call, and process-tree cleanup evidence.

## Migration

- Replace `[subagents].max_parallel` with `max_running`. Optional
  `max_queued` and `max_live_tasks` independently bound accepted queued work
  and all non-terminal descendants.
- The model-facing `subagent` call no longer accepts `mode`; submission is
  runtime-managed and returns a task id.
- Replace `subagent_status` with `task_list`, `task_wait`, or
  `task_read_output`.
- Replace model-facing `exec_command` and `write_stdin` with `bash`,
  `task_read_output`, `task_send_input`, `task_wait`, and `task_stop`.

Existing conversation history remains readable. A legacy `max_parallel` key is
ignored rather than treated as a second capacity authority.
