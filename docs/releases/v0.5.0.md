# Orca v0.5.0

Terminal UI release: a redesigned interactive terminal UI with approvals in
place of the input, a tasks dock, session recap, and steering a running turn
with `Ctrl+Enter`. An unset or `auto` model now routes to `deepseek-flash`.
Background agents continue the conversation when they finish, and runtime fixes
make background turns, plan mode, and detached workers dependable.

## Changes

### Terminal UI

- A two-column welcome screen with contextual tips and a new whale mark.
- The input is drawn between two rules with a `›` prompt. The status bar shows
  the approval mode on the left (`⇧Tab` cycles it), the folder and git branch
  in the middle when there is room, and the model, reasoning effort, context
  left, usage, and `? help` on the right.
- The conversation marks your messages with `›` and Orca's replies with `●`,
  collapses reasoning to one `⋯ thinking` line, and draws each tool call with a
  short name, its output under a `│` rail, and a diff summary for edits.
- Long tool output and long notices collapse. `e` expands the latest one,
  `Shift+E` expands all of them, and a click toggles a row.
- An activity line above the input shows the running tool, the elapsed time,
  and the interrupt key, and lists queued follow-ups.
- Every dialog shares one panel, option, and hint style. The help panel is a
  table, the slash menu is aligned, and mention rows show their kind.
- The session picker groups conversations by project, with the current project
  first, and hides test sessions.
- CJK text wraps between characters and never past the edge; wrapped rows hang
  under their first column.
- Command output is drawn as text, never as terminal control sequences, and a
  shell command shows its output instead of its result envelope.

### Approvals, plan mode, and background work

- Approvals appear in place of the input. `Esc` denies, and `PgUp`/`PgDn`
  page through a preview taller than the panel.
- `/tasks` opens a dock under the conversation instead of replacing it, and
  `/agents` opens the Agent Workspace. Clicking an agent opens it: a finished
  agent opens its transcript, and a running one its live conversation or
  activity.
- A turn moved to the background with `Ctrl+B` stops at a tool call that needs
  approval, and the dock opens that approval. Tool calls the current mode
  allows continue on their own.
- A proposed plan stays where it sits in a streamed reply, and its **Plan
  ready** approval appears in live sessions. Switching into or out of plan mode
  in the middle of a conversation is noted where it happens, so the model
  follows the current mode.

### Input and turns

- `Ctrl+Enter` steers a follow-up into the running turn, which reads it after
  its current step; `Enter` still queues it for the next turn. This needs a
  terminal with the kitty keyboard protocol.
- `Esc` clears a non-empty draft, and `↑` brings it back until the next
  message is sent. With an empty input, `Esc` still takes back the last
  message.
- A turn that Orca starts itself, such as a queued message or a continuation
  after background agents finish, appears as its own turn, and `Esc`
  interrupts it.

### Session recap

- `/recap` summarizes the conversation in a strip above the input, and the
  full text opens in a panel. Returning to the terminal after about three quiet
  minutes writes a recap automatically. Recap is not available over an ACP
  attachment, and the TUI says so.

### Background agents and runtime

- When background agents finish while the main conversation is idle, Orca
  starts a turn to continue with their results. It does so only while the TUI
  shows that conversation, never over queued work or a pending question, and
  not again for the same results.
- Background agents report progress and permission requests while the parent
  turn runs, instead of showing "running" until it ends. An agent whose relay
  could not deliver its result settles from the task registry, and an agent
  launched from a queued message or a continuation turn no longer fails to
  start.
- Detached workers no longer hold the terminal open after the TUI exits, and
  they end once their task is gone or their lease is lost. A transient
  continuation write error no longer ends a healthy background agent.
- A relayed usage event keeps its digest because floats now parse exactly, so
  an intact relay is no longer quarantined.
- A turn cancelled while committing a response ends as cancelled, not as a
  runtime consistency failure.
- A backgrounded response that reuses an earlier tool call id is renamed the
  way the foreground does, instead of wedging the task.
- Shell sessions with a workspace lifetime keep running after the turn that
  started them.

### Model and credentials

- An unset or `auto` model routes to `deepseek-flash` instead of
  `deepseek-v4-pro`. The welcome screen and status bar show the resolved model.
- `~/.orca/auth.json` is written readable by its owner only (`0600`). Saving
  the key again also tightens a file an earlier version left readable.

### Evaluation and documentation

- The evaluation harness, ledger, and current results are in the repository;
  the terminal-bench adapter pipes instructions so they cannot match
  themselves.
- A new Terminal UI guide. The approval modes, mention search, side
  conversations, models, and quickstart docs describe the current
  interactions, and the website's terminal shows the new UI.

## Compatibility

- **Default model.** A run without an explicit model now uses
  `deepseek-flash`. Set `model = "deepseek-v4-pro"` or pass
  `--model deepseek-v4-pro` to keep Pro. JSONL `model.routed` events for such
  runs report the reason `default_flash` instead of `default_pro`.
- **Keys.** `Esc` on an approval denies the call. `Esc` with text in the input
  clears the draft, where it used to do nothing. `/tasks` toggles the tasks
  dock; use `/agents` for the full Agent Workspace.
- **API key file.** An existing `~/.orca/auth.json` keeps its mode until the
  key is saved again. Run `chmod 600 ~/.orca/auth.json` to tighten it now.

Existing configurations and conversation history remain readable.
