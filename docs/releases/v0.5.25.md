# Orca v0.5.25

Orca keeps replies cut short by Esc or the output limit, shows provider retries as they happen, and tells you when opening a saved session requires a newer version.

## Changes

- **Keep a reply cut short.** If you press Esc after the model has written visible text, the reply stays on screen with `(interrupted)`. At the output limit it stays with `(stopped at the output limit)`. You can ask the model to continue, even after resuming the session. Orca drops unfinished tool calls, and ACP clients keep the text they already received without a reload or duplicate reply. The turn still ends `Cancelled` or `Failed`, respectively, with the same exit code as before.
- **See when a provider retry will run.** The terminal status line shows `Retrying in <n>s (attempt <k> of <max>): <reason>`, including any shared cooldown in the wait. `orca exec --output-format jsonl` reports `provider.retry` with `attempt`, `max_attempts`, `delay_ms`, `kind` and `reason`. The attempt count reflects HTTP sends already made. After a successful retry, `context.updated` shows that request's input tokens. `usage.updated` and cost budgets still include usage reported by failed attempts.
- **Know when a session needs a newer Orca.** The picker shows `Newer version` (`newer_version`) when a transcript uses a higher `schema_version` or contains an unrecognized required record. Resume, fork, rename and export refuse the session with `please upgrade Orca to open it`.
- **Background commands report completion during the turn.** The model sees the notice at the next step where its tool calls have settled. If the model is giving its final answer, the notice waits for the next turn. It includes up to the last 8 KiB of output and tells the model which `task_id` and `cursor` to pass to `task_read_output` for earlier output still on hand. Orca skips the notice when `task_wait` or `task_read_output` has already returned the final status to the model, or the model has called `task_stop`.
- **MCP server instructions reach the model.** The `instructions` returned by a server's `initialize` call go in a separate system message after Orca's internal context. Each `<mcp_server_instructions>` block applies to that server's tools and resources. Orca limits the text to 32 KiB per server and the message to 64 KiB and 4,096 tokens. The instructions arrive with the server's tools, including for child agents, and are withdrawn if the connection is invalidated.

## Fixes

- **DeepSeek errors use the HTTP status.** HTTP 429 is `RateLimit`, 5xx is `Server`, and a context-length 400 or 413 is `ContextExceeded`. A number in the error text, such as `5000 tokens`, no longer triggers a retry on its own. A rejected key reads `DeepSeek rejected the API key`. A balance refusal reads `DeepSeek reports an insufficient account balance`. HTTP diagnostics are redacted and bounded to 4 KiB, with `(HTTP <status>, request id <id>)` when both values are available.
- **Orca's tools keep their places under DeepSeek's cap.** Built-in and configured external tools take priority, and MCP tools fill the remaining places in name order. At startup, Orca warns if the available tools can exceed the limit. With no external tools configured, it estimates how many MCP tools may be omitted and points to `disabled_tools` and `enabled_tools`. When the list of omitted tools changes and is nonempty, Orca reports the count and up to the first three names in `DeepSeek request left out <count> tools: <names>. The request limit is 128.`
- **A stopped `run_script` keeps its log.** When a script reaches its time or memory limit, the result includes the lines it logged before stopping, up to the usual output limit.
- **`edit` and `write_file` preserve CRLF.** `edit` matches multiline text with normalized line endings in a file whose line endings are mostly CRLF, then writes CRLF back. When overwriting a file, `write_file` checks for a CRLF majority in the first 64 KiB to choose the line endings.
- **Session listings and search honor the transcript.** Listings refresh outdated index entries in batches before applying filters, and search skips unrecognized records marked `"ignorable": true`. A transcript with a repeated top-level key or missing metadata is marked unhealthy.

## Compatibility

- **Session health and records.** Consumers of session listings may see `newer_version`. Orca 0.5.25 skips unknown records marked `"ignorable": true` and preserves their bytes and position on rewrite or export. A fork copies the records Orca understands. Orca 0.5.24 and earlier refuse sessions containing those unknown records, even with the flag. `session.meta` now accepts unknown fields. Changes that require a newer reader still raise `schema_version`.
- **Provider events and errors.** The new JSONL event `provider.retry` is live only and leaves session files unchanged. `ProviderError` can include `http_status` and `request_id`, which are omitted when unavailable.
- **Kept replies.** A cut-short assistant reply is recorded as an ordinary completed response with an optional `cut_short` field that older Orca versions ignore. In JSONL, `model.response.completed` carries `cut_short` as `interrupted` or `output_limit`.
- **MCP requests.** DeepSeek's 128-tool limit now gives Orca's own tools priority. The separate MCP instructions message changes request bytes only for sessions whose MCP servers send instructions.
- **Prompt cache.** The system prompt now says `A background command's completion is reported at your next step in this turn, or when the next turn starts.` This changes the cached prompt prefix once after upgrading for every session that receives the shell-command guidance, including default sessions.

## Verification

Regression tests cover reading and rewriting newer session records, retry timing and usage, background-command notices in the next model request, and replaying a kept reply with the v0.5.23 record format. Tests also cover CRLF writes, stopped-script logs and MCP tool selection. Release gates run with framework retries disabled. Linux and native Windows x64/ARM64 checks must pass on the final main commit before tagging.

```sh
cargo check
env -u NODE_OPTIONS node scripts/release/verify-version-sync.mjs
env -u NODE_OPTIONS npm --prefix site ci
env -u NODE_OPTIONS npm --prefix site run build
env -u NODE_OPTIONS npm --prefix site run check:seo
cargo fmt --all -- --check
```

## Upgrade

```sh
npm install -g @blade-ai/orca@0.5.25
orca --version
```

Or install the native binary with the installer on https://orcaagent.dev/.
