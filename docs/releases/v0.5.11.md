# Orca v0.5.11

Release-note draft. Verification and release acceptance are pending.

Changes since v0.5.10:
- On macOS 14 or later, the interactive TUI's main session can inspect and
  operate other apps with approval for each app and Esc to stop.
- Computer use tries background actions first and reports foreground use.
  Command shortcuts require a short foreground switch; the user can turn
  foreground fallback off.
- Live conversations keep only the newest three tool images. Tool image
  types are detected from file headers, and resuming a session does not load
  tool image data into the model's conversation.
- The Terminal-Bench adapter keeps the task instruction out of command lines,
  so a task's `pkill -f` cannot match that text and end the trial (#126).

## Changes

### Computer use on macOS

The `computer` tool can list and launch apps, inspect windows and their
accessibility elements, click, type, send keys, and scroll. Use it to check a
UI or work in an app without a command-line interface. It requires macOS 14
or later and Accessibility and Screen Recording permissions for the terminal
running Orca. Input Monitoring is also needed if the driver reports missing
listening access when installing the Esc listener.

App approvals offer **Allow once**, **Allow this app this session**,
**Always allow this app (saved)**, and **Deny**. The saved option writes a
`computer` allow rule with the app's exact bundle id as its `pattern` to the
user configuration. Password text entry asks separately each time, with only
**Allow typing this once** or **Deny**. This covers `type` and text-entering
`key` actions: printable keys alone or with Shift/Option, and `Cmd+V` (also
with Shift/Option). App grants and patterned allow rules, even one naming an
explicit `#secure` target, do not preapprove these calls. Only a whole-tool
allow rule for `computer` without a `pattern` does. Password managers in the
built-in list and apps declaring the finance category are blocked by default
unless an exact bundle-id allow
rule lifts the block; the host terminal remains blocked regardless of rules.
Listed terminals, IDEs, Finder, System Settings, and browsers carry risk
warnings. Deny rules take precedence over allow rules.

If password focus is detected only during a point action or from a stale
observation, Orca refuses unapproved input and sends no text. The result
instructs the agent to observe again and target the secure field by its element id
to request approval on retry.

For `computer`, plan mode permits only `list_apps` and `observe`.
`list_apps` needs no app approval; `observe` and app calls in `full-auto`
still require it unless an applicable rule or app grant already allows them.

Orca operates in the background where possible. `launch_app` starts apps or
opens URLs/files without requesting activation; an app may still choose to
activate itself. Actions that need the foreground briefly switch to the
target app and restore the previous app and pointer, and the result reports
foreground use. A `key` containing Command
always takes this path: background Command shortcuts did not reach the app
in the real-Mac checks. `[computer_use] foreground_fallback` defaults to
`true`; setting it to `false` in the user configuration refuses those actions.
Project configuration cannot set it. From the first `computer` call until
the turn ends, Orca captures Esc system-wide to interrupt the running turn,
including when another app is in the foreground or a screenshot preview is
open.

Click the `[N image(s) attached]` line under a tool result to preview its
screenshot, and press `q` to close the preview. A `truncated` observation
means the accessibility tree reached its time limit and is partial; use
`query` to narrow a new observation or point targets from the latest
screenshot, then check the action result.

Computer use is limited to the interactive TUI's main session. Dragging,
direct field-value assignment, subagents, workflow children, ACP, and
`orca exec` are not supported. A whole-tool deny rule removes `computer` from
the model's available tools. The English and Chinese site docs describe
setup, approvals, risk levels, foreground switching, disabling the tool, and
privacy; the configuration pages and README link to them.

### Tool images

- The live conversation retains data for only the newest three tool images,
  matching the request limit. Older observations keep their resource
  references and a note that newer observations superseded them; the TUI
  loads older previews from their resource files.
- PNG, JPEG, GIF, and WebP are detected from their file headers, overriding a
  mismatched declared type. Unsupported image data is dropped with a note.
- Deep compaction counts the tool images the conversation retains; superseded
  images beyond the newest three no longer count.
- Resuming a session keeps tool-image references and text without reading
  tool image data back into the model's conversation.
- Screenshots are sent to the provider with `deepseek-flash` (including its
  legacy names `deepseek-v4-flash` and `deepseek-v4-flash-vision-exp`) or `auto`.
  Other model selections get text and a note in place of tool images, even
  when a custom model supports user-attached images. Tool images are not sent
  to the separate vision model used to describe user attachments.

### Terminal-Bench adapter

The adapters pass the task instruction through the `ORCA_INSTRUCTION`
environment variable, then copy and unset it before a shell builtin sends it
to Orca's stdin. Previously it was still present in the shell's command line:
a task's `pkill -f` could match a path in that instruction and end the trial.
Neither Orca nor its task commands inherit the variable. This fixes #126,
merged to main on October 12, 2026.

## Compatibility

- Configurations and sessions from v0.5.10 remain readable. The new
  `foreground_fallback` setting defaults to `true` when absent.
- Computer use is available on macOS 14 or later in the interactive TUI's
  main session. Linux, Windows, ACP, and headless execution do not gain the
  tool.
- Older tool screenshots remain available for TUI preview from stored
  resource files, but are not reloaded into resumed model conversations.
