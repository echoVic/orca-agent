# Orca v0.3.14

Orca v0.3.14 strengthens long-running TUI and background-agent reliability
across process boundaries, makes attachment event ownership explicit, and adds
deterministic DeepSeek cache-prefix identity with real-provider verification.

## What Changed

- **Fenced background task ownership.** Persistent task records now carry a
  lease owner, expiry, fencing epoch, and publication revision. Expired or
  replaced workers cannot publish a stale terminal result; another process can
  take over an abandoned task, and task status refreshes from durable state.
  Stop requests revoke the active lease before signalling the verified worker.
- **One TUI attachment routing authority.** Parent and Side Conversation events
  now enter through a centralized attachment router. Activation publication,
  deferred parent-interaction replay, and relay ownership are serialized, so a
  rotated relay cannot publish against the wrong attachment and queued
  interactions replay in FIFO order before new active events.
- **Explicit DeepSeek cache identity.** DeepSeek tool schemas are ordered by
  function name before the 128-tool cap. Runtime history records an audit-only
  cache checkpoint derived from the lowered message prefix, selected tool
  schemas, endpoint, model, and reasoning mode. Forks do not inherit this
  checkpoint as conversation state, and transcript readers ignore it.
- **Verified remote compaction.** A credential-gated production compactor smoke
  exercises the real DeepSeek summary path. The release evaluation reduced a
  34-message fixture to 9 messages and wire pressure from 4,992 to 1,216 tokens
  while retaining the current request and a durable summary baseline.
- **Narrower ThreadActor state ownership.** Runtime thread/event identity,
  usage accounting, and recovered approval registration now live behind a
  private actor-state boundary rather than remaining broadly mutable runtime
  host fields.

## Compatibility

CLI arguments, TUI workflows, server/JSONL and ACP protocols, and existing
session records remain compatible. `BackgroundTaskSummary` gains an optional
`publicationRevision` field, and session history may contain an additive
audit-only `provider.prompt_cache_checkpoint` record that older readers ignore.

The legacy pending-interaction store API remains as a documented no-op
compatibility projection. It is not removed in this release because the legacy
Goal continuation path still exists and the major-version semver gate has not
run.

## Verification

- Cross-process task lease, takeover, stop, publication, recovery, and PTY gates
- Runtime, provider, TUI attachment-routing, and compaction focused suites
- DeepSeek prompt-cache identity real-API verification with a non-zero second
  request cache hit
- DeepSeek remote-compaction real-API verification
- Runtime surface and Windows platform contract validators
- Workspace tests, release helper self-tests, website build, SEO, version sync,
  formatting, and diff checks

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.14
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.14 sh
```
