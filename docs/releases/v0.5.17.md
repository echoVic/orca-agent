# Orca v0.5.17

This patch strengthens session recovery, retry control and evidence about what a run did, and includes the CLI permission changes and Orca Agent branding merged since v0.5.16.

## Changes

- New interactive TUI sessions start with Full Access. Use `--yolo` to select full-auto explicitly when launching or resuming, or switch the active session from a pending approval. Use `orca app-server` and `orca acp` for protocol serving, `-C`/`--cd` to select a workspace, and `--continue` to resume the latest TUI session; legacy forms remain accepted.
- Headless completion reports whether saved history is actually durable and resumable, with a recovery command or reason recovery is unavailable. The result includes unresolved descendant blockers. Deleted, truncated or replaced logs cannot advertise successful recovery.
- A bounded workspace observation records net content changes, including shell writes and changes to files that were already dirty. Attribution remains `unknown`; incomplete observations do not imply no changes. `writes_applied` continues to describe successful file-tool receipts.
- Provider requests in one process share endpoint-and-credential cooldowns for 429/503 and parse both forms of `Retry-After`. Runtime, HTTP and recovery retries share the actual-send cap and wait budget; cancellation and deadlines stop waiting and preserve known usage.
- Compression records local token estimates, elapsed time, summary calls and known usage/cost. Automatic compression shares the remaining operation deadline and cancellation. Streamed responses record the first non-empty reasoning, text or tool delta and its type.
- Capability evaluation retains actual configuration, fixture/verifier fingerprints, paired read evidence for discovered constraints and independent SQLite verification. Repeated runs report success rates, variance and Wilson intervals while preserving failed-attempt costs.
- Models that need vision descriptions retain quoted User records for tool screenshots, with snapshot identity and current/historical labels. Duplicate observations, prefix trimming and restored sessions preserve useful descriptions. Direct Flash vision remains supported.
- The product is identified as Orca Agent, with the official mark used in the website social card.
- Built-in DeepSeek prices and peak hours were checked against the official pricing page on 2026-11-05; rates are unchanged.

## Compatibility

- **Permission default:** new interactive sessions now use Full Access. Choose `--approval-mode suggest` or `--plan` when you want a more restrictive session. Existing explicit modes and legacy protocol flags remain available.
- Headless JSONL history remains opt-in through `--save-history`; `--no-history` still disables it. Check `resumable` before using a recovery command.
- Completion and observation fields are additive. Exit codes and `writes_applied` retain their existing meanings.
- Workspace observation is bounded and platform dependent. Unknown or incomplete measurements remain unknown; estimates are not invoices. First delta may be reasoning or a tool call, rather than visible answer text. Shared cooldowns apply within one process.

## Verification

The implementation was verified on macOS with 4,798 workspace tests passing and one local proxy timeout; an unchanged serial recheck passed. The TUI library passed 1,848 tests with one nextest output-pipe cleanup warning, PTY contracts passed 40 tests, and capability Python tests passed 60 tests. The full evidence and limits are in `docs/reports/2026-11-04-harness-evidence-delivery.md`.

The reviewed platform inventory includes the cfg-gated Unix completion file flags and workspace directory traversal. Windows completion uses reparse-point rejection; workspace observation reports `safe_directory_traversal_unavailable` on Windows instead of unsafe path recursion.

Release gates run with framework retries disabled. Linux and native Windows x64/ARM64 must pass on the final main commit before this tag is pushed. The release workflow builds all six target archives, publishes npm packages and checks published archive/package checksums and clean installs.

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -j 1
cargo nextest run -p orca-tui --lib --locked --profile ci-serial --retries 0
cargo nextest run --test tui_pty_contract --locked --profile ci-serial --retries 0
cargo nextest run --workspace --all-targets --locked --profile ci --no-fail-fast --retries 0
node scripts/release/verify-version-sync.mjs
node scripts/release/test-stage-npm.mjs
node scripts/release/test-verify-published.mjs
npm --prefix site run build
npm --prefix site run check:seo
```
