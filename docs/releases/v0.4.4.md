# Orca v0.4.4

Patch release: complete the final TUI state-ownership convergence slice.

## TUI State Ownership

- Move `TuiEvent`, `UserAction`, interaction keys, response values, and related protocol records into `crates/orca-tui/src/protocol.rs`.
- Move `AppState::update` and its event-dispatch/reducer helpers into `crates/orca-tui/src/state_reducer.rs`.
- Give transcript revisions, render caches, search, streaming assembly, and flush watermarks a dedicated `TranscriptState` owner.
- Give pending user-input and MCP acknowledgement state a dedicated `InteractionState` owner.
- Give scrolling, selection, frame geometry, clipboard notices, and unread counts a dedicated `ViewportState` owner.
- Move owner-specific invariant tests with their owners and retain only cross-owner behavior in the state integration suite.

`AppState` remains the composition root for session, projection, composer, and owner state. Protocol implementations have one owner; `types` keeps precise public and crate-private re-exports so existing in-tree paths do not duplicate definitions.

## Compatibility

- CLI commands, JSONL session metadata, runtime surface wire formats, npm package names, and release archive layouts remain unchanged.
- No persisted session, goal, or workflow formats change.
- The TUI source layout changes: new code should import protocol and state owners directly rather than adding fields or events to `types.rs`.
