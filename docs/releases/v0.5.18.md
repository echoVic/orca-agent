# Orca v0.5.18

This patch makes a stuck shell interruptible and a failed session write survivable, and adds endpoint controls for custom and reverse-proxy providers along with a new `web_fetch` tool for reading URLs.

## Changes

- Esc now stops the command the TUI is showing at the operating-system level. Runtime shell sessions and tool subprocesses register their active process group with a handle shared by the TUI, and Esc kills that group directly before asking the runtime to cancel, so an interrupt no longer depends on the session transcript being writable. Timed-out and cancelled process groups receive SIGTERM, a 50 ms grace period follows, then SIGKILL. The default `[tools].shell_timeout_secs = 0`, previously no cap, now becomes a built-in ten-minute hard ceiling, and a command whose pipes were inherited by escaped descendants waits at most two seconds for its readers after the child exits.
- Failed session persistence degrades instead of blocking work. When appending a tool result to the JSONL transcript fails, the result stays in the live conversation, Orca warns and marks the writer degraded, and the turn continues; the same applies when writing the assistant response event fails. The degraded flag is shared by every clone of the writer, so the whole transcript is known to be unreliable rather than the tool call failing.
- Custom and reverse-proxy provider endpoints are easier to configure and diagnose. `ORCA_BASE_URL` and the legacy `DEEPSEEK_BASE_URL` are trimmed of surrounding whitespace and trailing slashes, and an empty value falls back to the default endpoint instead of producing requests to `/chat/completions`. The new `/base-url` command shows the effective endpoint, marks a configured one as `(custom)`, sets a URL for the current session, and `reset` restores the default; `/status` lists the endpoint too. `orca doctor` calls out a custom endpoint and warns that third-party services usually do not support `/beta` strict tools. `ORCA_STRICT_TOOLS=1` forces the strict tool payload onto a custom endpoint that accepts it; only the exact value `1` enables it, and only an endpoint whose URL ends in `/beta` is strict without it. The provider source now documents example free and self-hosted compatible endpoints — SiliconFlow, OpenRouter and a local Ollama server — with the warning not to configure them with a `/beta` suffix.
- New `web_fetch` tool returns the readable text of a URL. HTML input is reduced to text: scripts, styles, navigation, footers, asides and heads are removed, block tags become newlines, common entities are decoded, and the page title and meta description lead the result as Markdown; plain text passes through unchanged. A request has a 60-second timeout, an 8 MiB body cap and at most 100,000 characters of output. `http` URLs are upgraded to `https`, non-HTTP schemes, URL credentials and single-label hosts are rejected, and redirects are followed only within the same origin and port for at most ten hops; a cross-origin redirect fails. An optional `prompt` keeps only the paragraphs that mention one of its keywords and falls back to the whole text when nothing matches. The fetch uses the same HTTP client and cancellation path as `web_search`.

## Compatibility

- **Interrupts:** Esc sends SIGKILL (or the platform equivalent) to the running command's process group before the runtime cancellation runs. A foreground command stopped that way is killed outright rather than asked to stop, so its own traps and child cleanup may not run. The interrupt path does not read or write the session transcript.
- **Session history:** a failed history write no longer fails the tool call or the turn. The transcript is marked degraded and may be missing the affected item, so a session recovered from that file may not contain it; Orca prints a warning on stderr when the write fails.
- **Shell timeout:** `[tools].shell_timeout_secs = 0` (the default) now applies a ten-minute hard cap instead of removing the limit, so a command that would have run longer is stopped; a model-supplied `timeout_ms` still shortens the deadline. Explicit non-zero values keep their meaning, up to the existing one-hour clamp.
- **Custom endpoints:** `ORCA_BASE_URL` and `DEEPSEEK_BASE_URL` keep their precedence, but trailing slashes and surrounding whitespace are removed and an empty value now means the default DeepSeek endpoint. `/base-url` changes only the current session and is not written to `config.toml`. A custom endpoint is never sent strict tool schemas unless `ORCA_STRICT_TOOLS=1`, and forcing strict mode on a service that does not support it can make requests fail; `true` is not the same as `1`.
- **`web_fetch`:** the tool name is additive and existing tool names are unchanged. It requires network access, follows only same-origin redirects, and returns at most 100,000 characters, so a long page is truncated. Cross-origin redirects are reported as errors rather than followed.

## Verification

Release gates run with framework retries disabled. Linux and native Windows x64/ARM64 checks must pass on the final main commit before the tag is pushed; a tag-triggered release reuses those results instead of rerunning the full suites, while a manual dispatch runs every gate below. The release workflow builds all six target archives, publishes the npm packages, and checks the published archive and package checksums and clean installs.

The changes in this release ship with unit tests across the core, provider, tools, runtime and TUI crates: environment base-URL normalisation and strict-tool gating, process-group stopping and pipe-drain bounds, degraded session writing, `/base-url` parsing and dispatch, endpoint diagnostics, and `web_fetch` URL normalisation, redirect guarding, HTML extraction, entity decoding and prompt filtering. The final gates run in CI.

```sh
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --locked -j 1
cargo nextest run -p orca-tui --lib --locked --profile ci-serial --retries 0
cargo nextest run --test tui_pty_contract --locked --profile ci-serial --retries 0
cargo nextest run --workspace --all-targets --locked --profile ci --no-fail-fast --retries 0
node scripts/release/verify-version-sync.mjs
node scripts/release/test-stage-npm.mjs
node scripts/release/test-verify-published.mjs
npm --prefix site run build
npm --prefix site run check:seo
```

```sh
npm install -g @blade-ai/orca@0.5.18

```
