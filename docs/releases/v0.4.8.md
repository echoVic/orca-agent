# Orca v0.4.8

Interactive subagent workspace release.

Orca already carried synchronous, detached, and workflow-child activity through
one durable runtime surface. This release makes that state useful in the default
TUI: users can see who is working, inspect what each child is doing, and invoke
only the controls that child can safely accept.

## Unified task workspace

- Keep up to four active child summaries visible in Conversation without
  displacing the transcript or composer.
- Add `/tasks` as the unified workspace for ordinary subagents, detached tasks,
  shell and monitor work, workflow runs, and workflow children. `/agents`
  remains an alias; `/workflows` remains the workflow-specific run tree.
- Preserve stable row identity while activity changes, sort the lightweight
  Conversation summary by real activity time, and show status, turn, usage,
  recovery state, and supported controls in the full workspace.
- Retain a bounded history of eight activity entries per child instead of
  exposing only its most recent tool or phase.

## Inspect and control child work

- Open a revision-fenced live transcript from the selected child and follow new
  output without reading an arbitrary filesystem path.
- Stop one selected child without cancelling its siblings.
- Resume or retry only a resumable, non-indeterminate continuation. Retry tells
  the child to inspect external state before repeating a possible side effect.
- Route follow-up messages through the child continuation owner with explicit
  task, attempt, checkpoint, and revision fences.

## Cancellation and recovery

- Commit one actor-owned terminal transition when Esc cancels a running
  subagent, then absorb activity that arrives late from the cancelled attempt.
  The parent prompt remains usable and the terminal does not enter a redraw or
  event-spam loop.
- Poll the typed surface projection while the TUI is idle, so detached activity
  already present in the runtime becomes visible without another user action.
- Preserve activity history and continuation state across actor restart, with
  the same fail-closed rules for indeterminate side effects.

## Workflow preview

- Render `WorkflowDraft` as a compact preview with phases, estimated agents,
  concurrency, mutation risk, and expandable JavaScript.
- Keep `/workflows` as the dedicated run manager while `/tasks` provides the
  cross-kind operational view.

Workflow-level pause/resume still requires the workflow ingress receipt to
participate in the same actor-owned revision transition. This release does not
expose a control that would bypass that ownership boundary.
