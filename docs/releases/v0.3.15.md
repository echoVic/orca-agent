# Orca v0.3.15

Orca v0.3.15 eliminates the high-parallelism test hangs and flaky failures
that appeared under `cargo test --test-threads=16`, hardens the goal store
against concurrent opens, and makes the default local verification command
(`cargo test --lib`) reliable again.

## What Changed

- **Thread-local test homes.** The test harness no longer redirects the
  `ORCA_HOME` environment variable. Per-test private homes are thread-local
  overrides carried by `orca-core` folder trust, and `RuntimeHost` installs
  the calling test's home on all of its threads (supervisor, tokio workers,
  blocking pool), so a hosted test resolves one consistent private home while
  every other test resolves the process-wide isolated home. This removes the
  exclusive test-env lock that deadlocked host workers against `with_orca_home`
  closures, eliminating the unbounded `wait_operation_terminal` /
  `host.shutdown()` stalls under 16-way parallelism.
- **Fenced goal schema initialization.** `GoalStore` opens serialize schema
  DDL behind a sibling cross-process file lock (following the task-registry
  precedent) and set WAL once at initialization, so concurrent openers of the
  same database no longer race `Immediate` DDL transactions
  (`database is locked` / `disk I/O error` / `no such table: goal_meta`).
- **Serialized shared-index tests.** Tests that touch the shared session and
  task indexes hold a plain serialization mutex again; home resolution never
  takes it, so a test waiting on its own host threads cannot deadlock.
- **Reliable parallel injections.** The typed-provider-outcome persistence
  failure injection is keyed by session so parallel tests cannot consume each
  other's injection budget, and two load-sensitive tests poll for actor state
  instead of racing a 20 ms budget or an immediate probe.

## Compatibility

CLI arguments, TUI workflows, server/JSONL and ACP protocols, and existing
session records remain compatible. Test-support helpers are `#[cfg(test)]` or
`#[doc(hidden)]`; no production behavior, persisted format, or public API
changes.

- Runtime surface, version sync, npm staging, and website build gates

## Upgrade

```bash
npm install -g @blade-ai/orca@0.3.15
```

macOS and Linux native installer:

```bash
curl -fsSL https://orcaagent.dev/install.sh | \
  INSTALL_DIR=/usr/local/bin ORCA_VERSION=0.3.15 sh
```

Windows PowerShell, including workspace sandbox setup:

```powershell
powershell -ExecutionPolicy Bypass -Command "iwr -useb https://orcaagent.dev/install.ps1 | iex"
```
