## 新套件 1：goal 模式（`scripts/eval/goal_probe.py`）

Goal 模式是 TUI/runtime 特性（`docs/goal-mode.md`），`/goal` 是唯一入口，`$ORCA_HOME/goals.sqlite3`
是权威状态。探针用真实 TUI（tmux）+ 脚本化 mock provider 驱动，断言数据库与 TUI 存活：

| 用例 | 断言 | 结果 |
|---|---|---|
| create | `/goal <objective>` 建行 + 1 run + ≥1 turn + objective 一致 | PASS |
| no-progress | 模型始终不声明终态 → 3 个 outer turn 后以 `no_progress` 暂停（不无限循环） | PASS |
| pause | `/goal pause` → paused（reason user） | PASS |
| resume | `/goal resume` → 新 run，状态回 active | PASS |
| clear | `/goal clear` → goals 行删除 | PASS |
| recovery | 杀掉 TUI 后用 `--continue` 重启，goal 仍在库里 | PASS |

边界行为（探索）：裸 `/goal` 显示 "ℹ No goal is currently set."；无会话时 clear/edit/pause/resume
报 "The session must start before you can change a goal."（符合文档"需已记录会话"）；3000 字符目标可正常建 goal。

## 发现的问题

**#151 — 未知 `/workflow:<name>` 报 `RuntimeUnavailable`**：runtime 实际返回
``workflow script `x` not found``（`crates/orca-runtime/src/workflow/script.rs:243`），但 surface 命令错误
只有两个变体（`runtime_surface/commands.rs:357`），launch 路径每步 `map_err(|_| RuntimeUnavailable)`
丢弃原因（`runtime_actor/thread_actor_operation.rs:2620-2650`），TUI 再用 `{error:?}` 渲染
（`orca-tui/src/surface_client.rs:1789`）。复现与证据由 `workflow_mode_probe.py` 的 unknown 用例给出。
