# v0.3.14 Review Regression Fixes

## Problem

The standard parallel `runtime_host` integration suite can resolve a task
registry under a temporary `ORCA_HOME` owned by another test. Once that test
removes the directory, durable task mutations fail or reload a missing task.
Separately, an adopted async worker that exits without publishing a terminal
record is reaped but remains `Running` forever.

## Contract

- The `runtime_host` integration binary uses one process-wide temporary
  `ORCA_HOME` for its entire lifetime. Tests that need exclusive access to
  shared files still serialize their closure, but never replace or delete the
  process-wide home while other tests run.
- Durable task files remain authoritative. Missing persistence is not converted
  into an in-memory success path.
- A reaper may publish `Failed` only when the durable record still identifies
  the exited child and its observed lease owner/epoch is current and unexpired.
- Lease owner identities bind an opaque UUID to the acquiring process ID, so a
  reaper cannot mistake a recovery process's current lease for the exited
  child worker's lease.
- If the record is terminal, its worker identity changed, or its lease was
  revoked, expired, or taken over, the reaper only refreshes local state.
- A child that exits before acquiring a lease may be failed only when the
  adoption publication revision is still unchanged.

## Verification

- A focused task test covers worker exit without terminal publication.
- Existing terminal-publication and takeover fencing tests remain green.
- `cargo test -p orca-runtime --test runtime_host --locked` passes with default
  test parallelism, without relying on nextest retries.
- The repository CI `nextest` profile, formatting, and diff checks pass before
  integration. Strict clippy is evaluated separately so unrelated lint-baseline
  findings are reported rather than folded into this behavior fix.
