# Code Mode (read-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a `run_script` tool whose JavaScript calls `read_file`, `glob`, `grep` and `git_status` directly, with only the script's output returned to the model.

**Architecture:** The script runs in a confined Node child process whose API lives in the script's own realm (the pattern `workflow/host.mjs` uses since `c8e3ca32`). Each tool call the script makes is a JSON line to the Rust runtime, which checks it, runs the PreToolUse hook, executes it through the read-only executor and writes the answer back. `run_script` itself is a runtime-owned, read-only, non-concurrent tool dispatched by `RuntimeToolRouter`.

**Tech Stack:** Rust (orca-core, orca-tools, orca-runtime), Node `node:vm`, cargo nextest.

**Spec:** `docs/superpowers/specs/2026-11-18-code-mode-design.md`

## Global Constraints

- Tool name `run_script`; one argument, `script` (string).
- Script tools: exactly `read_file`, `glob`, `grep`, `git_status`.
- Defaults: `enabled = false`, `timeout_secs = 60`, `max_tool_calls = 100`; inner result limit 256 KiB; protocol line limit 1 MiB.
- Inner request id: `<run_script call id>:<n>`, `n` from 1.
- No other tool's schema, description or visibility changes.
- Every process launch goes through `ExecutionBroker` (`scripts/validate-execution-broker-boundary.mjs`).
- Before finishing: `cargo fmt --all -- --check`, the four `scripts/validate-*.mjs` validators, and `cargo nextest run --workspace --all-targets --locked --profile ci --no-fail-fast --retries 0`.

### Task 3: The script host

**Files:** Create `crates/orca-runtime/src/script/{mod.rs,host.rs,host.mjs}`, `tests/script_host_contract.rs`. Modify `crates/orca-runtime/src/workflow/host.rs` (visibility only: `node_confinement_args`, `node_entry_path`, `WorkflowHostChild`, `WorkflowHostFileGuard`, `read_bounded_workflow_frame`), `crates/orca-runtime/src/lib.rs`.

**Produces:**

```rust
pub struct ScriptHostLimits { pub wall_clock: Duration, pub max_line_bytes: usize }
pub struct ScriptToolCall { pub call_id: String, pub tool: String, pub arguments: serde_json::Value }
pub enum ScriptHostOutcome { Completed { output: String }, Failed { error: String } }
pub struct ScriptHost;
impl ScriptHost {
    /// Runs `script`, answering each tool call with `on_tool_call`
    /// (`Ok(text)` resolves it, `Err(text)` rejects it).
    pub fn run(
        script: &str,
        limits: ScriptHostLimits,
        on_tool_call: &mut dyn FnMut(ScriptToolCall) -> Result<String, String>,
        should_cancel: &dyn Fn() -> bool,
    ) -> io::Result<ScriptHostOutcome>;
}
```

`host.mjs`: argv `[host, scriptPath]`. Host realm keeps `hostCall(operation, json) -> json` with operations `tool_call` (emits `{"type":"tool_call",call_id,tool,arguments}`, returns the id), `completed`, `failed`; stdin lines `tool_result` / `tool_error` are handed to the realm as text. The realm function (`installScriptApi(hostCall)`, compiled in the context via `vm.runInContext`) defines `tools.{read_file,glob,grep,git_status}`, `console.log`, runs the script compiled as an async function body, and reports the assembled output. Same rules as the workflow host: `hostCall` never throws, the realm wraps it in a binding-less `catch`, the host never awaits a realm promise, `importModuleDynamically` is omitted.

`ScriptHost::run`: write the script to a temp file; start Node through `ExecutionBroker::launch_user_trusted` with `node_confinement_args(node, host_path, script_path, None)` and `remove_credential_env`; read stdout lines on a thread (bounded by `max_line_bytes`); loop on `recv_timeout(50ms)` checking `should_cancel` and the deadline; kill the tree on cancel (`io::ErrorKind::Interrupted`), on deadline (`Failed` "script ran longer than Ns") and on an oversized or unparsable line (`Failed`); on EOF without a terminal line return `Failed` with the stderr tail.

Contract tests (each skips when `!WorkflowHost::node_available()`):

- [ ] `a_script_returns_what_it_computed_from_tool_results`: script `const a = await tools.read_file({ path: "a" }); return a.toUpperCase();`, handler returns `"hello"` → `Completed { output: "HELLO" }`, handler saw tool `read_file`, arguments `{"path":"a"}`.
- [ ] `logged_lines_come_before_the_returned_value`: `console.log("one", 2); return { ok: true };` → output `"one 2\n{\n  \"ok\": true\n}"`.
- [ ] `a_script_that_returns_nothing_has_only_its_log`: `console.log("x");` → `"x"`.
- [ ] `a_failed_tool_call_rejects_and_can_be_caught`: handler `Err("no such file")`; script catches and returns `error.message` → `"no such file"`.
- [ ] `a_thrown_error_fails_the_script`: `throw new Error("boom")` → `Failed` containing "boom".
- [ ] `a_syntax_error_runs_nothing`: `return (;` → `Failed`, handler never called.
- [ ] `calls_started_together_are_answered_in_order`: `Promise.all` of three reads → handler saw ids in order, output joins three answers.

- [ ] `cancelling_stops_a_running_script`: `await new Promise(() => {})`-style wait on a tool call whose handler flips the cancel flag → `Err(Interrupted)`.
- [ ] `a_script_has_no_host_objects_and_no_node`: script returns `[typeof process, typeof require, typeof setTimeout]` plus the realm check used in `tests/workflow_host_contract.rs` (`makerOf(tools.read_file) === makerOf(() => {})`, same for a resolved value, a rejection, `console`, `tools`) → all `"undefined"` / `"own"`.

### Task 4: Inner tool calls

**Files:** Create `crates/orca-runtime/src/script/calls.rs`.

**Consumes:** `ScriptToolCall` (Task 3); `prepare_tool_invocation_with_external`, `apply_pre_tool_outcome_with_external`, `HookRunner`, `RuntimeReadonlyToolInvocation`, `RuntimeToolCallRuntime::execute_readonly_batch`.

**Produces:**

```rust
pub(crate) const SCRIPT_TOOLS: [&str; 4] = ["read_file", "glob", "grep", "git_status"];
pub(crate) const SCRIPT_TOOL_OUTPUT_BYTES: usize = 256 * 1024;

pub(crate) trait ScriptToolExecutor { fn execute(&self, request: ToolRequest) -> ToolResult; }

pub(crate) struct ScriptToolCalls<'a> { /* outer id, cwd, mcp_registry, hooks, cancel, executor, max calls, count, lines */ }
impl ScriptToolCalls<'_> {
    /// Answers one call: `Ok(output)` or `Err(why)`. Never panics on script input.
    pub(crate) fn answer(&mut self, call: ScriptToolCall) -> Result<String, String>;
    pub(crate) fn made(&self) -> u32;
    /// One line per call since the last drain, for `tool.output.delta`.
    pub(crate) fn drain_report(&mut self) -> Vec<String>;
}
```

Order inside `answer`: count (over `max_tool_calls` → `Err("script reached its limit of N tool calls")`, and every later call too); name in `SCRIPT_TOOLS` else `Err("<name> is not available to scripts; available: …")`; build `ToolRequest { id: "<outer>:<n>", name, arguments }`; `tool_is_available_readonly_concurrent`; prepare + PreToolUse hook + apply outcome (schema errors and hook blocks become `Err`); execute; `Completed` → `Ok(output or "")`, anything else → `Err(error text)`. Report line: `read_file src/a.rs · ok · 3ms`, the main argument being `path`, `pattern`, or nothing.
