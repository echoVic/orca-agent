# v0.5.20 Follow-ups Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Count DeepSeek's per-use tool fees (search, fetch, OCR) in Orca's cost estimate and `max_cost_usd` budget, and fix the OCR minors the v0.5.20 final review deferred.

**Architecture:**
- Tools report billable units, never dollars. A new `orca_core::tool_types::ToolServiceUsage` rides on `ToolResult` as a field serde skips, the way `file_change_preview` already does.
- The runtime prices the units at flat built-in rates (`pricing/rates.rs`) and adds the cost to the `CostTracker`.
- At the root, `run_tool_turns` records the same delta in the operation's budget journal and emits `usage.updated`. Production subagents run that same kernel (`agent_loop::execute_child_agent_loop` → `run_agent_loop`), so they are covered too.
- The executor-style child loop (`fold_child_agent_tool_result`, which tests and the public `agent_child` API use) adds the fee to its child tracker, which `sync_child_cost_to_lease` already turns into lease cost.
- Hosted TUI/ACP generations take their usage as the session tracker's after−before (`runtime_host.rs` `usage_delta`), so the status bar and `/status` pick the fees up without surface changes.

**Tech Stack:** Rust (serde, sha2, std `Condvar`/`Mutex`), MDX docs.

## Global Constraints

- Billing rules come from DeepSeek's docs as of 2026-11-15:
  - https://api-docs.deepseek.com/quick_start/pricing: search and fetch $0.75 per 1,000; file parsing/OCR $0.225 per 1,000 pages; the peak/off-peak rule applies to token prices only.
  - /guides/search: "A request is billable only when it returns HTTP 200 and produces a result (Search must return a non-empty `results` array, and Fetch must return page content). Failed requests, empty search results, and timeouts are not billed."
  - /guides/ocr: "Billed by the number of pages recognized successfully (`page_count`). A recognition that fails or times out is not billed. Disconnecting does not cancel a recognition … billed if it completes."
- Counting rules (Claude's calls, following those docs):
  - search: count 1 when DeepSeek's raw `results` array is non-empty, even if Orca then drops hits without a URL; count 0 for a failure, an empty result, or the Exa fallback.
  - fetch: count 1 when `deepseek_web::fetch` returns `Ok`; it already treats empty content as a failure.
  - OCR: count `page_count.unwrap_or(pages.len())` pages only for a recognition this read requested and DeepSeek completed. Memory-cache hits, disk-cache hits, and reads that shared another read's recognition count 0. A cancelled upload counts 0: DeepSeek may bill it, but Orca never sees its page count, and the docs say so.
- Prices are flat: no time-of-use multiplier, and `[models.*.pricing]` overrides do not apply, since those are per-token.
- Accounting id per charge: `tool-service:{tool_call_id}:{ConversationItemId::new()}`. Every real call is a separate bill, as `image-analysis:` charges already are.
- A fee that overruns `max_cost_usd` latches the controller (`record_cost_usd_micros` is a receipt, never an admission). The run stops at the next turn or tool admission with `StopReason::CostBudget`.
- Exact strings:
  - waiter failure: `DeepSeek OCR could not read {path}: {message}; a parallel read of this file got that answer, so this read did not try again`
  - the disk-cache key prefix stays byte-identical: `orca-ocr-v1\npurpose:text_recognition\n`, so existing `ORCA_HOME/ocr_cache` entries keep hitting.
- Run cargo as `env -u NODE_OPTIONS cargo …` and put test filters after `--`. Verify orca-runtime lib flakes serially (`--test-threads=1`) before believing them. Windows compiles only in CI, so check the `#[cfg]` attributes around any inserted item.
- No new crates. Tests make no live network calls; they use `crate::test_http` fixtures and the key `sk-test`.

## Review Focus

1. A fee pushes a run over `--max-cost-usd` in the middle of a turn: the call already ran and is not undone, and the next admission stops with `CostBudget`. Pinned by `a_service_fee_over_the_budget_stops_the_next_tool_admission` (Task 5).
2. Three reads of one PDF in parallel while DeepSeek returns an error: one upload, three failures, no 3×180 s chain. Pinned by `a_read_waiting_on_a_failed_recognition_gets_its_failure` (Task 3).
3. The recognizing read is cancelled while others wait: a waiter takes over instead of inheriting "cancelled". Pinned by `a_waiting_read_takes_over_when_the_recognizing_read_is_cancelled` (Task 3).
4. A DeepSeek search returns hits Orca drops for missing URLs: DeepSeek billed it, so the fee counts even though the output says no results. Pinned by `deepseek_search_counts_results_it_drops` (Task 4).
5. Someone later makes `web_search`, `web_fetch` or `read_document` batchable: the read batch has no charging, so fees would vanish. Pinned by `billed_tools_stay_outside_the_read_batch` (Task 4).
