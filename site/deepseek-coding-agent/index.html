Model fit

DeepSeek-native means more than an API endpoint.

Reasoning and routing

Orca treats DeepSeek reasoning settings and model routing as first-class coding workflow controls. Max reasoning effort is the default for coding turns, and the model selector can route fast lookups to a cheaper model while keeping edits on the stronger one.

Prefix-cache friendly

The prompt stays stable across tools, summaries, compaction, and resume so repeated turns avoid waste. Pinned system instructions and tool specs are placed in the cached prefix, and the context meter shows room left before compaction rather than a raw fraction.

Local, inspectable history

JSONL transcripts make DeepSeek Orca sessions searchable, resumable, forkable, and auditable. Every reasoning chunk, tool call, and verifier result is recorded locally, so you can replay a session or extract a trajectory for benchmarking.

1M-context coding

DeepSeek's long context window lets Orca load large modules, full diffs, and multi-file repro instructions in one turn. Compaction kicks in past the 80% threshold and preserves the system prefix and the most recent messages.

Streaming reasoning

Reasoning streams into the TUI as it arrives, so you can watch the agent think through a hard problem instead of waiting for a black-box answer. The reasoning is stored alongside the final reply for later review, and a resumed session shows reasoning before the answer loads.

OpenAI-compatible fallback

While Orca is tuned for DeepSeek, the config can point at any OpenAI-compatible endpoint. Teams with mixed providers keep the same tool, approval, and transcript model across backends, with no rewrite needed.

How DeepSeek-native works

Tuned for how DeepSeek actually codes.

Reasoning effort as a dial

Coding turns default to max reasoning effort so the model plans before it edits. For quick lookups and summarization, Orca can drop to a lower effort or route to a flash model, keeping latency and cost proportional to the task.

Tool semantics that match the model

Orca's tool specs are written for how DeepSeek calls tools: clear capability declarations, typed parameters, and failure messages that guide the next attempt. Edits show their diff, and the model records each call as the kind of tool it is.

Compaction that protects the prefix

When context fills up, compaction works by message unit so a pinned system prompt or a just-edited file is never frozen mid-turn. The cached prefix stays stable, which is where most of the cost savings come from in real sessions.

Cost and latency you can see

Orca uses DeepSeek's current prices and weekday peak rates for cost estimates, with background price refresh and user overrides. The TUI shows token usage, cost, and prefix-cache hit rate per turn, and the context meter shows room before compaction.

Vision for screenshots and diagrams

Paste a screenshot or drag an image into the TUI and Orca can reason about it with DeepSeek's vision model. UI bugs, diagram-to-code tasks, and pasted error images become first-class inputs to the coding loop, with the image stored locally for later review.

Subagents share the provider

Background subagents, workflow children, and hosted agents run through the same DeepSeek provider and budget accounting. A parent turn can delegate work without losing track of cost, context, or the final result, and child transcripts stay out of the root conversation.

When it shines

Workloads where DeepSeek-native pays off.

Long-context codebase understanding

Load an entire module, a large PR diff, or a multi-file repro into one turn. DeepSeek's context window lets Orca reason across the whole surface instead of summarizing away the details.

Reasoning-heavy debugging

Max reasoning effort helps with subtle bugs: race conditions, boundary conditions, and interactions between layers. The streamed reasoning is visible in the TUI and stored in the transcript.

Cost-aware autonomous runs

For a 128-turn autonomous goal, prefix-cache hits dominate the cost. Orca's stable prefix and unit-based compaction keep the cache warm across turns, which is where the real savings come from.

Vision-assisted UI work

Paste a design screenshot or a failing UI capture. Orca reads the image, finds the relevant components, edits the code, and verifies the result — all in one local loop.

Multi-file refactors

Large renames and API changes need the whole call graph in view. With a 1M-context window, Orca can see the impact before editing, then verify the build after each batch.

Resumable long sessions

A DeepSeek session that spans hours survives restarts through JSONL. Resume restores the model state, the plan, and the goal, so a long migration does not have to restart from scratch.

FAQ

Questions about the DeepSeek coding agent.

Do I have to use DeepSeek?

No. Orca is tuned for DeepSeek and gives the best experience there, but the config can point at any OpenAI-compatible endpoint. The tool, approval, and transcript model stays the same across providers.

What does "prefix-cache friendly" mean in practice?

It means the part of the prompt that repeats every turn — system instructions, tool specs, pinned context — is placed in a stable prefix. DeepSeek caches that prefix, so each turn only pays for the new messages instead of reprocessing the whole prompt.

How does Orca handle the 1M-context window?

Orca fills the window naturally and compacts past the 80% threshold. Compaction works by message unit, so pinned content survives, and the context meter shows how much room is left before compaction triggers.

Can I see the model's reasoning?

Yes. Reasoning streams into the TUI as it arrives and is stored in the JSONL transcript alongside the final answer. You can review it after the turn or extract it for benchmarking.

How are costs estimated?

Orca uses DeepSeek's current prices and weekday peak rates, with a background price refresh and user overrides. The TUI shows per-turn token usage, cost, and the prefix-cache hit rate.

Does vision work in the terminal?

Yes. Paste or drag an image into the TUI and Orca can reason about it with DeepSeek's vision model. Screenshots, diagrams, and error captures become inputs to the same coding loop.
