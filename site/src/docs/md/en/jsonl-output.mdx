# JSONL Output

By default, orca exec writes readable text. Set --output-format jsonl when
another program should consume the event stream. Each stdout line is one JSON
event envelope.

~~~bash
orca exec --output-format jsonl "Inspect the repository" > run.jsonl
~~~

The output path belongs to the shell, not to an Orca option. Use redirection,
a pipe, or a process supervisor to decide where the stream goes.

## Envelope

Each event has these stable top-level fields:

| Field | Meaning |
| --- | --- |
| version | Event-schema version. |
| run_id | Identifier for this execution. |
| seq | Monotonic sequence within the run. |
| timestamp_ms | Event publication time in milliseconds since Unix epoch. |
| type | Event kind, such as turn.started or tool.call.completed. |
| payload | Event-kind-specific data. |

Treat type and payload as a versioned protocol. Consumers should retain unknown
event types rather than assuming that a stream contains only the examples they
currently recognize.

~~~bash
orca exec --output-format jsonl "Run the test suite" |
  jq -c 'select(.type == "tool.call.completed")'
~~~

## History behavior

A JSONL run writes its event stream to stdout but does not record local history
by default. Add --save-history when it must be resumable:

~~~bash
orca exec --output-format jsonl --save-history \
  "Fix the parser" > parser-run.jsonl
~~~

Use --no-history for a text or JSONL run that must leave no local conversation
record. It cannot be combined with a resume, fork, or continue operation.

## Automation boundary

JSONL is an observation stream, not proof that an external effect is safe to
repeat. Preserve terminal tool and verification events with the run record; if
a process stops after a tool started but before a terminal event, inspect the
target state before replaying that action.
