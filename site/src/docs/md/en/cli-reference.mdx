# CLI Reference

The public command line contract is intentionally small. Run `orca --help` or
the relevant subcommand's `--help` for the binary that is installed on your
machine. The checked-in contract is also recorded in
`docs/public-cli-manifest.json`.

## Install

```bash
npm install -g @blade-ai/orca
```

The canonical site and installer are [orcaagent.dev](https://orcaagent.dev/).

## Root command

```text
orca [OPTIONS] [PROMPT]...
orca [OPTIONS] COMMAND
```

Running `orca` opens the interactive TUI. A prompt may be supplied as
positional text. The visible root commands are:

| Command | Purpose |
| --- | --- |
| `orca doctor` | Inspect local configuration, credentials, folder trust, and sandbox readiness. |
| `orca storage` | Inspect session disk usage and preview or apply archive retention. |
| `orca exec` | Run a non-interactive task and emit text or JSONL events. |
| `orca workflow` | Run and inspect persisted local workflows. |
| `orca trust` | Show or update folder trust. |
| `orca mcp` | Add, list, show, remove, log in to, or log out of MCP servers in the user config. |

Root options are `--resume [SESSION_ID]`, `--fork <ID>`, `--continue`,
`--model <MODEL>`, `--mode <MODE>`, `--api-key <KEY>`, `--base-url <URL>`, and
`--cwd <PATH>`. Use an approval mode (`suggest`, `auto-edit`, `full-auto`, or
`plan`) for an interactive run. `--mode server` and `--mode acp` instead select
a protocol transport and cannot be combined with a prompt or subcommand.

## `orca doctor`

```text
orca doctor [--cwd PATH] [--format text|json]
```

`doctor` is a local, read-only preflight. It never contacts the provider,
starts MCP, provisions sandbox capabilities, writes configuration, or changes
folder trust. It reports typed `pass`, `warn`, and `fail` checks for:

- configuration syntax and source paths;
- credential presence and source (never the credential value);
- effective model and endpoint configuration;
- the nearest folder-trust decision; and
- the platform sandbox backend.

Warnings keep exit status `0`. A required failed check returns exit status `1`.
Text is intended for people; JSON is stable machine-readable output with
camelCase fields such as `schemaVersion` and `folder-trust` check IDs.

```bash
orca doctor
orca doctor --cwd ./project --format json
```

## `orca storage`

```text
orca storage [--max-bytes BYTES] [--older-than-days DAYS] [--apply]
```

Without `--apply`, this command only previews usage and candidates. See
[Storage and retention](session-commands.md#storage-and-retention) for the
archive policy, image ownership, and backup contract.

## `orca exec`

```text
orca exec [OPTIONS] [PROMPT]...
orca exec [OPTIONS] resume [SESSION_ID] [PROMPT]...
```

The supported execution options are:

| Option | Meaning |
| --- | --- |
| `--output-format TEXT|JSONL` | Human-readable output or one JSON object per event. |
| `--cwd PATH` | Workspace directory. |
| `--mode suggest|auto-edit|full-auto|plan` | Approval policy for tool actions. |
| `--model MODEL` | Model override. |
| `--api-key KEY` | API key override. |
| `--base-url URL` | API endpoint override. |
| `--verifier COMMAND` | Command to run after the task. |
| `--max-turns N` | Maximum model turns for this run. |
| `--max-tool-calls N` | Maximum tool calls for this run. |
| `--max-cost-usd USD` | Maximum estimated cost for this run. |
| `--max-wall-time-secs SECONDS` | Maximum wall-clock time for this run. |
| `--resume ID` | Resume a saved conversation by ID or prefix. |
| `--resume-at MESSAGE_ID` | Restore only through a persisted message boundary. |
| `--fork ID` | Fork a saved conversation. |
| `--continue` | Continue the latest saved conversation. |
| `--no-history` | Do not write this run to local history. |
| `--save-history` | Persist history while using JSONL output. |

Examples:

```bash
orca exec "Fix the failing test" --verifier "cargo test"
orca exec --output-format jsonl --max-turns 20 "Refactor the parser" > run.jsonl
orca exec resume SESSION_ID --resume-at MESSAGE_ID "Continue from the checkpoint"
```

Use shell redirection for an output file. The CLI does not have a separate
output-path option.

## `orca workflow`

The workflow command exposes `run`, `list`, `show`, `source`, `stop`, `pause`,
`resume`, `clone`, `restart-failed`, and `restart-phase`. Each operation is
local and has its own arguments; inspect `orca workflow <COMMAND> --help`
before scripting it.

## `orca trust`

```text
orca trust [show|add|remove] [--cwd PATH]
```

`show` is read-only. `add` and `remove` update the user-owned folder-trust
store, so use them only after reviewing the directory and its sandbox policy.

## `orca mcp`

```text
orca mcp add NAME [OPTIONS] (--url URL | -- COMMAND [ARGS]...)
orca mcp list [--json]
orca mcp get NAME [--json]
orca mcp remove NAME
orca mcp login NAME
orca mcp logout NAME
```

`orca mcp` only writes the user-owned `$ORCA_HOME/config.toml` (and, for
`login`/`logout`, the credential store next to it); a project's
`.orca/config.toml` is never touched. A change takes effect the next time a
session starts — it does not affect a session that is already running.

| Subcommand | Purpose |
| --- | --- |
| `orca mcp add` | Add a stdio or remote (HTTP/SSE) MCP server. |
| `orca mcp list` | List configured servers, one per line, or as JSON with `--json`. |
| `orca mcp get` | Show one server's configuration. |
| `orca mcp remove` | Remove a server from the user configuration, and delete its saved login if it has one. |
| `orca mcp login` | Log in to a remote server with OAuth. |
| `orca mcp logout` | Delete a remote server's saved login. |

`add` takes either a trailing stdio command or `--url`, never both:

| Option | Meaning |
| --- | --- |
| `-e, --env KEY=VALUE` | Environment variable for a stdio server (repeatable). Conflicts with `--url`. |
| `--url URL` | Remote server endpoint. |
| `--transport http\|sse` | Remote transport; defaults to `http`. Only meaningful with `--url`. |
| `--header 'Name: value'` | HTTP header for a remote server (repeatable). Requires `--url`. |
| `--bearer-token-env-var VAR` | Environment variable holding a bearer token, read at connect time. Requires `--url`. |
| `--client-id ID` | OAuth client id. Requires `--url`. |
| `--callback-port PORT` | Local OAuth redirect callback port. Requires `--url`. |
| `-- COMMAND [ARGS]...` | Stdio server command and its arguments. |

`NAME` takes letters, digits, `-` and `_`, with at least one letter or digit
and no `__`. Orca names a server's tools from its name in lowercase, with every
run of `-` and `_` turned into one `_` and none left at either end, so `add`
refuses a name that reads the same as a configured one that way (`GitHub`
beside `github`, `my-server` beside `my_server`) and names the server it
clashes with.

`list` and `get` print a stdio server's command and arguments and a remote
server's url as configured, so keep secrets out of those. They never print the
values of `env` or `headers`, only their names, and the auth column or `auth:`
line reports only a status word (`oauth: logged in`, `oauth: not logged in`,
`bearer: $VAR`, `static header`, or `-` for a stdio server), never a token.
`get` also shows `enabled_tools` and `disabled_tools`: `-` for one that is not
set, and `none` for an empty list.

`login` opens the server's authorization page in your browser and prints the
url in case it does not open; it refuses a stdio server or one with a
configured `Authorization` header or `bearer_token_env_var`, since those do
not use OAuth. `logout` deletes the saved login; it fails if the server has
none.

Examples:

```bash
orca mcp add docs -- npx -y docs-mcp-server
orca mcp add search --url https://mcp.example.test/mcp --bearer-token-env-var SEARCH_TOKEN
orca mcp add tracker --url https://tracker.example.test/mcp
orca mcp list --json
orca mcp get docs
orca mcp login tracker
orca mcp logout tracker
orca mcp remove docs
```

## Configuration and environment

The user file is `$ORCA_HOME/config.toml` when `ORCA_HOME` is set, otherwise
`~/.orca/config.toml`. A project may provide `.orca/config.toml`, but it is
loaded only after the folder is trusted. Effective precedence is CLI options,
environment variables, trusted project configuration, user configuration, and
built-in defaults.

Supported environment overrides include `ORCA_API_KEY`/
`DEEPSEEK_API_KEY`, `ORCA_MODEL`/`DEEPSEEK_MODEL`,
`ORCA_BASE_URL`/`DEEPSEEK_BASE_URL`, `ORCA_MODE`, and
`ORCA_REASONING_EFFORT`/`DEEPSEEK_REASONING_EFFORT`. Keep credentials out of
source control. `orca doctor --format json` reports only whether a credential
is present and where it came from.
