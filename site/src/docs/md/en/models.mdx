# Models

Select a provider model with --model for an interactive or headless run:

~~~bash
orca --model deepseek-v4-pro "Explain the current architecture"
orca exec --model deepseek-flash "Fix the import ordering" \
  --verifier "cargo fmt --check"
~~~

The supported model names and endpoint behavior come from the selected
provider. Do not treat an example model name as a promise that every endpoint
supports it. Run orca doctor to inspect the effective local model and endpoint
configuration before launching a task.

For DeepSeek, `deepseek-flash` is the canonical Flash preset and currently
targets DeepSeek-V4.1-Flash. It supports image understanding and uses the Flash
price tier. The retired `deepseek-v4-flash` and
`deepseek-v4-flash-vision-exp` names remain valid compatibility inputs, but
Orca normalizes both to `deepseek-flash` before routing, persistence, cache
identity, and cost estimation. They are not shown as separate models in the
interactive selector.

## Persistent selection

Set the model in user configuration or through the environment:

~~~toml
model = "deepseek-v4-pro"
reasoning_effort = "high"
~~~

Declare capabilities for a specific provider model under its quoted model ID.
Explicit declarations override Orca's built-in model metadata:

~~~toml
model = "provider/multimodal-model"

[models."provider/multimodal-model"]
supports_images = true
~~~

~~~bash
export ORCA_MODEL="deepseek-v4-pro"
export ORCA_REASONING_EFFORT="high"
~~~

The supported reasoning-effort values are low, high, and max. Set it through
configuration or the interactive model settings; it is not a per-invocation
public CLI control.

## Choose by evidence

Start from the model configured for the workspace. Change it only when the task
needs a different capability, latency, or cost profile, then record the
verifier result. Execution budgets are separate from model selection:

~~~bash
orca exec \
  --model deepseek-flash \
  --max-turns 15 \
  --max-cost-usd 2 \
  --verifier "cargo test -p parser" \
  "Refactor the parser"
~~~

For model, credential, endpoint, and trust precedence, see
[Configuration](configuration.md).
