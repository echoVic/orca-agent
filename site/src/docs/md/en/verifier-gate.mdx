# Verification

Pass a shell command with --verifier when completion needs an independent
check. Orca runs it after the task and records the result with the run.

~~~bash
orca exec "Fix the login regression" \
  --verifier "npm test -- --testPathPattern=login"

orca exec "Refactor the parser" \
  --verifier "cargo test -p parser && cargo clippy -p parser -- -D warnings"
~~~

## Pick evidence that can fail

A useful verifier is:

- independent of the model's textual claim;
- narrow enough to identify the changed behavior;
- deterministic enough to rerun; and
- fast enough to use routinely.

~~~bash
# Good: checks the requested behavior.
orca exec "Add a parser error case" --verifier "cargo test -p parser parse_error"

# Weak: succeeds without checking the change.
orca exec "Add a parser error case" --verifier "echo done"
~~~

The CLI currently exposes one verifier command per execution. Put multi-step
checks in a shell script when quoting becomes hard to review:

~~~bash
orca exec "Refactor authentication" --verifier "./scripts/verify-auth.sh"
~~~

Omit --verifier for work that has no meaningful automated check. There is no
verifier-default configuration command and no verifier-specific timeout option
in the public CLI.

## Resume after a failed check

A failed verification result is evidence for the next turn, not proof that all
writes can be replayed. Resume the recorded run with the failure context:

~~~bash
orca exec resume SESSION_ID \
  --verifier "npm test -- --testPathPattern=login" \
  "Read the verifier failure and fix only the remaining regression"
~~~

Keep the verifier output with the CI artifact or JSONL stream so reviewers can
distinguish a verified result from an unverified one.
