# Configuration

Orca resolves configuration directly from TOML files and environment variables.
Use an editor to change the TOML file, then run `orca doctor` to validate the
local configuration and see the resolved model/endpoint without starting a
session.

## Locations and precedence

The user-owned configuration directory is selected once:

1. `$ORCA_HOME` when the environment variable is set.
2. `~/.orca` otherwise.

The user configuration is `config.toml` in that directory and the local auth
file is `auth.json`. A workspace can include `.orca/config.toml`, but Orca
loads it only when the workspace is trusted. Project configuration may tune
presentation and model selection; it cannot grant credentials, change approval
mode, add MCP servers, loosen permissions, or configure process-launching
surfaces.

For an individual setting, precedence is:

1. CLI option
2. Environment variable
3. Trusted project `.orca/config.toml`
4. User `config.toml`
5. Built-in default

## Minimal user configuration

```toml
# $ORCA_HOME/config.toml, or ~/.orca/config.toml
model = "deepseek-v4-pro"
base_url = "https://api.deepseek.com"
mode = "suggest"
reasoning_effort = "high"

[budget]
max_turns = 20
max_tool_calls = 80
max_cost_usd_micros = 2000000
max_wall_time_ms = 1800000
```

`mode` accepts `suggest`, `auto-edit`, `full-auto`, or `plan`.
`reasoning_effort` accepts `low`, `high`, or `max`. CLI execution limits are
operation-scoped: set `--max-turns`, `--max-tool-calls`, `--max-cost-usd`, or
`--max-wall-time-secs` for a specific `orca exec` run when you do not want a
stored budget default. The file uses integer microdollars and milliseconds;
the CLI accepts USD and seconds.

## Subagents

Subagent execution is scoped to one root task tree. Direct, nested, Workflow,
hosted, continued, and recovered children share the same limits:

```toml
[subagents]
delegation = "adaptive" # off | explicit | adaptive
max_depth = 2
max_running = 32
max_queued = 256
max_live_tasks = 512
max_investigation_turns = 6
max_investigation_tool_calls = 8
```

`max_running` limits active execution leases. Accepted overflow is queued
without starting a worker; `max_queued` bounds that queue and `max_live_tasks`
bounds every non-terminal descendant, including parents waiting for children.
Waiting parents release their execution lease and must re-enter the queue before
running again.

The retired `max_parallel` key is ignored and does not act as a second capacity
authority. Use `delegation = "off"` to disable new delegation.

## Credentials

Prefer an environment variable:

```bash
export ORCA_API_KEY="sk-..."
# DEEPSEEK_API_KEY is also supported.
```

The local auth file can contain a JSON object with a `DEEPSEEK_API_KEY` member:

```json
{
  "DEEPSEEK_API_KEY": "sk-..."
}
```

Do not commit credentials. `orca doctor --format json` reports credential
presence and source only; it never emits the credential value.

## Environment overrides

| Purpose | Variables |
| --- | --- |
| Credential | `ORCA_API_KEY`, `DEEPSEEK_API_KEY` |
| Model | `ORCA_MODEL`, `DEEPSEEK_MODEL` |
| Endpoint | `ORCA_BASE_URL`, `DEEPSEEK_BASE_URL` |
| Approval mode | `ORCA_MODE` |
| Reasoning effort | `ORCA_REASONING_EFFORT`, `DEEPSEEK_REASONING_EFFORT` |

An invalid `ORCA_MODE` or reasoning-effort value prevents effective
configuration from resolving. Run `orca doctor` after changing environment or
TOML settings to catch it before a task run.

## Folder trust

New workspaces are treated as untrusted. Trust controls whether a workspace
may load its project configuration and use full write/network sandbox modes.
Inspect the current decision with:

```bash
orca trust show --cwd ./project
```

After reviewing the workspace, record an explicit decision:

```bash
orca trust add --cwd ./project
orca trust remove --cwd ./project
```

The closest explicit ancestor decision applies to a nested directory. A closer
explicit untrusted decision overrides a broader trusted ancestor.
