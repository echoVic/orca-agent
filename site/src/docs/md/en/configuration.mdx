# Configuration

Orca resolves configuration directly from TOML files and environment variables.
Use an editor to change the TOML file, then run `orca doctor` to validate the
local configuration and see the resolved model/endpoint without starting a
session.

## Locations and precedence

The user-owned configuration directory is selected once:

1. `$ORCA_HOME` when the environment variable is set.
2. `~/.orca` otherwise.

The user configuration is `config.toml` in that directory and the local auth
file is `auth.json`. A workspace can include `.orca/config.toml`, but Orca
loads it only when the workspace is trusted. Project configuration may tune
presentation and model selection; it cannot grant credentials, change approval
mode, add MCP servers, loosen permissions, or configure process-launching
surfaces.

Both `config.toml` files are UTF-8 TOML. One Orca cannot read, such as one
saved as UTF-16 (which Windows PowerShell 5.1's `>` writes), or cannot parse,
is left out with a warning when Orca starts: none of its settings apply.

For an individual setting, precedence is:

1. CLI option
2. Environment variable
3. Trusted project `.orca/config.toml`
4. User `config.toml`
5. Built-in default

The built-in approval mode is `full-auto` (yolo) for a new TUI session and
`auto-edit` for headless `exec` and shared daemons. A resumed conversation keeps
its saved mode unless the launch explicitly selects `--mode` or `--yolo`.

## Minimal user configuration

```toml
# $ORCA_HOME/config.toml, or ~/.orca/config.toml
model = "deepseek-v4-pro"
base_url = "https://api.deepseek.com"
mode = "suggest"
reasoning_effort = "high"

[budget]
max_turns = 20
max_tool_calls = 80
max_cost_usd_micros = 2000000
max_wall_time_ms = 1800000
```

`mode` accepts `suggest`, `auto-edit`, `full-auto`, or `plan`.
`reasoning_effort` accepts `low`, `high`, or `max`. CLI execution limits are
operation-scoped: set `--max-turns`, `--max-tool-calls`, `--max-cost-usd`, or
`--max-wall-time-secs` for a specific `orca exec` run when you do not want a
stored budget default. The file uses integer microdollars and milliseconds;
the CLI accepts USD and seconds.

## Cost estimates

Cost estimates follow DeepSeek's published peak and off-peak prices. Each
process checks once at session startup and refreshes prices from models.dev in
the background if the cache is missing or at least 24 hours old. Refresh is
enabled by default. Both settings belong in the user configuration; project
`.orca/config.toml` cannot set them:

```toml
[pricing]
refresh = false            # do not contact models.dev for prices

[models."my-model".pricing]
input_cache_miss = 0.5     # US dollars per million tokens
input_cache_hit = 0.05
output = 1.5
```

A `[models."<name>".pricing]` table needs all three prices and applies at every
hour. See [Models](models.md#cost-estimates) for how estimates are made.

## Computer use (macOS)

The interactive TUI's main session can operate other apps on macOS 14 or
later. Its only setting belongs in the user configuration; project
`.orca/config.toml` cannot set it:

```toml
[computer_use]
foreground_fallback = false
```

`foreground_fallback` defaults to `true`: actions that need the foreground
briefly switch to the target app and then restore the previous app and pointer.
Set it to `false` to refuse those actions, including all Command shortcuts.
See [Computer Use](computer-use.md) for system permissions, app and window
approval, and disabling the tool with a deny rule.

## File checkpoints (`/rewind`)

When a session records history, Orca captures one file checkpoint per turn so
`/rewind` can restore files and the conversation. The `[rewind]` table belongs
in the user configuration; a trusted workspace may also set it in
`.orca/config.toml`:

```toml
[rewind]
enabled = true            # capture a checkpoint per turn; false also empties /rewind
observe_untracked = true  # report changes made outside tracked tool writes
max_checkpoints = 100     # checkpoints kept per session (minimum 1)
```

`ORCA_DISABLE_FILE_HISTORY` (non-empty, not `0`) disables capture and
`ORCA_REWIND_DISABLE_OBSERVE` (any value) disables the turn-boundary workspace
observation; the environment always overrides the file. Evicted checkpoints
are stamped with a retention watermark, after which only their conversation
rewind remains available, and their file blobs are garbage-collected
automatically. A file restore is refused when the workspace no longer matches
the workspace the checkpoint was recorded in.

## Permission-rule targets

`[[permissions.rules]]` belongs in the user configuration. A rule names a
`tool`, an optional target `pattern`, and a `decision` of `allow`, `prompt`, or
`deny`. The strictest matching rule wins. Targets include:

| Tool | Target |
| --- | --- |
| `bash` | Command line. |
| File tools | File path. |
| `computer` | App bundle id, `bundle#window:<id>` for your existing window, or a target ending in `#secure` for password entry. |
| MCP tools | Canonical tool name, such as `mcp__github__create_issue`; normally omit `pattern`. |
| `read_mcp_resource` | `server:uri`. |
| `read_skill` | The `id` argument, usually the skill directory name. |
| `Workflow` | Script path, otherwise workflow name or draft id. Inline code does not match any pattern rule, including wildcards. |

Outside `full-auto`, app, wildcard and whole-tool allow rules do not cover
your existing windows. Only an exact `bundle#window:<id>` allow covers that
window, never its password entry. Prefer the window panel's session grant, since window ids do not last
across sessions. App deny and prompt rules still apply to windows, and window
deny and prompt rules apply to password entry in that window outside
`full-auto`. In `full-auto`, password entry uses `bundle#secure`, which a
whole-tool `computer` allow rule can preapprove for apps that do not run
commands. Window deny and prompt rules do not apply there; app deny and prompt
rules still apply. See
[Approval modes](approval-modes.md#permission-rules) for matching and the
command-running-app and secure-input exceptions.

## Subagents

Subagent execution is scoped to one root task tree. Direct, nested, Workflow,
hosted, continued, and recovered children share the same limits:

```toml
[subagents]
delegation = "adaptive" # off | explicit | adaptive
max_depth = 2
max_running = 32
max_queued = 256
max_live_tasks = 512
max_investigation_turns = 6
max_investigation_tool_calls = 8
```

`max_running` limits active execution leases. Accepted overflow is queued
without starting a worker; `max_queued` bounds that queue and `max_live_tasks`
bounds every non-terminal descendant, including parents waiting for children.
Waiting parents release their execution lease and must re-enter the queue before
running again.

The retired `max_parallel` key is ignored and does not act as a second capacity
authority. Use `delegation = "off"` to disable new delegation.

The `subagent` tool defaults to `context: "fresh"`, which starts the child
with a standalone brief. Use `context: "fork"` when the task needs completed
turns from the parent. Orca reuses the parent's DeepSeek system prompt, ordered
tools, model, and reasoning effort, then adds the child's task and role as a
user message. The active parent turn is excluded and the child reports its own
work. Orca refuses calls outside the child's role at execution. When the parent
has no completed turn or the recorded prefix is unavailable, Orca starts a
fresh child with a note. Orca saves a private, redacted copy of the fork
history for queued launches and resumes. To continue an existing child, use
`resume_from` and omit `context`.

## Credentials

Prefer an environment variable:

```bash
export ORCA_API_KEY="sk-..."
# DEEPSEEK_API_KEY is also supported.
```

The local auth file can contain a JSON object with a `DEEPSEEK_API_KEY` member:

```json
{
  "DEEPSEEK_API_KEY": "sk-..."
}
```

Do not commit credentials. `orca doctor --format json` reports credential
presence and source only; it never emits the credential value.

The shells and commands the agent runs never inherit `ORCA_API_KEY`,
`DEEPSEEK_API_KEY` or `BRAVE_SEARCH_API_KEY`, so a command that prints its
environment cannot reveal them. If your own project's tests read one of these
variables, give them the value another way, such as a project `.env` file or a
differently named variable.

## Environment overrides

| Purpose | Variables |
| --- | --- |
| Credential | `ORCA_API_KEY`, `DEEPSEEK_API_KEY` |
| Model | `ORCA_MODEL`, `DEEPSEEK_MODEL` |
| Endpoint | `ORCA_BASE_URL`, `DEEPSEEK_BASE_URL` |
| Approval mode | `ORCA_MODE` |
| Reasoning effort | `ORCA_REASONING_EFFORT`, `DEEPSEEK_REASONING_EFFORT` |

An invalid `ORCA_MODE` or reasoning-effort value prevents effective
configuration from resolving. Run `orca doctor` after changing environment or
TOML settings to catch it before a task run.

## Web search and fetch

`web_search` uses the first of these that is available:

1. Brave, when the `BRAVE_SEARCH_API_KEY` environment variable is set.
2. DeepSeek's Search API, when Orca runs against the official DeepSeek endpoint (see below).
3. Exa, which needs no key. Exa also answers when a DeepSeek search fails, and the result says so.

`web_fetch` always requests the page from your machine first. On the official DeepSeek endpoint, a failed request is tried again through DeepSeek's Fetch API, and the result begins with a line saying so. A page whose body has no readable text, such as an app shell that only renders with JavaScript, also counts as a failure. The second try runs on DeepSeek's servers, which follow redirects by their own rules. There is no second try when:

- Orca's own rules refused the URL or a redirect, for example a redirect to another site;
- the page answered 404 or 410;
- the address is private: a LAN, loopback, link-local or otherwise reserved IP address, or a host name ending in `.local`, `.localhost`, `.localdomain`, `.internal`, `.intranet`, `.private`, `.corp`, `.home`, `.lan` or `.home.arpa`.

Orca calls DeepSeek's web and OCR APIs only when the provider is DeepSeek, an API key is set, and `base_url` is unset or points at `https://api.deepseek.com` on the default port, with any path. The key goes to that address and nowhere else. With any other `base_url`, such as a third-party gateway, `web_search` and `web_fetch` work as if the DeepSeek APIs did not exist, and `read_document` explains what it needs.

DeepSeek bills these calls separately from tokens: 0.75 US dollars per 1,000 successful searches, and the same per 1,000 successful fetches (November 2026 prices). Orca adds them to its cost estimate and to the `--max-cost-usd` budget: a search counts when DeepSeek returns results, a fetch when it returns the page, and a failed call counts nothing. To stop using them, turn them off in the user configuration; project `.orca/config.toml` cannot change this setting:

```toml
[tools]
deepseek_web = false   # Brave or Exa for search, local requests only for fetch, no OCR
```

## Reading files in the workspace

`read_file`, `read_document`, `grep`, `glob`, and `list_files` resolve paths inside the workspace. An empty path selects the workspace root. A missing intermediate directory or a file used as a directory is an error. Links to locations inside the workspace work. The tools refuse paths that resolve outside and skip listing entries that point outside. If a directory is replaced with a link while a file is opening, the tool refuses the read.

`grep` skips symlinked ignore files. It uses the workspace's `.gitignore` and `.ignore` rules and also honors two Git ignore sources outside the workspace. These are the user's global excludes file (`core.excludesFile`, defaulting to `$XDG_CONFIG_HOME/git/ignore` or `~/.config/git/ignore`) and the repository's `info/exclude`, including the common Git directory of a linked worktree.

`grep` runs ripgrep when macOS Seatbelt or Linux bubblewrap or Landlock can enforce restricted reads. On Windows, on hosts without that enforcement, or when ripgrep is missing, Orca searches in process.

## Reading documents and images

Under the same conditions, the `read_document` tool reads PDF, Word (`.doc`, `.docx`), PowerPoint (`.ppt`, `.pptx`) and image files (`.png`, `.jpg`, `.jpeg`, `.webp`, `.gif`, `.bmp`, `.tif`, `.tiff`). It uploads the file to DeepSeek's OCR API and returns the recognized text with a `--- Page N ---` line before each page, numbered as DeepSeek numbers it; the first line says so when some pages came back without text. DeepSeek says the file is not stored in its Files API and is not passed to a chat model. `offset` and `limit` count the lines of that text, as `read_file` counts a file's lines. `read_file` still reads text, and points the model at `read_document` when a document is not text.

The upload makes `read_document` a network call, like `web_search` and `web_fetch`: plan mode refuses it, and suggest mode asks before it runs. Without the official endpoint, an API key and `deepseek_web`, it says why it cannot read the file.

- A file over 100 MiB is refused before the upload, and DeepSeek reads at most 1,000 pages of a document. A recognition can take up to three minutes.
- Orca keeps recognized text in memory for the 8 documents it read most recently, and on disk in `ORCA_HOME/ocr_cache` (up to 64 MiB, least recently used first), keyed by the file's content. Reading a long document in `offset`/`limit` chunks, reading a copy of it, or reading it again from a subagent or a later session pays once; a file that changed is recognized again. The cache holds the whole recognized text of each document, readable by your user account only, and deleting a session does not remove it; delete the directory to clear it.
- DeepSeek bills 0.225 US dollars per 1,000 pages it recognized (November 2026 prices), and Orca adds that to its cost estimate and budget too. A read served from the cache, or one that waited for another read of the same file, costs nothing. Cancelling a read does not stop a recognition DeepSeek has started, and DeepSeek still bills it; Orca never learns how many pages that recognition had, so the estimate leaves it out.

## Multi-file patches

Set `apply_patch = true` under `[tools]` to enable the
[multi-file patch tool](#agent-loop). It is off by default.

## Scripts that call tools (experimental)

`run_script` lets the model write a short JavaScript program that calls read-only tools itself and returns only what it computes. A question that would take a search, several file reads and some filtering, each a separate model round with its full output in the context, becomes one round and one short result. It is off by default:

```toml
[tools.script]
enabled = true
timeout_secs = 60      # how long one script may run
max_tool_calls = 100   # how many tool calls one script may make
memory_limit_mb = 64   # how much memory one script may hold; never less than 8
```

A script can call `read_file`, `glob`, `grep` and `git_status`, and nothing else. It cannot write, run commands or reach the network, so it needs no approval and works in plan mode, the same as calling those four tools directly. `PreToolUse` hooks run for each call a script makes.

- The script runs inside Orca, in a JavaScript engine that has no file, network or process access of its own; every read goes through Orca's own tools. Nothing needs to be installed.
- Calls a script starts together, as with `Promise.all`, run at the same time, up to `max_read_parallel` at once.
- When a script's time is up, the calls it has running are stopped and the calls it has not started are not started. A `PreToolUse` hook already running for one of its calls finishes first.
- Nothing is kept between scripts.
- In the terminal UI, a `run_script` row opens with a click or ctrl+o to show the script the model wrote, each call it made (its arguments, how it ended, the first lines of what came back, and which calls ran together) and what went back to the model. The model sees only the script's result, cut at the usual tool output limit. Each batch of calls appears on the row when it ends, while the script is still running. They are saved with the session, up to 256 KiB for one script, so a resumed session shows them too. A script whose calls were not saved shows `Calls were not recorded for this run` in their place: one run by a version that did not save them, or one whose result Orca wrote itself after an interruption, when no batch had ended by then.
- A script stuck inside a single built-in operation that never finishes (reversing an object that claims to hold 2^53 items, say) is stopped on time like any other, but that operation keeps a CPU core busy, and the script's memory, until it finishes or Orca exits. While two such scripts are still running in an Orca process, `run_script` refuses to start another there and says so.
- `/scripts` prints whether the tool is on, its limits, and the description and parameters the model is sent for it.
- A script counts as one tool call in a budget, however many calls it makes itself.

The setting is read from the user configuration; a project's `.orca/config.toml` cannot turn it on.

## Network and certificates

Orca checks HTTPS certificates against the operating system's trust store: the keychain on macOS, the system certificate store on Windows, and the system CA bundle on Linux.

- If your company's proxy or gateway uses its own CA, install that CA in the system trust store. Orca needs no setting of its own. On Linux, if you lack root access, the `SSL_CERT_FILE` and `SSL_CERT_DIR` environment variables point Orca at a CA bundle or a directory of certificates instead of the system locations, so what they point at must hold every root you need, not only your company's CA.
- On a minimal Linux system, such as a slim container image, install `ca-certificates` first. Otherwise Orca cannot create its HTTP client at all, so every request fails, plain HTTP included: a local `http://` MCP server, or a `base_url` that starts with `http://`.
- The `HTTPS_PROXY`, `HTTP_PROXY` and `NO_PROXY` environment variables work as before.

## Folder trust

New workspaces are treated as untrusted. Trust controls whether a workspace
may load its project configuration and use full write/network sandbox modes.
Inspect the current decision with:

```bash
orca trust show --cwd ./project
```

After reviewing the workspace, record an explicit decision:

```bash
orca trust add --cwd ./project
orca trust remove --cwd ./project
```

The closest explicit ancestor decision applies to a nested directory. A closer
explicit untrusted decision overrides a broader trusted ancestor.

## Project instructions

Orca loads the user-wide `AGENTS.md` from `$ORCA_HOME`. For a trusted project,
it also loads the root `AGENTS.md` and `.orca/rules/*.md` at session startup.

Put instructions for a specific area in a subdirectory's `AGENTS.md`. After a
successful `read_file`, `write_file`, `edit`, or change made by `apply_patch`,
Orca checks for `AGENTS.md` files between the trusted workspace root and the
affected file. It adds each new version to the conversation before the next
model request and checks that the source still applies on resume. If the
model writes an `AGENTS.md`, Orca adds it on the next touch in its scope.

User-wide instructions, project-root instructions, and each chain of nested
instructions each have a 65,536-byte budget. If a chain exceeds its budget,
Orca drops the broadest files first and cuts the most specific file if needed.
The budget notice names the files it dropped or cut.
