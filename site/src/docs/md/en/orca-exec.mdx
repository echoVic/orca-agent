# orca exec

orca exec runs one non-interactive task. It is the public entry point for shell
scripts and CI. The interactive TUI remains the right place to inspect a
long-running conversation while it is running.

## Syntax

~~~text
orca exec [OPTIONS] [PROMPT]...
orca exec [OPTIONS] resume [SESSION_ID] [PROMPT]...
~~~

The prompt is positional. Pass - to read it from standard input.

~~~bash
orca exec "Fix the failing parser test" --verifier "cargo test -p parser"
printf '%s\n' "Summarize the changed files" | orca exec -
~~~

## Execution options

| Option | Purpose |
| --- | --- |
| --output-format <text|jsonl> | Select human-readable text or one JSON object per event. The default is text. |
| --cwd <PATH> | Use a specific workspace. |
| --mode <suggest|auto-edit|full-auto|plan> | Select the tool-approval policy. |
| --model <MODEL>, --api-key <KEY>, --base-url <URL> | Override the effective provider configuration for this run. |
| --verifier <COMMAND> | Run a verification command after the task. |
| --max-turns <N>, --max-tool-calls <N> | Limit model turns or tool calls. |
| --max-cost-usd <USD>, --max-wall-time-secs <SECONDS> | Limit estimated cost or wall-clock time. |
| --no-history | Do not record this run locally. |
| --save-history | Record a JSONL run locally as well as writing its stream to stdout. |

All resource limits are unlimited until explicitly supplied. A verifier is
optional: omit --verifier when the task has no meaningful automated check.

## CI example

~~~bash
set -o pipefail

orca exec \
  --cwd "$GITHUB_WORKSPACE" \
  --mode auto-edit \
  --max-turns 20 \
  --max-cost-usd 3 \
  --verifier "npm test" \
  "Fix the failing tests" \
  > orca-events.txt
~~~

For a structured stream, select JSONL and redirect stdout:

~~~bash
orca exec \
  --output-format jsonl \
  --save-history \
  --verifier "cargo test" \
  "Fix the regression" \
  > orca-events.jsonl
~~~

Use the process exit status and the verifier output as the automation gate.
Orca does not publish a stable numeric taxonomy beyond that process result, so
scripts should not infer semantics from undocumented exit-code labels.
