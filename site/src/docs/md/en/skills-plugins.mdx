# Skills

A skill is a directory containing a SKILL.md instruction file. Orca discovers
skills from:

1. `.orca/skills` in a trusted project.
2. `.agents/skills` in a trusted project.
3. `$ORCA_HOME/skills`, or `~/.orca/skills` when `ORCA_HOME` is unset.
4. `~/.agents/skills`.

For duplicate IDs, the first matching location wins. Orca uses the nearest
ancestor containing `.git` as the project root, or the workspace root outside
Git. Trust that directory to enable its project skills.

Orca gives the model a catalog of skill IDs and descriptions so it can call
`read_skill` when a task matches. The catalog becomes part of the conversation
and updates when it changes. It is limited to 4,096 tokens. `list_skills`
shows the full list.

## Minimal skill

~~~markdown
---
name: Rust review
description: Review Rust changes for correctness and recovery risks
when_to_use: Use for changes to runtime ownership or persistence
paths:
  - "crates/**/*.rs"
---

Read the owning runtime path before commenting.
Prioritize concrete failure modes and missing tests.
~~~

The directory name is the skill ID and may contain ASCII letters, digits,
hyphens, or underscores. The supported metadata fields are name, description,
when_to_use, and paths.

## Invoke a skill

Mention a discovered skill by ID in the prompt:

~~~text
$rust-review Review the current branch.
$rust-review:permissions Review the permission changes.
~~~

The optional text after the colon is substituted for `{{arg}}` in the skill
body. Orca adds the mentioned body to the conversation once per version and
keeps it available for follow-up prompts until context compaction. When a
body exceeds 4,096 tokens, Orca points to `read_skill` for the rest. The TUI
also shows discovered skills in mention search.

There is no public command for loading or unloading a skill. Add, edit, or
remove its SKILL.md file, then start the task that mentions it.
