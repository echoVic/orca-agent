# Resume a Headless Run

Use orca exec resume when a recorded headless run needs another turn. The
selector is a session ID, an unambiguous prefix, or latest.

~~~bash
orca exec resume SESSION_ID "Continue from the last checkpoint"
orca exec resume latest --max-turns 10 --max-cost-usd 2 "Run the focused tests"
~~~

The extra message is positional, not a named option. All execution options are
available on the resume subcommand, including --verifier, --output-format, and
the resource limits.

## Other continuity controls

The same choices are available as options on a new orca exec invocation:

| Intent | Public form |
| --- | --- |
| Resume a known conversation | orca exec --resume SESSION_ID "Continue" |
| Resume through a persisted message boundary | orca exec --resume SESSION_ID --resume-at MESSAGE_ID "Continue" |
| Continue the latest conversation | orca exec --continue "Continue" |
| Fork a recorded conversation | orca exec --fork SESSION_ID "Try a different approach" |

--resume, --fork, and --continue are mutually exclusive. --resume-at requires
a resume or continue choice and cannot be used while forking. A continuity
operation records history, so it cannot be combined with --no-history.

## Choose the right boundary

Resuming continues the saved conversation. Forking starts a new recorded branch
from the selected conversation, which is useful when the next approach should
not alter the original history. Both commands restore only durable state; a
tool call interrupted before its terminal record should be treated as
potentially applied and inspected before repeating it.

The public CLI intentionally does not provide bulk listing, export, or deletion
commands for stored conversations. Open the interactive TUI when you need to
browse local history, then copy the selected ID into a headless command.
