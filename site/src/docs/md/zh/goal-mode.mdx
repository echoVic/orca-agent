# 目标导向任务

Orca 的公开 CLI 不要求单独的目标文件格式。将目标、边界和验收条件写进任务请求，再用资源限制和验证器让这些边界可执行。

~~~bash
orca exec \
  --mode suggest \
  --max-turns 20 \
  --max-tool-calls 80 \
  --max-cost-usd 3 \
  --verifier "npm test -- --runInBand" \
  "修复 token 刷新。只改 src/auth 及其测试；若依赖受阻请说明。"
~~~

## 一份有用的任务说明

重要任务至少应说明四件事：

1. **结果**：完成后必须成立的事实。
2. **范围**：允许和禁止触及的文件、系统与操作。
3. **预算**：需要时限制回合、工具调用、费用和运行时间。
4. **证据**：验证命令或其他可观察的完成检查。

审批模式是第五个独立约束。plan 始终只读；suggest、auto-edit 和 full-auto 依次扩大执行策略。选择具备写入或网络能力的模式前，先审查工作区及其信任决定。

## 可重复任务

长提示词应放在仓库中的脚本或 CI 任务里，不要依赖自定义命令空间。这样目标可以和验证器一起审查，也便于迁移：

~~~bash
orca exec --output-format jsonl --save-history \
  --verifier "./scripts/verify-auth.sh" \
  "$(cat .orca/tasks/fix-token-refresh.txt)" > run.jsonl
~~~

已记录运行未完成时，使用新的位置说明恢复。不要假设中断的工具调用已自动回滚。
