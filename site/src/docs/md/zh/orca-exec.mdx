# orca exec

orca exec 用于执行一个非交互任务，是脚本和 CI 的公开入口。需要在任务运行时检查完整对话时，应使用交互式 TUI。

## 语法

~~~text
orca exec [OPTIONS] [PROMPT]...
orca exec [OPTIONS] resume [SESSION_ID] [PROMPT]...
~~~

提示词是位置参数。传入 - 时从标准输入读取提示词。

~~~bash
orca exec "修复解析器失败的测试" --verifier "cargo test -p parser"
printf '%s\n' "总结已修改的文件" | orca exec -
~~~

## 执行参数

| 参数 | 用途 |
| --- | --- |
| --output-format TEXT\|JSONL | 选择人类可读文本或每行一个 JSON 事件；默认是 text。 |
| --cwd PATH | 指定工作区。 |
| --mode suggest\|auto-edit\|full-auto\|plan | 选择工具审批策略。 |
| --model MODEL, --api-key KEY, --base-url URL | 覆盖本次运行的提供商配置。 |
| --verifier COMMAND | 任务结束后执行验证命令。 |
| --max-turns N, --max-tool-calls N | 限制模型回合或工具调用数。 |
| --max-cost-usd USD, --max-wall-time-secs SECONDS | 限制估算费用或运行时间。 |
| --no-history | 不记录本次运行。 |
| --save-history | JSONL 运行同时保留本地会话记录。 |

所有资源限制默认不设上限。验证器是可选的；没有可靠自动检查时，不要传 --verifier。

## CI 示例

~~~bash
set -o pipefail

orca exec \
  --cwd "$GITHUB_WORKSPACE" \
  --mode auto-edit \
  --max-turns 20 \
  --max-cost-usd 3 \
  --verifier "npm test" \
  "修复失败的测试" \
  > orca-events.txt
~~~

需要结构化事件时，选择 JSONL 并由 shell 重定向标准输出：

~~~bash
orca exec \
  --output-format jsonl \
  --save-history \
  --verifier "cargo test" \
  "修复回归" \
  > orca-events.jsonl
~~~

自动化应使用进程退出状态和验证器输出作为门槛。Orca 不承诺一套额外稳定的数字退出码分类，因此脚本不应根据未公开的退出码名称推断结果。
