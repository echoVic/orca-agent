# 审批模式

审批模式只是 Orca 生效能力策略的一个输入。它不能覆盖目录信任、权限规则、沙箱执行结果或显式拒绝。多条权限规则匹配时，最严格的结果生效。

## 公开模式

| 模式 | 能力上限 |
| --- | --- |
| plan | 只读。写入、网络、Shell、元数据写入和子 Agent 能力均被拒绝。 |
| suggest | 工作区写入上限；运行时要求审批的地方仍需审批。 |
| auto-edit | 工作区写入上限；按正常编辑策略执行。 |
| full-auto | 最宽的能力上限；仍受平台沙箱和配置拒绝规则约束。 |

选择能完成任务的最窄模式。尤其是 full-auto 不能绕过操作系统隔离、工作区信任或被拒绝的根目录。

## 选择模式

无头运行使用 --mode：

~~~bash
orca exec --mode plan "检查架构并提出修改建议"
orca exec --mode suggest "修复失败的单元测试"
orca exec --mode auto-edit "应用已审查的格式化改动"
orca exec --mode full-auto "在一次性沙箱中执行任务"
~~~

根交互命令同样接受 --mode。其值既可以为 TUI 会话选择审批模式，也可以选择 server 或 acp 协议传输；选择传输时不要再组合任务提示词或子命令。

配置文件使用顶层 mode 字段，环境变量使用 ORCA_MODE：

~~~toml
mode = "suggest"
~~~

~~~bash
export ORCA_MODE="suggest"
~~~

CLI 选项优先于环境变量、受信任项目配置、用户配置和内置默认值。

## 在 TUI 中修改

`Shift+Tab` 依次切换模式：suggest → auto-edit → full-auto → plan。切到 full-auto 前会要求你明确确认 Full Access。状态栏左侧显示当前模式（`⇧Tab suggest`）。

使用 /mode 查看或设置当前模式：

~~~text
/mode
/mode suggest
/mode auto-edit
/mode full-auto
/plan
/plan off
~~~

设置变更通过运行时应用，而不是修改本地提示词。模式变更只对当前会话生效，不会被保存。任务正等待审批时，应按界面展示的工具、目标和作用域作出决定，不要把切换模式当作捷径。

## 处理审批

工具调用需要审批时，TUI 会在输入框的位置显示审批面板：

| 选项 | 效果 |
| --- | --- |
| `1` Allow once | 执行这一次。 |
| `2` Allow this exact call | 执行，并且之后同一工具、同一目标的调用不再询问。调用没有具体目标时不提供这一项。 |
| `3` Allow（工具名）this session | 执行，并且在退出前不再询问这个工具。 |
| `4` Deny | 不执行，Orca 会换一种做法。按 `Esc` 也是拒绝。 |

预览内容比面板长时，用 `PgUp`/`PgDn` 翻页查看。

## 后台轮次的审批

用 `Ctrl+B` 放到后台的轮次，会停在第一个需要你答复的工具调用上，任务 dock 显示 `needs approval`。在 dock 里按 `Enter`（输入框需为空）或点击那一行，就能打开这个审批。如果按当前模式和权限规则这个工具本来不用问，轮次会自己继续，并在对话里注明。

## Plan 模式

在 plan 模式下，Orca 只读地调查，可能会先问几个澄清问题，最后给出计划。随后 **Plan ready** 对话框让你选择：实现计划（切回进入 plan 之前的模式；如果会话一开始就在 plan 模式，则切到 auto-edit），或者留在 plan 模式继续完善。对话进行到一半也可以切到 plan 模式。详见[终端界面](terminal-ui.md)。

## 信任是独立边界

目录信任决定项目配置能否参与生效。审查工作区后，才使用公开 trust 命令查看或修改它：

~~~bash
orca trust show --cwd ./project
orca trust add --cwd ./project
orca trust remove --cwd ./project
~~~

优先级和存储位置见[配置说明](configuration.md)。
