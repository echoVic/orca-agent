# 审批模式


Orca 实现了四模式审批格，让你可以在自主性和控制力之间权衡。本页涵盖所有审批模式、如何设置它们以及平衡信任与安全的最佳实践。

## 审批格

Orca 的审批模式形成一个格——每个模式都是前一个模式权限的严格超集：

```
┌─────────────────────────────────────────────────────────────────┐
│                    审批模式格                                    │
│                                                                 │
│  plan ──▶ suggest ──▶ auto-edit ──▶ full-auto                   │
│    │        │          │              │                        │
│    │        │          │              │                        │
│    ▼        ▼          ▼              ▼                        │
│  无工具   手动       自动批准     自动批准                      │
│  调用     批准       文件编辑     所有操作                      │
│           所有工具   + 读取      （无检查）                     │
│           Shell 需要  允许                                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 模式对比表

| 模式 | 文件读取 | 文件编辑 | Shell 命令 | 网络 / MCP | 破坏性操作 |
|------|----------|----------|------------|------------|-----------|
| `plan` | ❌ | ❌ | ❌ | ❌ | ❌ |
| `suggest` | ✅（静默） | ⚠️（批准） | ⚠️（批准） | ⚠️（批准） | ⚠️（批准） |
| `auto-edit` | ✅（静默） | ✅（自动） | ⚠️（批准） | ⚠️（批准） | ⚠️（批准） |
| `full-auto` | ✅（静默） | ✅（自动） | ✅（自动） | ✅（自动） | ✅（自动） |

- ✅ = 自动允许
- ⚠️ = 需要用户批准
- ❌ = 不允许

### 详细行为

#### `plan` — 仅规划

<Callout type="info">

智能体**从不执行**任何工具。它只生成计划、推理和建议的工具调用供你审查。

</Callout>

```
智能体：我计划进行以下更改：
       1. 创建 src/auth/token.rs，120 行
       2. 修改 src/auth/login.rs 以使用新模块
       3. 更新 src/mod.rs 以导出新模块

       工具调用：write_file("src/auth/token.rs")
       状态：已阻止 —— 审批模式为 "plan"
```

**适用场景**：高度受监管的环境、教学和演示、在执行前审查复杂的重构。

#### `suggest` — 建议并批准

<Callout type="info">

智能体**建议**工具调用，你在执行前批准每个调用。文件读取是静默的（无需批准）。

</Callout>

```
智能体：我想读取 src/auth/login.ts
       [自动执行 — 在 suggest 模式下文件读取是静默的]

智能体：我想修改 src/auth/login.ts（4 处更改）
       [审批对话框]
       文件：src/auth/login.ts
       更改：+12 行，-3 行
       风险：低（编辑现有文件）
       [批准] [拒绝] [查看差异]
```

**适用场景**：大多数 TUI 使用场景。你保持对破坏性操作的控制，而智能体处理常规读取。

#### `auto-edit` — 自动批准编辑

智能体**自动批准**文件读取和编辑。Shell 命令、网络调用和破坏性操作仍需要批准。

```
智能体：我将修改 src/auth/login.ts 以添加 token 过期验证
       [自动执行 — 在 auto-edit 模式下文件编辑自动批准]

智能体：我需要运行 npm test 来验证更改
       [审批对话框]
       命令：npm test
       风险：低（只读操作）
       [批准] [拒绝]
```

**适用场景**：无头 `orca exec` 会话、批量重构、CI 自动化。非交互模式的默认值。

#### `full-auto` — 完全自主

智能体**执行所有操作**而无需询问。任何操作都没有审批对话框。

```
智能体：我将运行完整的测试套件，修复任何失败，然后提交
       [所有操作自动执行]

智能体：我需要 curl 外部 API 获取数据
       [自动执行 — full-auto 模式下无需批准]
```

**适用场景**：沙箱环境、一次性项目、完全信任智能体时。谨慎使用——没有安全网。

## 设置审批模式

### CLI 标志

```bash
orca --approval plan
orca --approval suggest
orca --approval auto-edit
orca --approval full-auto
```

### 斜杠命令（仅 TUI）

在会话期间更改审批模式：

```
/approval plan
/approval suggest
/approval auto-edit
/approval full-auto
```

## 按文件夹信任

Orca 支持基于文件位置的细粒度审批控制。你可以指定文件夹，其中的编辑自动批准，不受全局审批模式影响。

### 配置受信任的文件夹

```toml
[approval]
mode = "suggest"

# 自动批准这些文件夹内的所有编辑
trust_folders = [
    "src/components/ui/",
    "src/utils/",
    "src/hooks/",
]

# 要求对这些命令模式进行显式批准
require_confirmation_for = [
    "delete",
    "rm ",
    "curl ",
    "wget ",
    "sudo ",
]
```

### 受信任文件夹的工作原理

| 场景 | 全局模式 | 文件夹在信任列表中 | 行为 |
|------|----------|-------------------|------|
| 编辑 `src/components/ui/button.tsx` | `suggest` | ✅ 是 | 自动批准 |
| 编辑 `src/components/ui/`（子文件夹） | `suggest` | ✅ 是 | 自动批准（递归） |
| 编辑 `src/utils/helpers.ts` | `suggest` | ✅ 是 | 自动批准 |
| 编辑 `src/auth/login.ts` | `suggest` | ❌ 否 | 需要批准 |
| 运行 `npm test` | `suggest` | N/A | 需要批准（Shell） |

> **提示：** 对 UI 组件库、工具模块或你希望智能体自由工作而无需持续审批对话框的其他区域使用按文件夹信任。

## 审批对话框

### 对话框布局

当需要批准时，TUI 显示非阻塞对话框：

```
┌─────────────────────────────────────────────────────────────────┐
│  ⚠️  需要审批                                                    │
│                                                                 │
│  智能体想要：                                                   │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  运行 Shell 命令：npm test -- --coverage                  │    │
│  │                                                         │    │
│  │  工作目录：/project/app                                  │    │
│  │  预估输出：约 200 行                                     │    │
│  │  风险：低（只读操作）                                    │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  选项：                                                         │
│  [A] 批准     [D] 拒绝     [V] 查看命令     [S] 跳过             │
│                                                                 │
│  提示：按 [A] 批准并继续，[D] 拒绝                              │
│                                                                 │
│  等待期间，智能体仍可规划和读取文件。                           │
└─────────────────────────────────────────────────────────────────┘
```

### 对话框功能

- **非阻塞**：智能体在你决策时继续工作
- **差异预览**：对于文件编辑，按 `V` 查看统一差异
- **风险评估**：操作风险的自动分类
- **命令检查**：批准前完全可见 Shell 命令
- **快速批准**：按 `A` 批准而无需打开对话框
- **始终允许**：某些对话框提供"始终允许此模式"以用于重复性任务

### 风险评估级别

<Callout type="danger">

| 级别 | 标准 | 示例 | |------|------|------| | `低` | 只读，无副作用 | `cat`、`ls`、`grep`、`git diff` | | `中` | 创建/修改文件 | `write_file`、`npm install`、`cargo build` | | `高` | 破坏性或不可逆的 | `rm`、`delete`、`drop_table`、`curl`（数据外泄） | | `严重` | 系统级危险 | `rm -rf /`、`sudo`、`mkfs`、`dd if=` |

</Callout>

> **注意：** 风险级别是建议，不是硬性阻止。你可以无论风险级别批准任何操作。Orca 从不自动阻止——它只标记风险。
