# JSONL 输出

orca exec 默认输出人类可读文本。需要由其他程序消费事件流时，传入 --output-format jsonl。标准输出的每一行都是一个 JSON 事件信封。

~~~bash
orca exec --output-format jsonl "检查仓库" > run.jsonl
~~~

输出文件由 shell 决定，而不是由 Orca 参数决定。使用重定向、管道或进程管理器选择保存位置。

## 事件信封

每个事件有以下稳定顶层字段：

| 字段 | 含义 |
| --- | --- |
| version | 事件模式版本。 |
| run_id | 此次执行的标识。 |
| seq | 同一次运行内单调递增的序号。 |
| timestamp_ms | Unix epoch 毫秒级发布时间。 |
| type | 事件种类，例如 turn.started 或 tool.call.completed。 |
| payload | 与事件种类对应的数据。 |

type 和 payload 是版本化协议。消费者应保留未知事件类型，而不是假定流只含当前示例中的事件。

~~~bash
orca exec --output-format jsonl "运行测试套件" |
  jq -c 'select(.type == "tool.call.completed")'
~~~

## 历史行为

JSONL 运行会将事件写入标准输出，但默认不记录本地历史。需要后续恢复时，加上 --save-history：

~~~bash
orca exec --output-format jsonl --save-history \
  "修复解析器" > parser-run.jsonl
~~~

对文本或 JSONL 运行使用 --no-history 可避免产生本地会话记录。它不能与恢复、分叉或继续操作同时使用。

## 自动化边界

JSONL 是观察流，不是外部副作用可以安全重放的证明。应保存工具和验证的终态事件；若进程在工具启动后、终态事件前停止，重复操作前先检查目标状态。
