# 上下文与压缩

上下文窗口由运行时在一次回合中管理，没有单独的公开命令用于检查或修改它。实时信息请看交互式 TUI；自动化场景则消费执行事件流。

~~~bash
orca exec --output-format jsonl "检查当前实现" |
  jq -c 'select(.type == "context.updated" or .type == "context.compacted")'
~~~

context.updated 给出该时刻观察到的 token 用量与上限。context.compaction.started 和 context.compacted 标记运行时压缩边界。这些事件只是观察结果：它们解释某些较早细节为什么不在当前提示中，并不允许丢弃持久化的对话或工具记录。

自动压缩只有在把对话压到压缩上限以内，或至少缩小十分之一时，才保留结果。否则对话保持原样，最近的工具结果也完整保留，Orca 要等对话再增长十分之一才会重试。当前提示本身就超过上限时，这一点尤其重要。如果某次请求已经没有空间留给回复，压缩一定会执行，并保留任何缩减。

需要引用先前精确事实时，在下一条提示中提供文件路径、测试名或会话边界，而不是依赖隐式的上下文猜测。

## 大段工具结果

在有历史记录的会话中，MCP、外部工具、`web_fetch` 和 `web_search` 的文本结果超过约 12,500 token 时，Orca 会把全文存成文件。模型能看到结果的开头和结尾，以及全文路径。它可以用 `read_file` 的 `offset` 和 `limit` 分段读取，也可以用 `grep` 搜索。两个工具都能读取当前会话保存的结果。

文件保存在 `$ORCA_HOME/session-results/<session-id>/spill/`。在 Unix 上，只有文件所有者有读写权限。工具输出缩减后仍保留路径，删除会话会一并删除这些文件。保存失败时，工具按原有方式返回结果。Shell 任务、`read_file`、`grep`、`glob` 和 `task_read_output` 继续使用各自的输出上限或分页机制。
