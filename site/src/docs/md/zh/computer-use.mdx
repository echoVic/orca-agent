# Computer Use（macOS）

## 能做什么

Orca 可以通过 `computer` 工具看见并操作其他 macOS 应用：列出或启动应用、观察窗口、
点击、输入文字、发送按键和滚动。可以用它检查自己刚写的界面，或在没有命令行接口的
应用里做事；文件和命令行工具能完成的工作，优先用这些工具。

## 要求

Computer use 只在 macOS 14 及以上、交互式 TUI 的主会话中可用。在
**系统设置 → 隐私与安全性**中，为运行 Orca 的终端授予**辅助功能**和**屏幕录制**权限。
授予屏幕录制后，如果权限还没生效，重启终端。如果驱动提示安装 Esc 监听器时缺少
监听权限，还需要授予**输入监控**；它不能替代辅助功能权限。

## 应用授权

第一次观察或操作应用前，Orca 会请求授权；已有权限规则决定这次调用，或会话处于
`full-auto`（见[审批模式](#审批模式)）时除外。面板提供六个选项：

- `1` **Allow once**（仅这一次）：执行当前调用，下次仍会询问。
- `2` **Allow this app this session**（本会话允许该应用）：退出前不再询问该应用的授权。
- `3` **Allow all apps this session**（本会话允许所有应用）：退出前不再询问任何应用的授权。
- `7` **Always allow this app (saved)**（总是允许该应用）：为该应用保存允许规则，后续会话也生效。
- `5` **Always allow all apps (saved)**（总是允许所有应用）：为所有应用保存允许规则，后续会话也生效。
- `4` **Deny**（拒绝）：拒绝当前调用，让 Orca 寻找其他办法。

保存选项写入用户配置：设置了 `ORCA_HOME` 时是 `$ORCA_HOME/config.toml`，否则是
`~/.orca/config.toml`。`7` 把应用的完整 bundle id 写成规则的 `pattern`，`5` 写入
`pattern = "*"`：

~~~toml
[[permissions.rules]]
tool = "computer"
pattern = "com.apple.Safari"
decision = "allow"
~~~

向标有 `[secure]` 的密码框输入文字时，每次都会单独询问，只有 `1`
**Allow typing this once**（仅允许这一次输入）和 `4` **Deny** 两个选项。
这包括 `type` 和能输入文字的 `key`：单独的可打印键、配合 Shift/Option 的可打印键，
以及 `Cmd+V`（也包括配合 Shift/Option 的粘贴）。导航键和其他非文字快捷键不触发
这项单独审批。

应用授权（包括所有应用的授权）和 `full-auto` 都不能预先批准密码输入。带 `pattern`
的 allow 规则也不能，包括精确应用 id、`*` 这样的通配符和显式的 `#secure` 目标。只有整个工具的 allow 规则，即 `tool = "computer"`、
`decision = "allow"` 且不写 `pattern`，能预先批准。匹配的 deny 规则仍优先，详见
[权限规则](approval-modes.md#权限规则)。

如果坐标目标或过期观察直到投递时才让驱动发现密码框，未批准的调用不会发送文字。
结果会提示重新观察，再用元素 id 指向密码框重试，以请求审批。

## 应用风险分级

钥匙串访问（`com.apple.keychainaccess`）、密码（`com.apple.Passwords`）、bundle id 以
`com.1password.`、`com.agilebits.` 或 `com.bitwarden.` 开头的应用，以及声明了
`public.app-category.finance` 类别的应用默认禁止操作。只有 `pattern` 与该应用
bundle id 完全相等的 allow 规则能解除默认禁止，通配符或整个工具的 allow 规则不行：

~~~toml
[[permissions.rules]]
tool = "computer"
pattern = "com.apple.Passwords"
decision = "allow"
~~~

运行 Orca 的宿主终端永远不能操作，任何规则都不能放开；无法识别宿主时，清单中的
终端应用全部禁止操作。其他清单内的终端（Terminal、iTerm2、Ghostty、Warp、kitty、
Alacritty、WezTerm、cmux）和 IDE（VS Code、`com.todesktop.` 或 `com.jetbrains.` 下的
应用、Xcode、Zed）会警告它们能在 Orca 沙箱外执行命令；访达警告文件访问，系统设置警告
修改系统设置，清单内的浏览器（Safari、Chrome、Firefox、Arc、Edge、Brave）警告网页
可能携带针对代理的指令。警告显示在授权面板里，也会出现在每个会话第一次操作该应用的
结果里；在 `full-auto` 下、或因规则和授权而不弹面板的调用，也能看到它。

## 审批模式

Plan 模式只允许 `list_apps` 和 `observe`，拒绝启动、点击、输入文字、发送按键和滚动。
`list_apps` 不需要应用授权。在 `plan`、`suggest` 和 `auto-edit` 下，应用调用（包括
`observe`）都会请求应用授权，已有适用规则或授权时除外。

`full-auto` 本来就能在宿主机上执行命令，所以这时应用调用不再请求应用授权。密码输入
仍然每次询问，deny 和 prompt 规则仍然生效，默认禁止的应用仍然禁止。

## 观察和截图

有元素 id 时，优先使用最新观察中的 id。如果结果提示省略了元素，可以用 `query`
按角色、标签或值缩小结果范围。`truncated` 表示无障碍树的遍历达到时间上限，只返回了
部分元素；树里没有列出的控件仍可能存在。可以带 `query` 重新观察，或使用最新截图中的
坐标目标，再检查动作结果，确认是否生效。

坐标以截图像素为单位，原点在左上角。没有内容元素树的应用仍可能列出标题栏按钮，
内容区域需要使用坐标目标。

点击 `[N image(s) attached]` 这一行即可预览工具结果的截图，例如 `[1 image attached]`。
按 `q` 关闭预览。

## 停止

从本轮第一次 `computer` 调用开始，直到本轮结束，Orca 都会在系统范围捕获 `Esc`。
`Esc` 中断正在运行的轮次，包括其他应用在前台或截图预览打开时。

## 后台和前台

Orca 优先在后台操作应用。动作需要前台时，会短暂切到该应用，完成后恢复原来的前台应用
和鼠标位置，结果会注明是否用了前台。`launch_app` 启动应用或打开 URL/文件时不请求激活，
应用自身仍可能选择切到前台。带 Command 的 `key` 动作始终使用这次切换，
因为发给后台应用的 Command 快捷键无法生效。

在用户配置中关闭这次切换（默认是 `true`，项目配置不能设置它）：

~~~toml
[computer_use]
foreground_fallback = false
~~~

关闭后，需要前台的动作会失败，包括 Command 快捷键。

## 关闭 computer use

在用户配置中添加整个工具的 deny 规则，不写 `pattern`。
Orca 就不会把 `computer` 提供给模型：

~~~toml
[[permissions.rules]]
tool = "computer"
decision = "deny"
~~~

## 隐私

截图可能包含隐私信息，使用 `deepseek-flash`（也接受旧名称 `deepseek-v4-flash` 和
`deepseek-v4-flash-vision-exp`）或 `auto` 时会发给模型提供方。
其他模型选择只收到无障碍元素树和其他文字结果，截图位置会附一条说明；工具截图不会
另外发给视觉模型解读。

## 现在还不支持

不支持拖拽和直接设置字段值。子代理、工作流子任务、ACP 客户端和 `orca exec`
不能使用 computer use。

远程控制软件（例如 UU 远程）在屏幕上覆盖一层窗口时，需要前台的操作会因为目标被其他窗口
遮挡而被拒绝。断开远程会话后即可使用。
