# 会话续传

Orca 将已记录的对话保存在本地，以便交互式或无头任务从持久化边界继续。公开命令行在启动时提供续传能力，而非另一套会话管理命令。

## 交互式启动

~~~bash
orca --resume SESSION_ID
orca --fork SESSION_ID
orca --continue
~~~

--resume 不带选择器时会打开交互式选择器。使用选择器浏览已记录的对话，再选择恢复或分叉。

## 无头启动

~~~bash
orca exec --resume SESSION_ID "继续排查"
orca exec --fork SESSION_ID "尝试第二种实现"
orca exec --continue "继续处理验证失败"
orca exec resume SESSION_ID "从检查点继续"
~~~

仅在恢复或继续时使用 --resume-at MESSAGE_ID，表示恢复到某个已持久化消息为止。互斥规则见[恢复无头运行](orca-exec-resume.md)。

## 哪些状态是持久化的

已记录对话包含恢复所需的模型和工具历史，但这不等于每个进行中的外部副作用都已完成。崩溃或中断后，若工具已经启动却没有终态结果，应在再次写入、发请求或运行命令前先检查状态。

交互式选择器是浏览本地历史的支持入口。自动化场景应把选出的会话 ID 与任务元数据一起保存，并通过上述命令重新传入。

## 存储与清理

恢复会话不限制历史总字节数或记录数，replay 逐条读取并归约。单条 JSONL 记录（含换行符）上限为 64 MiB，追加前完成校验。损坏记录仍会阻止恢复；列表或搜索扫描预算耗尽时可返回 `inspection_limited`，这不代表损坏，也不会禁用恢复或分叉。恢复时会独立校验完整历史。

新写入的内联图片按 SHA-256 保存到 transcript 同级的 `SESSION.jsonl.assets/` 目录，同一会话重复使用相同图片只保存一份。版本化 JSONL envelope 记录摘要、解码长度和引用位置，读取时校验图片字节，再还原原有模型和 surface 输入。旧的内联图片记录仍可读取。

归档会带上图片资产，压缩保持同一资产目录。分叉拥有独立副本，删除父会话不会删除子会话的图片。原始备份必须同时包含 JSONL（或 JSONL.zst）和资产目录；运行时 `JsonlThreadStore::export_session` API 可导出包含图片的可移植 JSONL。旧版 Orca 无法读取新的资产 envelope。

磁盘清理采用独立的显式策略，不影响会话有效性：

~~~bash
orca storage
orca storage --max-bytes 1073741824
orca storage --older-than-days 30
orca storage --older-than-days 30 --apply
~~~

不带 `--apply` 时仅报告占用与候选项，不删除数据。时间和配额策略只清理已归档会话，优先清理最旧项，并计入图片资产占用。活跃会话、被运行时占用的归档会话受到保护。配额是清理目标，不是写入或恢复门禁；报告会说明是否达标。
