# Agent 循环


Orca 通过结构化的七阶段回合生命周期处理每个用户请求。理解这个循环有助于你诊断问题、调整性能并充分利用每次交互。

## 回合生命周期

Orca 中的每个"回合"是从用户输入到工具执行再到结果呈现的完整循环。各阶段在单个回合内顺序执行，循环重复直到任务完成或触发预算门控。

```
┌─────────────────────────────────────────────────────────────────┐
│                    Agent 回合生命周期                             │
│                                                                 │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐          │
│  │ 1. 上下文   │──▶│ 2. 提供商   │──▶│ 3. 工具     │          │
│  │    组装     │   │    调用     │   │   分发      │          │
│  └─────────────┘   └─────────────┘   └─────────────┘          │
│         ▲                                 │                    │
│         │                                 ▼                    │
│  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐          │
│  │ 6. 结果     │◀──│ 5. 执行     │◀──│ 4. 审批     │          │
│  │    集成     │   │  结算       │   │    检查     │          │
│  └─────────────┘   └─────────────┘   └─────────────┘          │
│         │                                 │                    │
│         ▼                                 │                    │
│  ┌─────────────┐                          │                    │
│  │ 7. 回合     │◀─────────────────────────┘                    │
│  │    关闭     │                                               │
│  └─────────────┘                                               │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 阶段 1：上下文组装

每次模型调用之前，Orca 组装完整的上下文窗口：


<Steps>
<Step>

**系统提示词**——定义智能体角色、工具模式和安全规则的固定指令

</Step>
<Step>

**项目上下文**——仓库结构、关键文件、git 状态和相关代码片段

</Step>
<Step>

**最近对话**——最近 N 回合的用户/智能体交流

</Step>
<Step>

**每回合草稿**——当前回合的中间结果、工具输出和推理制品

</Step>
</Steps>


上下文组装：
```text
context = [系统提示词] + [项目上下文] + [最近回合] + [当前回合草稿]
```

运行时还会在此阶段检查上下文大小，如果窗口超过 1M token 限制的 85%，则触发压缩。每个模型可见窗口都有稳定的 `ContextWindowId`：usage 更新与 resume 保持该 ID，成功 compaction 后推进 ID，fork 则创建独立身份。

### 阶段 2：提供商调用

Orca 使用以下参数将组装好的上下文发送到 DeepSeek API：

- **模型 ID**——来自配置或 CLI 标志
- **温度**——控制输出随机性
- **推理努力**——思考深度（`low`、`medium`、`high`）
- **工具模式**——可用工具集（文件编辑、Shell、grep、glob 等）
- **图片块**——选择 `deepseek-v4-flash-vision-exp` 时直接发送；选择
  `auto`、Pro 或 Flash 时先转换为与任务相关的视觉上下文

模型的响应流包括：
- **推理 token**——内部链式思考（默认不向用户显示）
- **工具调用**——使用工具的结构化请求
- **文本响应**——自然语言输出

provider 流归一化、usage 投影、response completion、重试失败清理和 compaction
决策由 generation-context controller 负责。主 thread actor 只协调 mailbox
dispatch、fence 和跨 controller 提交。

### 阶段 3：工具分发

当模型发出工具调用时，Orca 的运行时会：


<Steps>
<Step>

**验证**每个调用是否符合工具模式（正确的参数、有效路径等）

</Step>
<Step>

**路由**调用到相应的工具处理器（文件系统、Shell、搜索、MCP）

</Step>
<Step>

**检查**安全规则（被阻止的命令、危险模式）

</Step>
<Step>

**排队**调用以尽可能批量执行

</Step>
</Steps>


Orca 支持**并行工具执行**——如果模型发出多个独立的工具调用，它们会同时执行。

### 阶段 4：审批检查

在执行任何工具调用之前，Orca 检查审批策略：

| 审批模式 | 检查内容 |
|----------|----------|
| `plan` | **所有内容**——每个工具调用都需要手动批准 |
| `suggest` | Shell 命令、删除、网络调用 |
| `auto-edit` | 仅破坏性 Shell 命令（`rm`、`curl` 等） |
| `full-auto` | **无**——所有调用自动批准 |

如果需要批准：
- TUI 显示带有命令、受影响文件和风险评估的审批对话框
- 智能体在等待时**继续规划**——它可以发出更多工具调用或文本响应
- 如果用户拒绝，工具调用被标记为"已拒绝"，模型会收到通知

### 阶段 5：执行结算

一旦批准（或自动批准），工具开始执行：


<Steps>
<Step>

**文件操作**——读取、写入、编辑、移动、删除

</Step>
<Step>

**Shell 命令**——在沙盒子进程中运行，带超时

</Step>
<Step>

**搜索工具**——grep、glob、语义代码搜索

</Step>
<Step>

**MCP 工具**——调用已配置的 MCP 服务器

</Step>
</Steps>


每次执行都会生成一个**结果对象**，包含：
- `status`：`success` | `error` | `timeout`
- `stdout` / `stderr`：命令输出
- `artifacts`：已更改文件、已创建文件等的列表
- `duration_ms`：执行时间

### 阶段 6：结果集成

结果被反馈到上下文窗口中，供下一次模型调用使用：


<Steps>
<Step>

**工具结果**追加到对话历史

</Step>
<Step>

**状态信息**高亮显示（成功 = 绿色，错误 = 红色）

</Step>
<Step>

**文件变更事件**被追踪到项目上下文中

</Step>
<Step>

**安全违规**被记录并可能触发模式升级

</Step>
</Steps>


模型现在可以看到其工具调用的结果，并决定下一步操作。

### 阶段 7：回合关闭

当以下情况发生时，回合关闭：

- 模型发出**最终文本响应**（没有待处理的工具调用）
- 用户**中断**并发送新消息
- 触发**预算门控**（最大回合数、最大费用或超时）
- 发生**不可恢复的错误**

回合关闭时：
1. 完整回合被**持久化**到会话数据库
2. Token 使用量**计入**预算门控
3. TUI 更新以显示最终状态
4. 在 `orca exec` 模式下，确定退出码

## 取消和所有权

### 优雅取消

用户可以使用 `Ctrl+C`取消正在进行的回合。这会触发：


<Steps>
<Step>

**立即**停止所有正在运行的 Shell 命令

</Step>
<Step>

**保留**会话中所有已完成的工具结果

</Step>
<Step>

**上下文保留**——模型可以从上次状态恢复

</Step>
<Step>

**预算核算**——迄今为止使用的 token 计入预算

</Step>
</Steps>


### 所有权模型

**运行时拥有执行权**，而非模型。这意味着：

- 模型**不能**直接执行 Shell 或写入文件——它只发出工具调用
- 运行时在执行之前**验证和门控**每个操作
- 取消时，运行时可以安全终止所有子进程
- 模型永远不会看到未经运行时调解的原始 Shell 输出

这种分离对安全性至关重要，并启用了以下功能：
- 非阻塞审批对话框
- 并行工具执行
- 沙箱化 Shell 访问
- 所有操作的审计日志

## 重试和错误恢复

### 自动重试

Orca 自动重试某些失败：

| 错误类型 | 重试行为 | 最大重试次数 |
|----------|----------|-------------|
| API 速率限制 | 指数退避 | 3 |
| API 超时 | 线性退避 | 2 |
| 瞬态网络错误 | 立即重试 | 2 |
| 工具执行超时 | 将超时延长 50% | 1 |
| 文件 I/O 错误 | 使用新句柄重试 | 1 |

### 错误升级

当自动重试耗尽时：


<Steps>
<Step>

**非关键错误**（例如，grep 未找到任何内容）——模型看到错误并调整其计划

</Step>
<Step>

**关键错误**（例如，磁盘已满、权限被拒绝）——回合进入"阻塞"状态

</Step>
<Step>

**模型**可以提出变通方案或请求用户帮助

</Step>
<Step>

**用户**可以取消、修改方法或修复底层问题

</Step>
</Steps>

## 上下文压缩

当上下文窗口接近 1M token 限制（通常在 85% 阈值时）时，Orca 触发**自动压缩**：

### 压缩规则


<Steps>
<Step>

**保留系统提示词**——始终保留

</Step>
<Step>

**保留项目上下文**——保留最新的文件树和关键制品

</Step>
<Step>

**保留最近回合**——保留最近 10 回合原样

</Step>
<Step>

**压缩旧回合**——将第 11–20 回合压缩为摘要

</Step>
<Step>

**丢弃草稿**——移除中间推理和重复的工具结果

</Step>
<Step>

**保留前缀缓存**——维护字节对齐的前缀以确保缓存命中

</Step>
</Steps>


### 压缩透明度

Orca 记录压缩事件并在 TUI 中显示压缩回合指示器：

```
[压缩] 回合 1-10 已压缩（原为 450K tokens，现为 80K tokens）
```

> **提示：** 如果频繁看到压缩，请考虑缩小任务范围或开始新会话。压缩会保留信息，但可能降低模型引用非常早期上下文的能力。
