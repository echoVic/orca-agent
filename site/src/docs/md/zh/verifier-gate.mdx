# 验证

当完成需要独立检查时，通过 --verifier 传入 Shell 命令。Orca 会在任务结束后执行它，并把结果与运行记录在一起。

~~~bash
orca exec "修复登录回归" \
  --verifier "npm test -- --testPathPattern=login"

orca exec "重构解析器" \
  --verifier "cargo test -p parser && cargo clippy -p parser -- -D warnings"
~~~

## 选择可以失败的证据

一个好的验证器应当：

- 独立于模型的文字声明；
- 足够聚焦，能判断目标行为是否改变；
- 足够确定，可以重复运行；
- 足够快，适合日常执行。

~~~bash
# 好：检查请求的行为。
orca exec "增加解析错误用例" --verifier "cargo test -p parser parse_error"

# 弱：没有检查改动本身。
orca exec "增加解析错误用例" --verifier "echo done"
~~~

CLI 每次执行只接收一个验证命令。多步检查难以审查时，放进 Shell 脚本：

~~~bash
orca exec "重构认证" --verifier "./scripts/verify-auth.sh"
~~~

没有可靠自动检查时，不要传 --verifier。公开 CLI 没有验证器默认配置命令，也没有验证器专用超时参数。

## 验证失败后恢复

失败的验证结果是下一回合的证据，而不是所有写入都可以重放的证明。带着失败上下文恢复已记录运行：

~~~bash
orca exec resume SESSION_ID \
  --verifier "npm test -- --testPathPattern=login" \
  "阅读验证失败信息，只修复剩余回归"
~~~

应把验证器输出和 CI artifact 或 JSONL 流一起保留，让审查者能区分已验证和未验证的结果。
