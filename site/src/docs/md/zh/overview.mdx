# 概述


Orca 是一款 **DeepSeek 原生终端编程智能体**，以 Rust 语言从零构建。与在通用聊天界面之上封装的包装型智能体不同，Orca 是端到端为代码设计的：其提示词、工具协议、交互模型和状态管理均专为软件工程任务而生。

## 什么是 Orca？

Orca 是一款终端智能体，能够理解你的代码库、规划多步骤变更、执行工具并验证结果——所有这些通过单一 Rust 二进制文件实现。它使用 DeepSeek 的原生工具调用协议，可直接访问文件操作、Shell 执行、搜索和结构化推理，无需中间抽象层。

Orca 提供三种交互界面：

| 界面 | 描述 | 适用场景 |
|------|------|----------|
| **TUI** | 全屏终端界面，包含聊天、文件树和审批对话框 | 交互式开发会话 |
| **无头 CLI** | 非交互式 `orca exec` 命令，用于脚本和 CI | 自动化流水线、批量重构 |
| **外部协议** | MCP 服务器、JSONL 事件流和程序化 API | 工具链集成、自定义前端 |

## 核心架构决策

### DeepSeek 原生提示词

Orca 使用 DeepSeek 的原生工具调用模式，而非通用的函数调用封装。这意味着：

- 模型看到的是专为编程设计的工具集（文件编辑、Shell、grep、glob、诊断）
- 工具调用流式逐次发出——模型可在单个推理轮次中发出多个工具调用
- 系统提示词和工具描述已针对 DeepSeek 的推理能力进行优化

### 单一 Rust 二进制文件

Orca 编译为约 15MB 的静态链接二进制文件。无需运行时安装，无需 Python 虚拟环境，无需 Node.js 依赖。这使得部署变得简单：

```bash
# 在任何平台上一条命令即可安装
curl -fsSL https://orca.ai/install.sh | sh
```

### 本地优先、可恢复

Orca 将会话状态存储为本地 SQLite 数据库。每次对话、工具调用和结果均持久保存。你可以恢复任何会话、从检查点分叉，或在数周后回顾过去的决策。

```bash
# 恢复昨天的会话
orca --resume 42

# 从特定回合分叉
orca --fork 42:turn-17
```

### 审批感知

Orca 实现了四模式审批格（`plan` → `suggest` → `auto-edit` → `full-auto`），让你可以在自主性和控制力之间权衡。你可以在项目级别、按文件夹或按会话设置审批。智能体在未经明确批准的情况下永远不会执行破坏性操作——且审批对话框是非阻塞的，因此智能体在你决策时可继续规划。

### 运行时拥有交互

Orca 的运行时拥有与模型的所有交互。模型永远不会直接执行 Shell 命令或写入文件。而是：


<Steps>
<Step>

模型发出结构化工具调用

</Step>
<Step>

运行时根据安全规则验证调用（例如，"不允许 `rm -rf /`"）

</Step>
<Step>

运行时显示审批对话框（在适用的模式下）

</Step>
<Step>

运行时执行工具并将结果返回给模型

</Step>
</Steps>


这种分离确保即使模型产生不安全的输出，运行时也充当安全门控。

### 持久目标与工作流

Orca 支持 **目标**（带预算门控和验证器的单一目标）和 **工作流**（带分支、上下文通道和错误恢复的多步骤过程）。两者均以版本化的 YAML 存储，可在会话、团队和仓库之间共享。

```yaml
# 目标：修复不稳定的测试套件
objective: 消除 src/__tests__/ 中所有不稳定的测试
budget:
  max_turns: 30
  max_cost_usd: 5.00
verifier:
  type: command
  run: npm test -- --flaky 2>&1 | grep -c "passing"
  expect_stdout: "0"
```

## 何时使用 Orca

| 场景 | 为什么选择 Orca |
|------|----------------|
| 大规模重构 | 上下文窗口 + 目标模式带验证器门控 |
| 新功能开发 | TUI 模式带 @提及搜索和侧边对话 |
| 代码审查自动化 | `orca exec` 配合 JSONL 输出用于 CI 集成 |
| 多仓库调试 | MCP 集成 + 持久会话状态 |
| 教授代码模式 | 带结构化指导的技能插件 |
