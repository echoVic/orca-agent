# CLI 参考

公开 CLI 契约保持精简。请对已安装的二进制运行 `orca --help`，或运行对应
子命令的 `--help`。仓库中的 `docs/public-cli-manifest.json` 会在测试中与
Clap 命令面保持一致。

## 安装

```bash
npm install -g @blade-ai/orca
```

官网和安装器的规范域名是 [orcaagent.dev](https://orcaagent.dev/)。

## 根命令

```text
orca [OPTIONS] [PROMPT]...
orca [OPTIONS] COMMAND
```

直接运行 `orca` 会打开交互式 TUI。没有配置模式时，新会话默认使用 `full-auto`
（yolo）；显式模式优先，恢复会话沿用保存的模式，除非明确覆盖。也可以把提示词
作为位置参数传入。
可见的根命令如下：

| 命令 | 用途 |
| --- | --- |
| `orca doctor` | 检查本地配置、凭据、目录信任和沙箱就绪状态。 |
| `orca storage` | 检查会话磁盘占用，预览或执行归档清理策略。 |
| `orca exec` | 非交互执行任务，输出文本或 JSONL 事件。 |
| `orca app-server` | 通过标准输入输出提供 JSON-RPC app 协议。 |
| `orca acp` | 通过标准输入输出提供 Agent Client Protocol。 |
| `orca workflow` | 执行和检查本地持久化工作流。 |
| `orca trust` | 查看或更新目录信任。 |
| `orca mcp` | 在用户配置中添加、列出、查看、删除、登录或登出 MCP 服务器。 |

根选项包括 `--resume [SESSION_ID]`、`--fork ID`、`--continue`、
`-m` / `--model MODEL`、`--mode MODE`、`--yolo`、`--plan`、`--api-key KEY`、
`--base-url URL` 和 `-C` / `--cwd` / `--cd PATH`。`--yolo` 选择 `full-auto`，
`--plan` 选择只读规划模式。两个快捷选项不能同时使用，也不能与 `--mode` 组合。

协议入口使用 `orca app-server` 或 `orca acp`。旧的 `--mode server` 与
`--mode acp` 继续可用。协议启动会拒绝提示词、历史选择参数（`--resume`、
`--fork`、`--continue`）和审批模式快捷选项。命名协议命令接受放在子命令前后
的模型、目录、密钥和 base URL 参数。

`exec` 的公共参数（`--mode`、模型、目录、密钥、base URL）可以放在 `exec`
前后，也可以放在 `exec resume` 后面。根层、`exec` 与 `resume` 层的显式值
不同会报错，相同值可以重复。CLI 参数优先于配置和环境变量。模型、密钥和 endpoint 的帮助
统一使用 `ORCA_MODEL`、`ORCA_API_KEY`、`ORCA_BASE_URL`；对应的 `DEEPSEEK_*`
兼容别名仍然可用。

## `orca doctor`

```text
orca doctor [--cwd PATH] [--json | --format text|json] [--online]
```

`doctor` 是只读的运行前检查。它不会启动 MCP、配置沙箱 capability、写入配置，
也不会改变目录信任；只有加上 `--online` 才会连接模型服务。它输出带类型的
`pass`、`warn`、`fail` 检查：

- 配置语法和来源路径；
- 凭据是否存在及其来源（绝不输出凭据值）；
- 生效模型和 endpoint 配置；
- 最近的目录信任决策；
- 当前平台的沙箱后端。

`--online` 会多一项 `credentials-online` 检查：用配置的 key 向配置的 endpoint
发一次 `GET /models`。列模型不调用模型，也不计费。服务接受 key 时通过，拒绝时
（HTTP 401 或 403）失败；判断不了时给出警告：返回其他状态码（有的 endpoint
不提供 `/models`）、10 秒内没有响应，或者没有可检查的 key。报告里不会出现 key。

只有存在 `fail` 时退出码才是 `1`；只有警告时退出码为 `0`。文本适合人工阅读，
JSON 是稳定的机器接口，字段使用 camelCase，例如 `schemaVersion`。

```bash
orca doctor
orca doctor --cd ./project --json
orca doctor --online
```

## `orca storage`

```text
orca storage [--max-bytes BYTES] [--older-than-days DAYS] [--apply]
```

不带 `--apply` 时只预览占用和候选项。归档策略、图片所有权与备份规则见
[存储与清理](session-commands.md#存储与清理)。

## `orca rewind`

```text
orca rewind [SESSION_ID] [--last] [--at MESSAGE_ID]
            [--mode both|code|conversation|summarize-from|summarize-up-to]
            [--dry-run] [--json] [--force] [--rollback OP_ID] [--prune]
```

把已保存会话的文件和/或对话回退到某一用户消息提交时的状态。不带 `--at`
时以最近的用户消息为目标（即撤销最后一轮）。`--mode code` 只恢复文件，
`conversation` 只截断对话，`both`（默认）两者都做。`--dry-run` 只输出计划；
`--json` 输出稳定 JSON 报告。外部进程或 bash 改动的文件不在检查点内，CLI
默认拒绝覆盖它们，需要显式 `--force`。`summarize-from` / `summarize-up-to`
用一次模型摘要替换目标一侧的历史（dry-run 不调用模型），摘要写入
`session.rewind` 记录并在恢复会话时重放。会话保留最近 100 个检查点；被淘汰的
旧检查点只能用 `conversation` 模式回退。`--rollback OP_ID` 回滚一次中断的恢复
（journal 保留时），`--prune` 清理无引用的检查点 blob。检查点要求会话已记录
历史，并且只记录 `edit` / `write_file` 触及的文件；`ORCA_DISABLE_FILE_HISTORY=1`
可关闭捕获。对应 TUI 命令是 `/rewind`。

## `orca exec`

```text
orca exec [OPTIONS] [PROMPT]...
orca exec [OPTIONS] resume [SESSION_ID] [PROMPT]...
```

支持的执行选项：

| 选项 | 含义 |
| --- | --- |
| `--output-format TEXT\|JSONL` | 人类可读输出，或每行一个 JSON 事件。 |
| `--json` | `--output-format jsonl` 的简写。 |
| `-C` / `--cwd` / `--cd PATH` | 工作区目录。 |
| `--mode suggest\|auto-edit\|full-auto\|plan` | 工具操作的审批策略。 |
| `--yolo` | 选择 Full Access，覆盖配置或恢复的模式。 |
| `--plan` | 选择只读规划，覆盖配置或恢复的模式。 |
| `-m` / `--model MODEL` | 覆盖模型。 |
| `--api-key KEY` | 覆盖 API 密钥。 |
| `--base-url URL` | 覆盖 API endpoint。 |
| `--verifier COMMAND` | 任务完成后执行的验证命令。 |
| `--max-turns N` | 本次运行最多模型回合数。 |
| `--max-tool-calls N` | 本次运行最多工具调用数。 |
| `--max-cost-usd USD` | 本次运行的估算费用上限。 |
| `--max-wall-time-secs SECONDS` | 本次运行的最长墙钟时间。 |
| `--resume ID` | 按 ID 或前缀恢复对话。 |
| `--resume-at MESSAGE_ID` | 只恢复到指定持久化消息边界。 |
| `--fork ID` | 分叉保存的对话。 |
| `--continue` | 继续最近保存的对话。 |
| `--no-history` | 不写入本次运行的本地历史。 |
| `--save-history` | 使用 JSONL 输出时仍保存历史。 |

示例：

```bash
orca exec "修复失败的测试" --verifier "cargo test"
orca --plan exec --json --max-turns 20 "分析解析器" > run.jsonl
orca exec resume SESSION_ID --resume-at MESSAGE_ID "从检查点继续"
orca exec resume --last fix failing test
```

`exec resume --last` 后的每个位置参数都属于提示词，不会消耗会话 ID。
`--resume-at` 可以放在 `resume` 前后；两处传入不同的消息边界会报错。

`doctor --json` 输出单个 JSON 报告，`exec --json` 输出 JSONL 事件，MCP
`list` / `get --json` 保持原有 JSON 输出。使用快捷选项时不要同时传入对应的
显式格式选项。

需要保存输出时使用 shell 重定向；CLI 没有单独的输出路径选项。

## `orca workflow`

工作流命令提供 `run`、`list`、`show`、`source`、`stop`、`pause`、`resume`、
`clone`、`restart-failed` 和 `restart-phase`。每个操作都有自己的参数；编写
脚本前请先查看 `orca workflow COMMAND --help`。

## `orca trust`

```text
orca trust [show|add|remove] [--cwd PATH]
```

`show` 是只读操作。`add` 和 `remove` 会更新用户目录中的信任存储，执行前请
确认目录内容和对应的沙箱策略。

## `orca mcp`

```text
orca mcp add NAME [OPTIONS] (--url URL | -- COMMAND [ARGS]...)
orca mcp list [--json]
orca mcp get NAME [--json]
orca mcp remove NAME
orca mcp login NAME
orca mcp logout NAME
```

`orca mcp` 只写用户拥有的 `$ORCA_HOME/config.toml`（`login`、`logout` 还会写旁边的
凭据存储），绝不改动项目的 `.orca/config.toml`。改动在下一次会话启动时生效——不会
影响已经在运行的会话。

| 子命令 | 用途 |
| --- | --- |
| `orca mcp add` | 添加一个 stdio 或远程（HTTP/SSE）MCP 服务器。 |
| `orca mcp list` | 列出已配置的服务器，每行一个；加 `--json` 输出 JSON。 |
| `orca mcp get` | 查看某个服务器的配置。 |
| `orca mcp remove` | 从用户配置中删除一个服务器，并删除它保存的登录（如果有）。 |
| `orca mcp login` | 用 OAuth 登录一个远程服务器。 |
| `orca mcp logout` | 删除一个远程服务器保存的登录。 |

`add` 要么带一个 stdio 命令，要么带 `--url`，二者恰好给一个：

| 选项 | 含义 |
| --- | --- |
| `-e, --env KEY=VALUE` | stdio 服务器的环境变量（可重复）。与 `--url` 冲突。 |
| `--url URL` | 远程服务器地址。 |
| `--transport http\|sse` | 远程传输方式，默认 `http`。只在带 `--url` 时才有意义。 |
| `--header 'Name: value'` | 发给远程服务器的 HTTP 请求头（可重复）。需要 `--url`。 |
| `--bearer-token-env-var VAR` | 保存 bearer token 的环境变量名，连接时读取。需要 `--url`。 |
| `--client-id ID` | OAuth client id。需要 `--url`。 |
| `--callback-port PORT` | 本地 OAuth 回调端口。需要 `--url`。 |
| `-- COMMAND [ARGS]...` | stdio 服务器命令及其参数。 |

`NAME` 只能含字母、数字、`-` 和 `_`，至少有一个字母或数字，不能含 `__`。Orca 用
服务器名给它的工具命名：转成小写，连续的 `-` 和 `_` 换成一个 `_`，并去掉首尾的 `_`。
这样规范化后与已配置的服务器相同的名字（比如已有 `GitHub` 时的 `github`、已有
`my-server` 时的 `my_server`），`add` 会拒绝，并指出与哪个服务器冲突。

`list` 和 `get` 会按配置原样显示 stdio 服务器的命令和参数、远程服务器的地址，所以不要
把密钥写在这些地方。`env` 和 `headers` 只显示键名，绝不显示值；认证状态列（或 `get`
里的 `auth:` 一行）只显示状态词（`oauth: logged in`、`oauth: not logged in`、
`bearer: $VAR`、`static header`，stdio 服务器则是 `-`），绝不显示 token。`get` 还会
显示 `enabled_tools` 和 `disabled_tools`：没设置的显示 `-`，空列表显示 `none`。

某个条目读不成服务器时（比如缺少 `name`，或某个值的类型不对），不会连带其他条目。
`list` 照常列出能读的服务器，在 stderr 上逐个指出出错的条目：按它在 `mcp_servers`
里排第几，有名字时再加上名字，然后以状态码 1 退出：

```text
orca: /home/me/.orca/config.toml: invalid MCP server entry 2 ('github'): invalid type in `env`, expected a map
```

对这个名字执行 `get` 也显示同样的信息，对其他服务器的 `get`、`login`、`logout` 照常
可用。提示只说条目哪里不对，绝不显示它的值。会话不会加载这样的配置：Orca 会给出警告，
改用默认设置启动，所以条目修好之前，MCP 服务器都不会连接。

`login` 会在浏览器里打开服务器的授权页面，并把地址打印出来以防没有自动打开；
对 stdio 服务器，或配置了静态 `Authorization` 请求头、`bearer_token_env_var` 的
服务器，它会拒绝执行，因为这些服务器不使用 OAuth。`logout` 删除保存的登录；
服务器没有保存登录时会报错。

示例：

```bash
orca mcp add docs -- npx -y docs-mcp-server
orca mcp add search --url https://mcp.example.test/mcp --bearer-token-env-var SEARCH_TOKEN
orca mcp add tracker --url https://tracker.example.test/mcp
orca mcp list --json
orca mcp get docs
orca mcp login tracker
orca mcp logout tracker
orca mcp remove docs
```

## 配置和环境变量

设置 `ORCA_HOME` 时，用户配置文件为 `$ORCA_HOME/config.toml`；否则为
`~/.orca/config.toml`。项目可以提供 `.orca/config.toml`，但只有目录受信任后才会
加载。生效优先级从高到低为命令行选项、环境变量、受信任项目配置、用户配置和内置
默认值。

支持的环境覆盖包括 `ORCA_API_KEY`/`DEEPSEEK_API_KEY`、
`ORCA_MODEL`/`DEEPSEEK_MODEL`、`ORCA_BASE_URL`/`DEEPSEEK_BASE_URL`、`ORCA_MODE`
和 `ORCA_REASONING_EFFORT`/`DEEPSEEK_REASONING_EFFORT`。不要把凭据提交到源码库；
`orca doctor --format json` 只报告凭据是否存在及其来源；加上 `--online` 时还会报告
服务是否接受它，但绝不输出凭据本身。
