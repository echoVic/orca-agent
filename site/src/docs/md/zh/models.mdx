# 模型


Orca 支持 DeepSeek 的 V4 模型系列，提供两种针对不同用例优化的变体。本页涵盖模型选择、推理努力级别以及成本/速度权衡。

## 可用模型

### 模型对比表

| 属性 | deepseek-v4-flash | deepseek-v4-pro |
|------|-------------------|-----------------|
| **主要用例** | 快速编辑、搜索、简单重构 | 架构设计、复杂调试、多文件变更 |
| **上下文窗口** | 1M tokens | 1M tokens |
| **最大输出 tokens** | 8K | 8K |
| **推理** | 已启用（较轻量） | 已启用（更深入） |
| **工具使用** | 是（所有工具） | 是（所有工具） |
| **输入费用** | 约 $0.001 / 1K tokens | 约 $0.004 / 1K tokens |
| **输出费用** | 约 $0.002 / 1K tokens | 约 $0.010 / 1K tokens |
| **速度** | 约 30 tok/s（推理） | 约 15 tok/s（推理） |
| **首个 token** | 约 2s | 约 4s |
| **MMLU（基准测试）** | 78.2% | 85.7% |
| **HumanEval（编程）** | 82.1% | 89.3% |
| **SWE-Bench（智能体）** | 52.4% | 64.8% |

### 何时使用每个模型


<Tabs>
<Tab label={"deepseek-v4-flash（默认）"}>


在以下情况选择 `deepseek-v4-flash`：

- **编辑现有代码**——跨 1–5 个文件的中小型更改
- **搜索和理解**——查找函数、追踪调用路径、解释代码
- **运行测试和修复**——快速迭代的测试驱动开发
- **批量重构**——在许多文件上应用一致的模式
- **脚本和自动化**——CI 管道中的 `orca exec`
- **快速原型设计**——搭建组件、编写样板代码

```bash
# 默认行为——flash 模型
orca "给仪表板添加加载动画"

# 显式使用 flash
orca --model deepseek-v4-flash "修复所有文件中的导入顺序"

# 带 flash 的无头模式
orca exec "给 React 组件添加错误边界" --model deepseek-v4-flash
```


</Tab>
<Tab label={"deepseek-v4-pro"}>


在以下情况选择 `deepseek-v4-pro`：

- **架构设计**——设计系统、选择模式、规划迁移
- **复杂调试**——跨许多文件的多步骤根因分析
- **遗留代码理解**——导航具有深度依赖的不熟悉代码库
- **性能优化**——识别瓶颈并提出优化方案
- **安全审计**——使用深度推理分析代码漏洞
- **多文件重构**——组织具有许多依赖变更的项目结构
- **测试生成**——编写具有边界情况覆盖的综合测试套件
- **入门指导**——理解新代码库并生成文档

```bash
# 用于复杂调试的 pro 模型
orca --model deepseek-v4-pro "调试 WebSocket 重连逻辑中的竞态条件"

# 用于架构的 pro 模型
orca --model deepseek-v4-pro "设计从 REST 到 GraphQL 的迁移策略"

#  pro + 高推理努力
orca --model deepseek-v4-pro --reasoning-effort high "重构整个数据层以支持多租户"
```

### 决策树

```
任务是否为：
├── 简单/机械性？（搜索、编辑、格式化）
│   └── deepseek-v4-flash
├── 中等复杂度？（多文件变更、测试编写）
│   ├── < 10 个文件 → deepseek-v4-flash
│   └── > 10 个文件 → deepseek-v4-pro
├── 复杂/创造性？（架构、调试、设计）
│   └── deepseek-v4-pro
└── 不确定？
    └── 从 flash 开始，如果智能体遇到困难则升级到 pro
```

## 推理努力级别

两个 V4 模型都支持三个推理努力级别，控制模型在输出前的思考深度。

### 推理努力表

| 级别 | 描述 | 使用场景 | 相对费用 | 相对速度 |
|------|------|----------|----------|----------|
| `low` | 最小推理，快速响应 | 搜索、简单编辑、格式化 | 0.5× | 快 2 倍 |
| `medium` | 平衡推理（默认） | 大多数任务 | 1.0× | 基准 |
| `high` | 深度推理、全面分析 | 复杂规划、调试、架构 | 2.0× | 慢 2 倍 |

### 设置推理努力

#### CLI 标志

```bash
# 低努力用于快速搜索
orca --reasoning-effort low "查找所有已弃用 API 的实例"

# 中等（默认）用于大多数任务
orca --reasoning-effort medium "给 API 层添加缓存"

# 高努力用于复杂架构
orca --model deepseek-v4-pro --reasoning-effort high "重新设计状态管理层"
```

#### 配置文件

```toml
[agent]
reasoning_effort = "medium"  # 所有会话的默认值
```

#### 每回合通过斜杠命令

在 TUI 中，你可以在会话中途更改推理：

```
/reasoning high
```

> **提示：** 从 `medium` 开始。将 `low` 用于快速搜索，仅在任务真正需要深度分析时使用 `high`。模型在 `low` 努力下仍会产生正确的结果——只是不会探索尽可能多的替代方案。

## 会话期间切换模型

你可以在会话中途切换模型。Orca 优雅地处理过渡：


<Steps>
<Step>

**当前上下文**被保留并发送到新模型

</Step>
<Step>

**推理努力**重置为新模型的配置默认值

</Step>
<Step>

**Token 计数**从会话现有预算继续

</Step>
</Steps>


```bash
# 在 TUI 中，使用以下命令切换模型：
/model deepseek-v4-pro
# 或
/model deepseek-v4-flash
```

> **注意：** 切换模型时，前缀缓存会中断（不同模型 = 不同的缓存键）。切换后的第一回合会较慢，因为上下文需要重新处理。

## 成本优化技巧

### 1. 从 flash 开始

对于 80% 的任务，`deepseek-v4-flash` 是正确的选择。只有在遇到复杂性障碍时才升级到 `pro`。

### 2. 战略性使用推理努力

- `low` 用于搜索/导航（节省 50% 费用）
- `medium` 用于大多数任务
- `high` 用于架构/调试（2× 费用，但结果更好）

### 3. 利用前缀缓存

保持同一会话运行以受益于缓存。开始新会话会丢失缓存命中。

### 4. 设置预算门控

```bash
orca exec "重构 API" --max-cost 2.00 --max-turns 15
```

### 5. 对批量任务使用 `orca exec`

无头模式避免 TUI 开销，每回合稍快一些。

### 6. 实时监控费用

TUI 显示每回合费用和总会话费用：

```
回合 5 费用：$0.08 | 会话总计：$0.42 | 预算：$10.00
```
