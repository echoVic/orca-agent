# 模型

交互式或无头运行通过 --model 选择提供商模型：

~~~bash
orca --model deepseek-v4-pro "解释当前架构"
orca exec --model deepseek-v4-flash "修复导入顺序" \
  --verifier "cargo fmt --check"
~~~

支持哪些模型名和 endpoint 行为取决于所选提供商。示例模型名不代表每个 endpoint 都支持它。启动任务前运行 orca doctor，检查本地实际生效的模型和 endpoint 配置。

## 持久化选择

可以在用户配置或环境变量中设置模型：

~~~toml
model = "deepseek-v4-pro"
reasoning_effort = "high"
~~~

~~~bash
export ORCA_MODEL="deepseek-v4-pro"
export ORCA_REASONING_EFFORT="high"
~~~

推理强度支持 low、high 和 max。应通过配置或交互式模型设置它；公开 CLI 不提供单次运行的此类控制。

## 基于证据选择

先使用工作区配置的模型。只有任务确实需要不同能力、延迟或成本特征时才切换，并记录验证器结果。执行预算与模型选择是独立的：

~~~bash
orca exec \
  --model deepseek-v4-flash \
  --max-turns 15 \
  --max-cost-usd 2 \
  --verifier "cargo test -p parser" \
  "重构解析器"
~~~

模型、凭据、endpoint 与信任的优先级见[配置说明](configuration.md)。
