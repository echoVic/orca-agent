# MCP 集成

MCP 服务器在用户拥有的 Orca 配置中声明，不由单独的公开命令空间管理。编辑 TOML 后，审查服务器命令或端点，再启动使用该配置的交互式或无头任务。

设置 ORCA_HOME 时，用户配置位于 $ORCA_HOME/config.toml；否则位于 ~/.orca/config.toml。项目配置仅在工作区已受信任后才会生效。

## Stdio 服务器

~~~toml
[[mcp_servers]]
name = "repository"
transport = "stdio"
command = "node"
args = ["/absolute/path/to/server.mjs"]
startup_timeout_ms = 10000
tool_timeout_ms = 30000

[mcp_servers.capabilities]
read = true
write = false
metadata_write = false
network = false
shell = false
agent = false
~~~

## SSE 服务器

~~~toml
[[mcp_servers]]
name = "docs"
transport = "sse"
url = "https://mcp.example.test/sse"
headers = { Authorization = "Bearer token-from-environment" }
startup_timeout_ms = 10000
tool_timeout_ms = 30000
~~~

transport 只能是 stdio 或 sse。stdio 服务器需要 command；SSE 服务器需要 url。凭据尽量放在环境变量中，并且只授予集成实际所需的能力。

## 安全操作

1. 从只读能力集开始。
2. 本地服务器程序使用绝对路径。
3. 信任项目配置前先审查工作区。
4. 使用 orca doctor 验证本地配置和沙箱就绪状态；它是只读的，不会启动 MCP 服务器。
5. 任务运行期间在交互式 TUI 中查看状态。

公开 CLI 不提供列出、重启、测试或诊断单个 MCP 服务器的命令。这些生命周期动作属于运行中会话和配置边界。
