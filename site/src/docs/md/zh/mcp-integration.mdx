# MCP 集成

用 `orca mcp add` 添加 MCP 服务器，用 `orca mcp list` 和 `orca mcp get` 查看，用
`orca mcp remove` 删除，用 `orca mcp login`/`orca mcp logout` 登录或登出远程服务器的
OAuth。这些命令只写用户拥有的 Orca 配置（`login`、`logout` 还会写旁边的凭据存储），
绝不改动项目的 `.orca/config.toml`；改动在下一次会话启动时生效。完整的选项列表见
[CLI 参考](cli-reference.md#orca-mcp)。

设置 ORCA_HOME 时，用户配置位于 $ORCA_HOME/config.toml；否则位于 ~/.orca/config.toml。

## Stdio 服务器

~~~bash
orca mcp add repository -- node /absolute/path/to/server.mjs
~~~

## 远程服务器（HTTP 或 SSE）

~~~bash
orca mcp add docs --url https://mcp.example.test/mcp \
  --header "Authorization: Bearer token-from-environment"
~~~

stdio 服务器需要 command；远程服务器需要 url。凭据尽量放在环境变量中：
`--bearer-token-env-var` 指定一个在连接时读取的环境变量名，而不是把 token 存进
配置文件。

`orca mcp add` 不会设置 capabilities、超时或[工具筛选](#工具筛选)。新服务器默认只有
只读能力；在 `orca mcp add` 写好的条目上手动编辑，按需授予：

~~~toml
[[mcp_servers]]
name = "repository"
transport = "stdio"
command = "node"
args = ["/absolute/path/to/server.mjs"]
startup_timeout_ms = 10000
tool_timeout_ms = 30000

[mcp_servers.capabilities]
read = true
write = false
metadata_write = false
network = false
shell = false
agent = false
~~~

## 远程服务器与登录

`--transport` 选择 `http`（streamable HTTP，默认）或 `sse`。`http` 使用当前的 MCP
传输方式：每个请求都是 POST，`initialize` 协商出的会话 ID 和协议版本会随之后每个
请求带上。`sse` 开始时也这样做，只有服务器对第一个 `initialize` POST 回 400、404 或
405 时，才改用旧版 HTTP+SSE 传输：先 GET 打开一个事件流，再把请求 POST 到它给出的
地址。已有的 `sse` 服务器照常工作；可能只支持旧版传输的服务器适合用
`--transport sse` 添加。

远程服务器的认证方式有三种：

- **静态请求头**——`--header "Authorization: ..."`，随每个请求发送。
- **`--bearer-token-env-var VAR`**——`orca` 在连接时从自己的环境变量里读取
  `VAR`，把它当作 bearer token 发送。token 本身绝不会写进配置文件。
- **OAuth**，给两者都没配置的服务器用。运行 `orca mcp login <name>` 在浏览器里
  完成授权；授权地址也会打印出来，方便在没有浏览器的机器上手动打开。
  `orca mcp logout <name>` 删除保存的登录。对 stdio 服务器，或者已经配置了
  静态请求头、`--bearer-token-env-var` 的服务器，`login` 会拒绝执行，因为它们都
  不使用 OAuth。

这些选项保存为服务器条目里的键，也可以手动写：

~~~toml
[[mcp_servers]]
name = "search"
transport = "http"
url = "https://search.example.test/mcp"
bearer_token_env_var = "SEARCH_TOKEN"   # --bearer-token-env-var

[[mcp_servers]]
name = "tracker"
transport = "http"
url = "https://tracker.example.test/mcp"
oauth_client_id = "orca-cli"            # --client-id
oauth_callback_port = 51000             # --callback-port
~~~

`oauth_client_id` 是授权服务器事先发给你的 client id；不配置时，Orca 会向服务器
动态注册。`oauth_callback_port` 固定浏览器回来时访问的地址
`http://127.0.0.1:<port>/callback` 的端口，给只接受事先登记过回调地址的服务器用；
不配置时使用任意空闲端口。

OAuth token 保存在 `$ORCA_HOME/mcp-credentials.json`，与 `config.toml` 同目录，
只有其所有者可读，按服务器名和地址保存——把服务器迁移到新地址会让旧地址下保存的
登录失效。`orca mcp list` 和 `orca mcp get` 会显示每个服务器的认证状态
（`oauth: logged in`、`oauth: not logged in`、`bearer: $VAR`、`static header`，
stdio 服务器则是 `-`），但绝不显示 token 本身。

会话进行中，保存的登录失效且刷新不了时，工具调用会报下面的错，这一轮结束后
`/mcp` 会把该服务器显示为 `needs login`：

~~~text
MCP server requires login: run 'orca mcp login <name>', or log in from /mcp
~~~

`login` 和 `logout` 只改动配置或凭据存储，不会影响已经在运行的会话。已经打开的
TUI 会话可以在 `/mcp` 面板里重新连接该服务器，从而应用这次改动。

## 服务器何时连接

会话开始时，它的服务器在后台同时连接：交互式 TUI 一打开就开始连接，不等第一条消息。
服务器在连上、连接失败或发现需要登录之前，状态为 `starting`；连接过程中发给它的每个
请求（`initialize`、`tools/list`、`prompts/list`）都受它的 `startup_timeout_ms` 约束，
未设置时为 30 秒。一轮第一次请求模型之前，只等待仍在连接的服务器，好让模型拿到它们
带来的全部工具；等待期间 TUI 的状态行显示 `connecting MCP servers`，按 `Esc` 会中断
这一轮，等待也一并中断。在 TUI 里，第一条消息开始的对话会接手已经连上的服务器，不重新
连接；在那之前退出，就结束这些服务器。

## 在 TUI 里管理服务器

在交互式 TUI 里，`/mcp` 列出当前对话的服务器及其状态：已连接（附工具数）、连接失败
（附原因）、需要登录，或已停用。按 `Enter` 查看某个服务器的工具（每个工具附上权限
规则里用的名字，只读工具带标记）、prompts，以及它的配置里设置的
`enabled_tools`/`disabled_tools`。`r` 重新连接所选服务器，`l` 用 OAuth 登录后重新
连接，`o` 删除保存的登录后重新连接。这些在发出第一条消息之前同样可用：那时服务器
已经在连接，在这里登录后重新连接的服务器，会由随后开始的对话接着使用。`/mcp` 列出的
是 Orca 启动时的配置：TUI 打开期间添加的服务器，要重启 TUI 后才会出现。面板和按键详见
[终端界面](terminal-ui.md#mcp-服务器)。

## Prompts

声明了 `prompts` 能力的服务器，连接和重新连接时都会列出它的 prompts；`/mcp` 在该服务器的
详情里显示它们。在 TUI 里，每个 prompt 都是一条斜杠命令，命名方式与该服务器的工具相同：
`/mcp__<server>__<prompt>`，后面按顺序跟上 prompt 的参数，比如
`/mcp__github__review_pr 123 main`。最后一个参数接收剩下的全部文本；缺少必填参数时显示用法，
不会执行。Orca 向服务器请求这个 prompt（`prompts/get`），把返回的内容当作你的消息发出：
各段文本用空行连接，嵌入资源取其文本，图片作为附件。服务器报错时，对话里会说明，不发送。
prompt 在发出第一条消息之前也能运行：它返回的内容就是那条消息，对话随之开始。
参数规则和大小上限详见[终端界面](terminal-ui.md#mcp-prompt-命令)。

## 工具返回的图片

只有 `deepseek-flash` 和使用它的 `auto` 能在 tool 消息中直接看到 MCP 工具返回的图片。`deepseek-v4-pro` 和自定义模型（即使声明了 `supports_images = true`）收到的是一句说明，告诉模型它看不到这些图片。仅接受 PNG、JPEG、GIF 和 WebP，解码后每张不超过 5 MiB；不符合的图片会被丢弃，并留下说明原因的文字。单个 MCP 响应连同图片最多 16 MiB，超过时这次调用会失败。

每次请求最多携带对话中最新的 3 张工具图片，更早的会替换为说明文字。这只影响发出的请求——完整历史仍保存在磁盘上。

恢复会话不会重新加载旧的工具图片，无论恢复时用的是哪个模型，恢复后的对话里仍然是那句说明文字。

## 只读工具

服务器可以在 `tools/list` 的返回中把某个工具标为只读（`readOnlyHint`）。这样一来，Orca 会把调用该工具当作一次读操作：

- suggest 模式下调用前不会询问；plan 模式下可以调用，其余 MCP 工具调用仍会被拒绝。
- 一个工具是否只读，完全以服务器自己的声明为准。
- 服务器同时标了 `destructiveHint` 的工具，仍会像其他写操作一样询问。

## 工具筛选

服务器条目可以限定 Orca 注册它的哪些工具。`orca mcp add` 不设置这两个键，需要手动
写。两者写的都是服务器在 `tools/list` 里给工具起的名字，比如 `createIssue`，而不是
Orca 的 `mcp__github__createissue`：

~~~toml
[[mcp_servers]]
name = "github"
transport = "http"
url = "https://github-mcp.example.test/mcp"
enabled_tools = ["list_issues", "create_issue", "delete_repo"]
disabled_tools = ["delete_repo"]
~~~

- `enabled_tools` 是白名单：只注册其中列出的工具。空列表 `enabled_tools = []`
  一个工具也不注册。
- `disabled_tools` 是黑名单，在白名单之后生效，所以两个名单里都有的工具不会注册。
  上面的例子只注册 `list_issues` 和 `create_issue`。
- 不写某个键，就不做那一项筛选。被筛掉的工具不会注册，模型看不到它。

`orca mcp get` 会显示这两个键：没设置的显示 `-`，空列表显示 `none`；`/mcp` 里服务器的
详情也会显示。

## 总是允许

MCP 工具的审批面板会比其他工具多两个选项：`5` Always allow `<tool>` (saved) 和 `6` Always allow the `<server>` server (saved)。两者都会执行这次调用，并像 `3` Allow `<tool>` this session 一样，在本会话剩余时间内不再询问；此外还会往用户配置里追加一条允许规则，让之后的会话也不再询问：

~~~toml
[[permissions.rules]]
tool = "mcp__github__create_issue"
decision = "allow"

[[permissions.rules]]
tool = "mcp__github__*"
decision = "allow"
~~~

第一条规则（`5`）只针对这一个工具；第二条（`6`）覆盖该服务器上的所有工具。两条规则都不写 pattern：不写 pattern 的规则覆盖这个工具的所有调用，而且 MCP 调用的目标本来就是工具自己的名字。手动写这类规则时，按 Orca 的方式写工具名，也就是 `/mcp` 详情里显示的写法：转成小写，连续的其他字符换成一个 `_`。Orca 读规则里的 `mcp__` 名字时也这样规范化，所以写 `mcp__GitHub__createIssue` 同样指 `mcp__github__createissue`。参见[权限规则](approval-modes.md#权限规则)。规则保存失败时（比如现有配置解析不了），这次调用仍会执行，本会话也仍然不再询问；对话里会说明规则未能保存的原因。

## 安全操作

1. 从只读能力集开始。
2. 本地服务器程序使用绝对路径。
3. 信任项目配置前先审查工作区。
4. 使用 orca doctor 验证本地配置和沙箱就绪状态；它是只读的，不会启动 MCP 服务器。
5. 在 TUI 的 `/mcp` 面板里查看每个服务器的状态，并在那里重新连接。

`orca mcp list` 和 `orca mcp get` 查看已配置的服务器时不会连接它们。它们会按配置原样
显示 stdio 服务器的命令和参数、远程服务器的地址，所以不要把密钥写在这些地方；`env`
和 `headers` 只显示键名，绝不显示值，也绝不显示 token。CLI 不提供重启、测试或诊断
运行中 MCP 连接的命令：运行中的连接属于它所在的会话，由 TUI 的 `/mcp` 面板显示其状态
并重新连接。
