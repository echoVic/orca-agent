# 配置说明

Orca 直接从 TOML 文件和环境变量解析配置。请用编辑器修改 TOML 配置文件，再运行
`orca doctor`：它会验证本地配置并显示生效的模型和 endpoint，不会启动会话。

## 位置和优先级

用户配置目录只会按以下规则解析一次：

1. 设置了环境变量时使用 `$ORCA_HOME`。
2. 否则使用 `~/.orca`。

该目录中的用户配置文件为 `config.toml`，本地认证文件为 `auth.json`。工作区可以
提供 `.orca/config.toml`，但只有工作区受信任后 Orca 才会加载它。项目配置可以调整
展示和模型选择，但不能提供凭据、修改审批模式、添加 MCP server、放宽权限，或配置
进程启动能力。

这两个 `config.toml` 都是 UTF-8 编码的 TOML。读不了的（例如存成 UTF-16 的文件，Windows
PowerShell 5.1 的 `>` 就会这样写）或解析不了的，Orca 启动时会给出警告并跳过，其中的设置
一项都不生效。

同一配置项的优先级从高到低为：

1. CLI 选项
2. 环境变量
3. 受信任项目中的 `.orca/config.toml`
4. 用户 `config.toml`
5. 内置默认值

审批模式的内置默认值：新 TUI 会话使用 `full-auto`（yolo），无界面的 `exec`
和共享 daemon 使用 `auto-edit`。恢复会话沿用会话保存的模式，除非启动时明确
传入 `--mode` 或 `--yolo`。

## 最小用户配置

```toml
# $ORCA_HOME/config.toml，或 ~/.orca/config.toml
model = "deepseek-v4-pro"
base_url = "https://api.deepseek.com"
mode = "suggest"
reasoning_effort = "high"

[budget]
max_turns = 20
max_tool_calls = 80
max_cost_usd_micros = 2000000
max_wall_time_ms = 1800000
```

`mode` 支持 `suggest`、`auto-edit`、`full-auto` 和 `plan`。
`reasoning_effort` 支持 `low`、`high` 和 `max`。CLI 的资源限制是单次运行范围的：
需要覆盖存储的预算默认值时，在 `orca exec` 上使用 `--max-turns`、
`--max-tool-calls`、`--max-cost-usd` 或 `--max-wall-time-secs`。
配置文件使用整数微美元和毫秒；CLI 分别使用美元和秒。

## 成本估算

成本估算按 DeepSeek 公布的高峰和空闲价格计算，默认开启后台刷新。每个进程在会话启动时检查一次，缓存缺失或已满 24 小时，就在后台从 models.dev 刷新。这两项只能写在用户配置里，项目的 `.orca/config.toml` 不能设置：

```toml
[pricing]
refresh = false            # 不访问 models.dev 刷新价格

[models."my-model".pricing]
input_cache_miss = 0.5     # 美元 / 百万 tokens
input_cache_hit = 0.05
output = 1.5
```

`[models."<名称>".pricing]` 必须写全三个价格，且不分时段。估算方法见[模型](models.md#成本估算)。

## Computer use（macOS）

在 macOS 14 及以上，交互式 TUI 的主会话可以操作其他应用。唯一的配置项写在
用户配置中，项目的 `.orca/config.toml` 不能设置它：

```toml
[computer_use]
foreground_fallback = false
```

`foreground_fallback` 默认是 `true`：需要前台的动作会短暂切到目标应用，再恢复原来的
应用和鼠标位置。设为 `false` 后，这些动作会被拒绝，包括所有 Command 快捷键。
系统权限、应用与窗口授权，以及用 deny 规则关闭工具的方法，见 [Computer Use](computer-use.md)。

## 文件检查点（`/rewind`）

会话记录历史时，Orca 会为每个 turn 捕获一个文件检查点，`/rewind` 可据此恢复文件与
对话历史。`[rewind]` 表写在用户配置中；受信任的工作区也可以在 `.orca/config.toml`
里设置：

```toml
[rewind]
enabled = true            # 每个 turn 捕获检查点；设为 false 时 /rewind 列表为空
observe_untracked = true  # 报告由写工具之外的改动造成的未跟踪文件
max_checkpoints = 100     # 每个会话保留的检查点数（最小 1）
```

`ORCA_DISABLE_FILE_HISTORY`（非空且不为 `0`）关闭捕获，
`ORCA_REWIND_DISABLE_OBSERVE`（任意值）关闭 turn 边界的工作区观察；环境变量
优先于配置文件。被淘汰的检查点会写入保留水位（retention watermark），此后只剩对话
回退可用，其文件 blob 会被自动垃圾回收。当会话所在工作区与检查点记录的工作区不一致
时，文件恢复会被拒绝。

## 权限规则的目标

`[[permissions.rules]]` 写在用户配置中。规则包含 `tool`、可选的目标 `pattern`，
以及取值为 `allow`、`prompt` 或 `deny` 的 `decision`。多条匹配时取最严格的一条。目标包括：

| 工具 | 目标 |
| --- | --- |
| `bash` | 命令行。 |
| 文件工具 | 文件路径。 |
| `computer` | 应用 bundle id；你的已有窗口为 `bundle#window:<id>`；密码输入的目标以 `#secure` 结尾。 |
| MCP 工具 | 规范工具名，如 `mcp__github__create_issue`；通常不写 `pattern`。 |
| `read_mcp_resource` | `server:uri`。 |
| `read_skill` | `id` 参数，通常是 skill 的目录名。 |
| `Workflow` | 优先用脚本路径，否则用工作流名称或草稿 id。内联代码不匹配任何带 pattern 的规则，包括通配符。 |

在 `full-auto` 之外，应用、通配符和整个工具的 allow 规则都不覆盖你的已有窗口，只有精确的
`bundle#window:<id>` allow 才覆盖这个窗口，且不预先批准其中的密码输入。
窗口 id 不跨会话，建议直接在窗口面板里授予本会话权限。应用 deny 和 prompt 规则仍覆盖
窗口；在 `full-auto` 之外，窗口 deny 和 prompt 规则也覆盖其中的密码输入。
`full-auto` 中，密码输入使用 `bundle#secure`，整个 `computer` 工具的 allow 规则
可以预先批准不能执行命令的应用的密码输入。窗口 deny 和 prompt 规则此时不适用，
应用 deny 和 prompt 规则仍生效。匹配方法、可执行命令应用和
密码输入的例外见[审批模式](approval-modes.md#权限规则)。

## 子代理

子代理执行以根任务树为作用域。直接、嵌套、Workflow、托管、续跑和恢复的子任务
共用同一组限制：

```toml
[subagents]
delegation = "adaptive" # off | explicit | adaptive
max_depth = 2
max_running = 32
max_queued = 256
max_live_tasks = 512
max_investigation_turns = 6
max_investigation_tool_calls = 8
```

`max_running` 限制活动执行 lease。超出的已接受任务会排队且不会提前创建 worker；
`max_queued` 限制该队列，`max_live_tasks` 限制所有未终结后代，包括正在等待子任务
的父代理。等待中的父代理会释放执行 lease，并在恢复执行前重新进入队列。

旧的 `max_parallel` 键会被忽略，不再形成第二套容量来源。需要禁止新委派时使用
`delegation = "off"`。

## 凭据

优先使用环境变量：

```bash
export ORCA_API_KEY="sk-..."
# 同样支持 DEEPSEEK_API_KEY。
```

本地认证文件可以是包含 `DEEPSEEK_API_KEY` 成员的 JSON 对象：

```json
{
  "DEEPSEEK_API_KEY": "sk-..."
}
```

不要提交凭据。`orca doctor --format json` 只报告凭据是否存在和其来源，绝不会输出
凭据值。

## 环境变量覆盖

| 用途 | 变量 |
| --- | --- |
| 凭据 | `ORCA_API_KEY`、`DEEPSEEK_API_KEY` |
| 模型 | `ORCA_MODEL`、`DEEPSEEK_MODEL` |
| Endpoint | `ORCA_BASE_URL`、`DEEPSEEK_BASE_URL` |
| 审批模式 | `ORCA_MODE` |
| 推理努力级别 | `ORCA_REASONING_EFFORT`、`DEEPSEEK_REASONING_EFFORT` |

无效的 `ORCA_MODE` 或推理努力级别会导致生效配置无法解析。修改环境变量或 TOML 后，
在执行任务前运行 `orca doctor`。

## 联网搜索与网页抓取

`web_search` 按下面的顺序，用第一个可用的服务：

1. Brave：设置了环境变量 `BRAVE_SEARCH_API_KEY` 时使用。
2. DeepSeek 的 Search API：Orca 连接的是 DeepSeek 官方 endpoint 时使用（见下文）。
3. Exa：不需要 key。DeepSeek 搜索失败时也由 Exa 补上，结果里会写明。

`web_fetch` 总是先从你的机器直接请求页面。连接的是 DeepSeek 官方 endpoint 时，直接请求失败会改用 DeepSeek 的 Fetch API 再试一次，结果第一行会写明这一点。正文里没有可读文字的页面（比如只靠 JavaScript 渲染的应用外壳）也算失败。第二次请求在 DeepSeek 的服务器上进行，按它自己的规则跟随重定向。以下情况不会再试：

- 网址或重定向被 Orca 自己的规则拒绝，比如重定向到了别的网站；
- 页面返回 404 或 410；
- 地址是私有的：局域网、本机回环或链路本地的 IP 地址，或以 `.local`、`.localhost`、`.internal`、`.lan`、`.home.arpa` 结尾的主机名。

只有同时满足这几个条件，Orca 才会调用 DeepSeek 的联网接口：提供方是 DeepSeek，设置了 API key，并且 `base_url` 没有设置，或者指向默认端口上的 `https://api.deepseek.com`（路径不限）。key 只会发往这个地址。`base_url` 是其他地址时（比如第三方网关），`web_search` 和 `web_fetch` 的行为就和没有 DeepSeek 接口时一样。

DeepSeek 对这些调用单独计费，不算在 token 费用里：每 1000 次成功的搜索 0.75 美元，每 1000 次成功的抓取也是 0.75 美元（2026 年 11 月的价格）。Orca 的成本估算不包含这部分。不想用的话，在用户配置里关掉；项目的 `.orca/config.toml` 改不了这一项：

```toml
[tools]
deepseek_web = false   # 搜索改用 Brave 或 Exa，抓取只在本机直接请求
```

## 网络与证书

Orca 用操作系统的证书库验证 HTTPS 证书：macOS 用钥匙串，Windows 用系统证书存储，Linux 用系统的 CA 证书包。

- 公司的代理或网关用自己的 CA 时，把这张 CA 装进系统证书库就行，Orca 不需要额外设置。在 Linux 上，如果没有 root 权限，可以用环境变量 `SSL_CERT_FILE` 和 `SSL_CERT_DIR` 让 Orca 改读你指定的 CA 证书包或证书目录，不再读取系统位置，所以指定的证书包或目录要包含你用到的所有根证书，不能只放公司的那一张。
- 精简版的 Linux（比如最小化的容器镜像）要先安装 `ca-certificates`，否则 Orca 根本创建不了 HTTP 客户端，所有请求都会失败，纯 HTTP 也不例外：本地的 `http://` MCP 服务器，或以 `http://` 开头的 `base_url`。
- `HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY` 环境变量照常生效。

## 目录信任

新工作区默认是不受信任的。信任决定工作区是否能加载项目配置，以及是否能使用完整的
写入/网络沙箱模式。查看当前决策：

```bash
orca trust show --cwd ./project
```

确认工作区后再记录显式决策：

```bash
orca trust add --cwd ./project
orca trust remove --cwd ./project
```

嵌套目录采用最近的显式祖先决策；更近的显式不受信任决策会覆盖更宽范围的受信任祖先。
