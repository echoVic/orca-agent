# 侧边对话


侧边对话让你在不消耗主上下文窗口的情况下与智能体拥有并行讨论。将其视为共享相同项目上下文但拥有独立对话历史的独立线程。

## 什么是侧边对话？

### 行为

侧边对话是会话内的独立聊天线程：

| 属性 | 主会话 | 侧边对话 |
|------|--------|----------|
| 上下文窗口 | 完整 1M tokens | 完整 1M tokens（独立） |
| 对话历史 | 主线程仅 | 侧边线程仅 |
| 项目上下文 | 共享 | 共享（同项目） |
| 工具访问 | 完整 | 完整 |
| 预算 | 主预算（共享） | 共享主预算 |
| 存储 | 持久化 | 持久化 |

### 关键行为


<Steps>
<Step title={"**独立上下文**"}>

每个侧边对话有自己的 1M-token 上下文窗口

</Step>
<Step title={"**共享项目上下文**"}>

文件树、git 状态和配置在所有线程之间共享

</Step>
<Step title={"**提升到主**"}>

侧边对话可以合并到主线程

</Step>
<Step title={"**可丢弃**"}>

侧边对话可以丢弃而不影响主线程

</Step>
<Step title={"**会话恢复**"}>

恢复会话时侧边对话也会被恢复

</Step>
</Steps>


### 线程架构

```
┌─────────────────────────────────────────────────────────────────┐
│                    会话：42                                      │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  主线程                                                 │    │
│  │  上下文：[系统][项目][主历史]                            │    │
│  │                                                         │    │
│  │  "修复登录 bug"                                        │    │
│  │  → 主对话继续...                                       │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  侧边线程 1: "调试缓存"                                  │    │
│  │  上下文：[系统][项目][侧边 1 历史]                       │    │
│  │                                                         │    │
│  │  → 独立调试 Redis 缓存失效                              │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  共享：项目文件树、git 状态、配置、MCP 服务器                     │
└─────────────────────────────────────────────────────────────────┘
```

## 创建和管理侧边对话

### 快捷键表

| 操作 | 快捷键 | 描述 |
|------|--------|------|
| 新建侧边对话 | `Ctrl+T` | 创建新的侧边线程 |
| 切换线程 | `Ctrl+Tab` | 循环切换线程 |
| 线程选择器 | `Ctrl+Shift+T` | 打开线程选择器 |
| 提升到主 | `/promote` | 将侧边线程合并到主线程 |
| 关闭线程 | `Ctrl+W` | 关闭当前侧边线程 |
| 重命名线程 | `/rename-thread <name>` | 重命名当前侧边线程 |

### 创建侧边对话


<Tabs>
<Tab label={"键盘快捷键"}>


按 `Ctrl+T` 创建新的侧边对话。将打开带有空上下文窗口的新输入区域。


</Tab>
<Tab label={"斜杠命令"}>


```
/side 调试缓存层
```

这会创建一个名为"调试缓存层"的侧边对话并切换到它。


</Tab>
</Tabs>

### 提升侧边对话

当侧边对话得出结论时，你可以将其提升到主线程：

```
/promote
```

这会：
1. 将所有消息和工具结果从侧边线程复制到主线程
2. 合并上下文（去重共享的项目上下文）
3. 关闭侧边线程
4. 返回主线程

> **注意：** 提升是单向的——主线程吸收侧边线程的内容。你无法"取消提升"。

## 用例

### 1. 调查支线任务

```
主线："修复登录 token 过期 bug"

侧边："调查中，我注意到缓存层似乎很慢。让我单独分析 Redis。"

→ 主线继续登录修复
→ 侧边独立分析 Redis 性能
→ 侧边结果："Redis 缓存未命中率为 15%（针对用户会话）"
→ 提升 → "顺便说一下，Redis 缓存也很慢"
```

### 2. 探索替代方案

```
主线："使用 REST 实现功能"

侧边："如果我们改用 GraphQL 呢？让我两个都做原型。"

→ 主线构建 REST 版本
→ 侧边原型 GraphQL 版本
→ 并排比较方案
```

### 3. 隔离调试

```
主线："添加用户注册功能"

侧边："WebSocket 连接似乎一直断开。让我在不中断主工作的情况下调试重连逻辑。"

→ 主线继续注册流程
→ 侧边独立调试 WebSocket 重连
→ 侧边产出修复方案，不阻塞主线
```

## 线程选择器

按 `Ctrl+Shift+T` 或输入 `/threads` 打开。

### 键盘快捷键

| 键 | 操作 |
|----|------|
| `↑` / `k` | 向上移动 |
| `↓` / `j` | 向下移动 |
| `Enter` | 切换到选中的线程 |
| `N` | 创建新的侧边线程 |
| `P` | 将侧边线程提升到主线程 |
| `D` | 关闭选中的线程 |
| `R` | 重命名选中的线程 |
| `Esc` | 关闭选择器 |

> **提示：** 谨慎使用侧边对话——每个线程从共享预算中消耗回合和费用。对于长时间运行的并行工作，考虑使用独立的 `orca exec` 会话。
