Tool contract

MCP fits the same tool model as the rest of Orca.

Spec-driven tools

MCP, built-in, and external tools share one model-visible contract instead of scattered ad-hoc prompts. Every tool declares its parameters and capabilities, so the model sees a consistent surface and gets structured results it can reason over.

Approval policies

Tool capabilities determine whether calls run directly, ask for approval, or stay blocked by policy. MCP tools get the same treatment as built-in ones: reads can be fast, writes and network calls are gated by the same rules.

Auditable results

Tool requests, outputs, approvals, and failures stay in the local JSONL transcript for later review. MCP calls are recorded with their server, tool name, parameters, and result, so external tool usage is as traceable as built-in calls.

Managed server lifecycle

Add, list, remove, log in to, and log out of connected MCP servers with orca mcp. Servers connect in the background at launch, so tools are available before your first message and stay listed in the /mcp panel.

Remote and local servers

Remote servers speak streamable HTTP and fall back to legacy SSE, with real OAuth or bearer-token login from the environment. Local stdio servers run as child processes and are supervised like any other tool, with logs available on demand.

Fail-closed by default

A server that drops its connection or returns an error fails closed rather than silently retrying. Turn-only tool approvals are never resumed after a restart unless the same definition can be restored, so a stale approval can never grant access to a changed tool.

How MCP tools work

External tools, same approval and audit model.

Register a server

Use orca mcp add to register a stdio or HTTP server. Orca stores the config, connects in the background, and lists the tools it exposes. Remote servers support OAuth or a bearer token from the environment, and inline arrays keep their comments when you edit the list.

Tools appear in the model's tool list

Every MCP tool is surfaced with its real schema. The model calls it the same way it calls a built-in tool, with typed parameters and a structured result. There is no separate prompt path for MCP, so the model never has to guess how to invoke any tool.

Approvals apply uniformly

MCP tools declare capabilities just like built-in tools. A read-only MCP tool can skip approval in suggest mode; a tool that writes or calls the network asks for approval, exactly as a built-in equivalent would. You can allow a tool once, for the session, or keep it blocked.

Images flow back to the model

When an MCP tool returns an image, it is delivered to the model as a real image input. DeepSeek's vision model can then reason about screenshots, diagrams, and captures returned by MCP servers, with the image stored in the transcript for later review.

Connections stay alive

Servers are pinged while idle and reconnected on failure. A turn waits only for servers still connecting, and Esc cancels an MCP call stuck behind a reconnect or a busy stream so you are never blocked by a hung server.

Everything is recorded

Each MCP call is always written to the JSONL transcript: server, tool, parameters, result, and approval state. You can also audit external tool usage the same way you audit built-in tools, and extract a full trajectory for debugging or benchmarking.

Use cases

What MCP unlocks inside the coding loop.

Search issues and PRs

An MCP GitHub server lets Orca search issues, read PRs, and post comments without a separate integration. The results are real data, not a description parsed from a web page, so the agent can act on exact numbers and statuses.

Read internal docs

Connect a docs server and Orca can read your team's runbooks, API references, and architecture notes. Cited sources come back as file paths and page titles, so claims are traceable instead of asserted from memory.

Browser automation

An MCP browser server can navigate, click, fill forms, and take screenshots. Orca can drive a web app to reproduce a bug and capture the result as evidence, then reason about the screenshot with vision support.

Database access

A read-only database MCP server lets Orca inspect schema, run queries, and verify data migrations without granting shell access to the database. Results come back as structured data the model can reason over directly.

Cloud and infrastructure

Connect a cloud provider's MCP server to inspect resources, check logs, and verify deployments. Approval policies keep destructive operations gated, so read-only reconnaissance can be fast while changes stay under your control.

Internal services

Wrap any internal API in an MCP server and it becomes a first-class tool. Orca can call it, inspect the result, and fold it into the coding loop. Because the tool is schema-driven, the model gets typed parameters and structured results instead of free-text prompts.

FAQ

Questions about Orca MCP tools.

What is MCP?

The Model Context Protocol is a standard for connecting external tools to AI assistants. Orca implements it so any MCP server can expose tools to the coding agent.

Are MCP tools treated differently from built-in tools?

No. They share the same spec-driven contract, approval policies, and audit trail. The model sees one consistent tool list regardless of whether a tool is built-in or MCP.

Can MCP tools run without approval?

Read-only MCP tools can skip approval in suggest mode. Any tool that writes, calls the network, or performs a privileged operation asks for approval, just like a built-in equivalent.

What happens if an MCP server disconnects?

Orca pings idle servers and reconnects on failure. A call stuck behind a reconnect can be cancelled with Esc, and failures are recorded in the transcript rather than retried silently.

Can I use MCP tools that return images?

Yes. Images returned by MCP tools are delivered to the model as image inputs. DeepSeek's vision model can then reason about them as part of the coding loop.

Are MCP tool calls recorded?

Yes. Every MCP call — server, tool, parameters, result, and approval state — is written to the local JSONL transcript. You can audit external tool usage the same way you audit built-in tools.
